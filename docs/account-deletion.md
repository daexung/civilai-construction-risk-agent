# 회원탈퇴

설정 → 계정 → 회원탈퇴에서 삭제 범위와 사용량 보관 내용을 안내합니다. Google 계정 확인을 다시 진행하고 ‘탈퇴’를 입력해야 최종 요청을 보낼 수 있습니다. 품셈이는 비밀번호를 수집하지 않으며 Google 계정 자체는 삭제하지 않습니다. Google의 세션 상태에 따라 인증 화면은 달라질 수 있고 비밀번호 재입력을 강제하지 않습니다.

서버는 Supabase가 검증한 로그인 토큰의 세션을 Auth DB와 비교합니다. 10분 유효 확인 요청보다 나중에 만들어진 동일 회원의 새 세션이어야 합니다. 토큰 갱신만으로는 탈퇴 확인을 통과하지 못합니다. 다른 회원의 ID나 세션은 사용할 수 없습니다.

회원탈퇴는 Supabase Auth Admin API로 계정을 하드 삭제합니다. 프로필·대화·메시지·이전 기록은 외래키로 함께 제거하고, 별도 계산 체크포인트와 회원 피드백도 삭제합니다. 영구 삭제 요청에 앞서 비공개 삭제 작업을 DB에 기록합니다. 서버는 미완료 작업을 1분 간격으로 재시도하며 완료 후 작업 기록을 제거합니다. 처리 중 계정의 서비스 요청은 차단하고, 이미 진행 중인 견적·이전 작업과 탈퇴가 동시에 실행되지 않도록 계정 단위 DB 잠금을 사용합니다.

같은 Google 계정으로 바로 재가입할 수 있습니다. Google의 안정적인 provider ID를 서버 비밀키로 HMAC 처리한 사용량 식별자를 사용하므로 Supabase 회원 ID가 바뀌어도 당일 사용량은 이어집니다. 기존 회원 ID 기반 집계는 새 식별자로 이전합니다. 원문 Google ID와 이메일을 별도 재가입 명단으로 저장하지 않습니다. 해시는 익명 데이터로 간주하지 않습니다. 날짜별 집계에서 7일보다 오래된 날짜는 서버 실행 중 1분 간격의 정리 작업으로 제거합니다. 서버 중단 시 정리는 재개 후 실행됩니다.

법적 근거: 부정 사용 방지 목적의 식별 해시 보관은 별도 처리 목적이며 필요성·기간·정당한 이익과 정보주체 권리의 균형 검토를 공개 전 완료해야 합니다. 개인정보처리방침에 항목·목적·기간을 안내합니다. 안내 문구만으로 적법성이 확정되는 것은 아닙니다.

서버 전용 `SUPABASE_SECRET_KEY` 또는 legacy `SUPABASE_SERVICE_ROLE_KEY`가 필요합니다. 루트 `.env`에서만 읽고 프론트·응답·로그에는 노출하지 않습니다. 키가 없으면 확인 요청 단계에서 503으로 중단하여 계정을 삭제한 것으로 표시하지 않습니다.

검증: `evals/check_account_deletion.py`는 로컬 Supabase의 테스트 계정만 사용하고 외부 Auth API는 모의 처리합니다. 실제 운영 계정을 삭제하는 검증을 실행하지 않습니다. 공개 전에는 전용 테스트 계정으로 Google 재확인부터 실제 Admin API 삭제까지 사용자가 최종 확인하여 점검해야 합니다.
