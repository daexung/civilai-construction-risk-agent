## 1. 입력과 기대 결과부터 고정

기존 질문을 우선 재사용하고 부족한 유형만 보충해 총 20문장 이내로 한다. 실행 전에 문장과 기대 공종·필요 근거를 저장한다. 정답은 사람 검토 전 초안이며, 확정할 수 없는 질문은 복수 후보·추가 조건 필요로 남긴다.

다음 사례는 반드시 포함한다.

| 질문 | 이번 단계에서 확인할 결과 |
|---|---|
| 콘크리트 관련 품셈 기준 있어? | 관련 공종 목록. 계산 명세 보유 여부와 무관하게 검색 |
| 펌프차 할증 기준이 뭐야? | 펌프차 관련 조정 규칙과 원문 위치 |
| 콘크리트 타설 1㎥ 품 알려줘 | 적절한 타설 공종 후보와 산출 기준. 공법이 없는데 특정 공법 하나로 단정하지 않음 |
| 철근콘크리트 펌프카 타설 100루베 견적 | 펌프차 타설의 관련 표·규칙. 계산·Excel 생성은 하지 않음 |
| 교량 견적: 콘크리트 타설 300㎥, 거푸집 500㎡, 철근 가공조립 20톤 | 세 작업 각각의 공종 후보와 근거. 통합 계산은 하지 않음 |
| 콘크리트 타설 노무비 | 포장 공종과 일반 타설 공종의 순위·관련성 비교 |
| 콘크리트 표면 마무리 기준 | 표면 마무리의 기준·표·주석. 기존 데이터의 100㎡당 누락 표시 |

다른 분야와 같은 번호가 있는 공종, 부정·범위가 중요한 규칙, 검색 자료에 답이 없는 질문도 포함한다. 목록의 관련 정답을 전부 알지 못하면 전체 목록 재현율을 계산하지 않는다.

질문 의도와 다공종 문장의 작업 분리는 평가 입력으로 명시한다. 이번 단계의 사람이 준 의도·작업 분리가 자동 의도 판별·자동 추출의 성공으로 보고되지 않도록 한다. 명시되지 않은 부문·공법을 정답 정보에서 검색기로 넘기지 않는다.

## 2. 같은 자료에서 검색 표현을 생성

가능하면 기존 전체 청크를 같은 입력으로 사용해 관련 없는 공종도 후보에 남긴다. 185쪽 주변의 소수 표만 검색해 놓고 전체 공종 검색이 개선됐다고 말하지 않는다.

같은 자료로 다음 표현을 자동 생성한다.

1. **공종 목록용:** 문서·부문·절 번호·제목·기존 자료에 명시된 소제목·작업 유형. 표가 여러 개여도 목록 결과는 공종으로 묶는다. 계산 명세가 없는 공종과 설명 절도 제외하지 않는다.
2. **규칙 설명용:** 조건·결과·예외가 함께 있는 원문 문장 또는 문단. 잘라서 독립적으로 이해하기 어려우면 원래 청크를 유지하고 부모 조회로 보완한다. 상위 절 규정도 포함한다.
3. **표·작업 조건용:** 기존 표 청크 또는 기존 시제품의 완결된 행 묶음. 제목·기준·머리글·단위·원문 식별자를 연결한다.

공종별 수작업 설정이나 질문별 정답 절 번호 가산을 만들지 않는다. 자료에 없는 작업 유형·적용 범위는 추측해 채우지 않는다. 원문 식별자와 부문을 유지하고, 같은 절 번호를 부문 간에 합치지 않는다.

ODL의 개선된 12쪽 자료와 기존 전체 청크는 품질과 범위가 다르다. **전체 검색 표현 비교는 동일한 기존 자료로**, ODL 근거 조립 연결은 별도 사례로 보고한다. 특정 정답 쪽만 ODL로 교체한 결과를 청킹만의 효과로 보고하지 않는다.

## 3. 비교 구성

기준 코드의 BM25 토큰화·설정을 읽어 오프라인 계산을 재사용한다. import가 설정·API에 연결될 우려가 있으면 필요한 순수 계산 부분만 실험 폴더에서 재사용한다.

| 구성 | 하는 일 | 확인 목적 |
|---|---|---|
| 가 | 기존 청크의 키워드 검색 | 현재 검색 표현의 기준 결과 |
| 나 | 질문 의도에 맞는 목록·규칙·표 표현 검색 | 검색 결과가 더 적절해지는지 |
| 다 | 나의 같은 검색 결과에 부모·주석·조건부 참조 조회를 연결 | 근거가 빠짐없이 전달되는지 |

나와 다의 검색 순위는 동일하게 유지한다. 다에서 근거를 더 붙인 것을 검색 순위 개선으로 세지 않는다. 세 기능은 함께 쓰는 최종 구조의 단계별 비교이며 하나만 고르는 후보가 아니다.

상위 5개 후보를 공종 단위와 원문 근거 단위로 각각 보고한다. 청크가 많은 절이 중복 결과로 목록을 채우지 않게 한다. BM25 점수 크기는 서로 다른 색인의 점수끼리 직접 비교하지 않는다.

실무 표현 차이(펌프카·펌프차, 루베·㎥ 등)는 공통 표현 정규화로 다룰 수 있다. 사용한 규칙을 미리 고정하고 가·나 모두 동일하게 적용한다. 질문별 수동 보정이나 공종 번호를 삽입하는 확장은 금지한다. 명시된 부문은 사용할 수 있지만 추정 부문으로 후보를 강제 제외하지 않는다.

## 4. 근거 상태의 보완

앞선 결과는 상위 절 일반 규정 4건을 선택 문맥으로 두고 일부를 길이 제한으로 생략했다. **적용 여부 미확정은 중요하지 않다는 뜻이 아니다.** 다음 세 가지를 구분한다.

- 이번 질문에 필요한 적용 조건·산출 기준·단위·관련 주석: 필수.
- 적용될 가능성이 있지만 범위를 아직 확인하지 못한 상위 규정·주석: 적용 범위 미확정. 생략되면 열린 항목에 남기며, 계산 근거가 완성됐다고 표시하지 않는다.
- 답에 필요하지 않은 주변 설명: 선택.

이번 단계에서 미확정 규정을 모두 해석하는 새 규칙을 만들 필요는 없다. 상태가 정확하게 전달되게 한다. `전달 완료`와 `적용 범위 확인 완료`를 별도로 표시한다.

새로 발견된 `(100㎡당)` 누락은 검색 개선으로 고쳐진 값이 아니다. PDF 보완 출처를 표시하고, 기존 원문 입력의 누락으로 보고한다. 검색 성공과 자료 결함을 분리한다.

## 5. 평가와 중단 기준

문장마다 질문, 기대 후보, 가·나 상위 5개, 다의 전달 근거와 원문 위치, 미확정·누락, 잘못 검색된 이유를 비교한다.

보고할 지표:

- 정답 후보가 있는 질문의 공종 적중률 상위 1개·5개. 복수 후보 질문은 기대 후보 집합을 명시한다.
- 규칙 질문의 필요한 원문 근거 적중 여부.
- 목록 결과 중 관련 공종 수·중복 수·관련 없는 공종 수. 전체 정답을 모르면 전체 재현율은 보고하지 않는다.

- 표·기준·단위·주석·참조의 전달 여부와 열린 항목.
- 색인 생성 시간, 질문별 검색 시간, 근거 조회 시간. 같은 로컬 실행 조건에서 측정한다.

키워드 검색이 짧은 실무 표현을 못 찾으면 그 한계를 기록한다. API 금지 조건에서 의미 검색·재정렬·LLM 답변 성능을 입증하려 하지 않는다.
