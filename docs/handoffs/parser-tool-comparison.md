# 품셈 파싱 도구 비교 작업 지시서

## 이번 작업의 목표

한국 건설 표준품셈 2026년판에서 표와 계산 근거를 가장 정확하게 보존하는 파싱 방식을 비교하고, 주력 도구와 전체 재파싱 여부를 추천한다. 기존 PyMuPDF 개선, OpenDataLoader, Docling 모두 후보이며 유지나 교체를 미리 결정하지 않는다.

이 세션에서는 비교 실험과 판단까지 진행한다. 운영 파이프라인 전환, 전체 재파싱, 청크 일괄 교체, 임베딩 재생성은 하지 않는다.

## 서비스와 배경

- 이미 운영 중인 건설 품셈·공사비 견적 챗봇이다. 홍보 전 단계이며 개발자는 한 명이다.
- 사용자 목표는 관련 기준 목록, 원문 설명, 품 산출, 단일 공종 견적, 여러 공종을 합친 견적과 실무에 사용할 Excel이다.
- 결과는 가정이 표시된 초안이지만 숫자 정확성·근거·재현성이 중요하다.
- 공종은 천 개 이상이며, 공종별 수동 예외 설정을 계속 추가하는 방식은 원하지 않는다.
- 지금은 실무자 검토를 받을 수 없다. 원문으로 확인할 수 있는 항목부터 진행하고, 해석이 불명확한 부분은 미확정으로 남긴다. 실무자 검토를 작업의 선행 조건으로 두지 않는다.
- 파싱은 사전 처리이므로 속도보다 정확성을 우선하되, 실행 시간·자원·유지보수 부담도 기록한다.

10. 사용자에게는 한국어로 답하고 한자를 쓰지 않는다. 코드 식별자와 도구 이름은 원래 표기를 사용할 수 있다.

## 비교 구성

| 후보 | 목적 |
|---|---|
| 현재 PyMuPDF 경로 | 운영 데이터 처리 방식의 기준 |
| 이전 PyMuPDF 개선 시제품 | 자체 보완이 충분한지, 정상 표 회귀가 있는지 |
| OpenDataLoader | 다른 추출 방식의 정보 보존·구조 인식 비교 |
| Docling | 표 구조 인식 방식 비교 |

도구별 버전, 실행 설정, 로컬 모델 사용 여부를 기록한다. OpenDataLoader 기본 모드와 하이브리드 모드를 같은 후보로 뭉뚱그리지 않는다. 외부 API가 필요한 모드는 이번 제약에서 제외한다. 실행할 수 없는 후보는 이유를 표시한다. 기존 산출물 재평가와 이번 재실행을 구분한다.

## 평가 방법

### 두 단계를 분리한다

1. **추출 결과**: 도구가 직접 만든 표의 글자·칸·좌표·행열·병합 범위.
2. **가공 결과**: 검색과 계산에 전달되는 머리글 경로·기준 단위·주석 연결·원문 위치.

모든 출력에 기존 문자열 변환기를 무조건 적용하지 않는다. 공통 평가 표현으로 필요한 정보를 보존해 비교하고, 도구별 구조 변환에서 생긴 오류는 별도로 기록한다. 추출기가 잘 읽었는데 후처리가 망가뜨린 경우를 구분한다.

### 표 선택

- 기존에 확인한 표와 정답 초안을 재사용해 반복 작업을 줄인다.
- `p185-t0`를 정상 표 회귀 대조군으로 반드시 포함한다.
- 거푸집 유형표, 병합 시공량 표, 압송관 기준 표, 10개소당 등 기준 수량이 다른 표를 포함한다.
- 작은 표만 고르지 않는다. 큰 표, 복잡한 머리글, 선이 없는 표, 여러 쪽에 이어지는 표도 확인한다.
- 개발용 표와 별도 평가용 표를 구분한다. 평가 표를 보고 방법을 고치면 그 표는 개발용으로 재분류한다.
- 별도 평가 대상·설정·채점 기준을 먼저 고정한다. 결과를 본 뒤 특정 후보에 유리하도록 바꾸지 않는다.
- 처음에는 비교에 충분한 제한된 표본으로 한 번 평가한다. 작은 실패를 보고 같은 표에 계속 맞추는 반복 개발로 범위를 넓히지 않는다.

### 정확성 기준

- 수치·부호·단위·기준 수량은 정확히 일치해야 한다.
- 행 이름과 열 조건에 올바른 값이 연결돼야 한다. 값이 문서 어딘가에 있는 것만으로 통과시키지 않는다.
- 병합된 공동 시공량을 여러 독립 값으로 잘못 해석하거나 중복 계산하지 않는다.
- 글자 유사도만으로 조건·부정·범위·제외 규칙을 통과시키지 않는다.
- 단순 장식 머리글 누락과 계산에 필요한 정보 누락은 따로 집계한다.
- 기준 단위와 주석은 연결 대상까지 확인한다. 불명확한 연결을 확정하지 않는다.
- 정답 초안은 원문 표·주석을 대조해 사용한다. 현재 청크나 계산 명세만으로 정답을 만들지 않는다. LLM이 작성한 정답과 실제 계산 검산을 구분한다.
- 전체 평균 외에 정상 표 회귀, 중요 수치 오연결, 불완전 결과를 정상으로 판정한 사례를 별도 보고한다.

## 완료 기준과 결과 형식

계속 비교 계획만 작성하지 말고, 가능한 후보는 실제 로컬 비교를 수행해 결과를 낸다. 불가능한 후보는 구체적인 원인을 남긴다.

최종 답변은 다음 내용을 포함한다.

1. 결론 세 줄: 주력 후보, 현재 결과의 신뢰 범위, 전체 재파싱 권장 여부.
2. 후보별 비교표: 평가 표본, 중요 정보 누락, 잘못된 연결, 정상 표 회귀, 기준·주석 오류, 시간·자원, 실행 또는 기존 결과 재평가 여부.
3. 대표 실패 사례: 원문과 추출·가공 결과의 차이, 실패가 생긴 단계.
4. 주력 후보 추천과 근거. 단일 도구가 부족할 때만 보조 경로를 제안하고 유지보수 부담을 설명한다.
5. 선택한 도구 뒤에 필요한 최소 후처리와 검증.
6. 데이터 재처리 범위와 이후 청킹·검색 비교의 다음 작업 하나.
7. 실험 파일 절대 경로, 도구 버전·설정, 재현 명령, 저장소 변경 여부.

운영 교체나 임베딩 재생성은 이 결과를 검토한 뒤 별도 작업으로 진행한다.
