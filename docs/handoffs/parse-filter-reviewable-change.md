# 이번 작업 하나: 파싱 필터 수정안을 검토 가능한 형태로 정리

## 결론과 범위

186·195쪽에서는 블록 전체를 표 안 글자로 제외하면서 기준이 사라졌다. 645쪽에서는 제목 블록 전체를 제외하면서 기준이 사라졌다. 줄별 판정으로 세 사례의 기준이 보존됐고, 186쪽에서는 보존한 기준이 기존 청킹 함수로 표에 연결됐다.

이번에는 **기준 코드 `baf186f`의 `pipeline/parse.py` 안 `read_text_blocks` 함수 하나의 수정안**을 정리한다. 운영 파일을 고치는 실행이 아니라, 함수의 제안 코드와 확인 결과를 문서로 제출하는 작업이다. 청킹 수정은 포함하지 않는다.

## 할 일

1. `read_text_blocks`의 수정 전후 차이를 하나의 제안 코드로 정리한다. 함수의 반환 형식과 호출부는 유지한다.
2. 제목 제외·표 안 글자 제외는 줄별로 판정한다. 앞선 시제품의 줄 중심·±2pt를 사용한다. 쪽 머리글 제외 방식은 이번 범위에서 유지한다.
3. 일반 설명·주석까지 전부 한 줄짜리 레코드로 쪼개지 않는다. 제외되는 줄이 없는 기존 글자 블록은 원래 묶음과 내용을 유지한다. 일부 줄을 제외한 경우 남은 연속된 글만 묶고 원문 위치 순서를 유지한다. 제목·표를 사이에 둔 떨어진 글을 하나로 다시 합치지 않는다.
4. 운영 코드나 파이프라인 전체를 실행하지 않고 제안 함수를 메모리에서 검사한다. 기존 표 좌표와 PDF 글자층만 사용한다. 이미 확인한 186·195·645쪽에서 기준 보존·표 안 중복 없음·제목 추출 유지·주변 주석 유지가 그대로인지 확인한다.
5. 작은 기능 검사 두 가지를 추가한다. 변경이 필요 없는 일반 설명 블록이 같은 반환 내용을 갖는지, 경계 안과 밖의 줄에서 기존 ±2pt 판정이 유지되는지 확인한다. 인위적 기능 검사를 새 품셈 표본 검증이라고 부르지 않는다.

실패한 경우 페이지별 예외나 새 규칙을 덧붙여 범위를 늘리지 말고, 실패 내용과 제안의 한계를 보고한다.

## 청크 ID에 대한 고지

기준 레코드 추가로 뒤따르는 줄글 ID가 `p186-x4`에서 `p186-x5`로 바뀌는 것은 현재 ID 생성 방식의 영향이다.

기준 코드의 청크 ID 사용처를 제한적으로 읽고, 재생성한 청크와 기존 벡터·캐시·저장된 근거를 혼용할 위험이 있는지 기록한다. 이 영향 때문에 청킹·ID·임베딩 코드를 함께 수정하지 않는다. 실제 데이터 갱신 시 대응해야 할 사항으로만 남긴다. 운영 서버·DB의 저장 상태는 확인하지 않는다.

## 제약

- 저장소 코드·설정·데이터·루트 가상환경은 변경하지 않는다. 커밋·푸시·PR·배포는 금지한다.
- LLM·임베딩·네트워크 API, 운영 서버·DB, 비밀값 파일 읽기는 금지한다.
- 설치·다운로드·새 파서 실행은 하지 않는다. PDF 기존 글자층 읽기와 함수의 메모리 검사만 수행한다.
- 검사는 루트 `.venv/Scripts/python.exe`, `AGENT_OFFLINE=1`, `AGENT_LLM=off`, `PYTHONDONTWRITEBYTECODE=1`, `-B`로 한다. 서비스·설정 로더를 실행하지 않는다.
- 결과 문서만 `docs/reviews/parse-filter-reviewable-change-result.md`에 작성한다.

## 제출 형식

사용자에게 먼저 아래를 설명한다.

- 바꿀 곳: 파싱 파일의 함수 하나.
- 바뀌는 행동: 제목·표 안 글자는 제외하되 바깥 기준은 보존.
- 확인 결과: 세 원문 사례와 두 기능 검사의 결과.
- 실제 적용 전 남은 것: 전체 파이프라인 회귀 검사, 청크·벡터 갱신 시 ID 대응.

그 뒤 수정 전후 diff 또는 교체할 함수 전체를 문서의 코드 블록으로 넣는다. 실제 저장소 파일에 적용하지 않는다. 결과 문서의 절대 경로를 보고하고 작업을 종료한다.
