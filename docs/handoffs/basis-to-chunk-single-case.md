# 이번 작업 하나: 보존한 기준이 청크까지 전달되는지 확인

## 목적

186쪽 `p186-t0`의 `(100㎡당)`을 파싱 필터에서 보존한 뒤, 기존 청킹 함수가 이 표의 `basis`와 검색용 글에 넣는지 확인한다.

앞선 두 종류의 필터 검사는 끝났다. 표 안 제외 필터는 186·195쪽, 제목 제외 필터는 645쪽에서 줄별 판정으로 기준을 보존했다. 이번에는 이 검사를 반복하거나 다른 표를 늘리지 않는다.

## 할 일

1. PDF 186쪽의 기존 글자층과 기존 표 좌표를 사용해, 앞서 확인한 줄별 필터 방식으로 `(100㎡당)`을 남긴다. 새 표 추출은 하지 않는다.
2. 이 기준 줄을 기존 파싱 코드와 같은 레코드 형식으로 만들고, 원문 순서와 해당 절을 유지한다. 기준을 청크에 직접 대입하지 않는다.
3. 해당 표의 기존 파싱 레코드가 로컬에 있으면 그것을 재사용한다. 없으면 기존 표 청크로부터 최소한의 기능 검사 입력을 구성하고, 원래 파싱 레코드를 재현한 것이 아니라는 한계를 명시한다. 기준과 표의 연결을 정답으로 미리 넣지 않는다.
4. 기준 코드 `make_chunks`를 메모리에서 실행해 `p186-t0`의 `basis`가 `(100㎡당)`인지, 검색용 글에 `기준 (100㎡당)`이 포함되는지 확인한다. 함수 호출 시 부문 정보는 기존 자료에서 명시적으로 전달하고 서비스·설정 로더를 실행하지 않는다.
5. 기존 입력과 기준 줄을 보존한 입력을 비교한다. 표 숫자·주석 내용을 임의로 고치지 않는다. 실패하면 실패 위치를 보고하고 종료한다.

이번에는 청킹 함수 수정, 운영 코드 반영, 계산·임베딩·검색, 183개 후보 전체 검사를 하지 않는다.

## 제약

- 저장소 코드·설정·데이터·루트 가상환경을 수정하지 않는다. 커밋·푸시·PR·배포는 금지한다.
- LLM·임베딩·네트워크 API, 운영 서버·DB, 비밀값 파일 읽기는 금지한다.
- 설치·다운로드·새 파서 실행은 하지 않는다. PDF 기존 글자층 읽기와 기존 함수의 메모리 검사는 허용한다.
- 검사는 저장소 루트 `.venv/Scripts/python.exe`, `AGENT_OFFLINE=1`, `AGENT_LLM=off`, `PYTHONDONTWRITEBYTECODE=1`, `-B`로 한다.
- 결과 문서만 `docs/reviews/basis-to-chunk-single-case-result.md`에 작성한다.

## 보고 형식

첫 문장에 `보존한 기준이 기존 청킹 함수로 표에 연결됐다` 또는 `표에 연결되지 않았다`를 적는다.

그 아래 다음 세 항목을 기존 방식과 시제품 입력으로 비교한다.

- 파싱 레코드에 `(100㎡당)`이 존재하는지.
- 표 청크의 `basis` 값.
- 검색용 글에 `기준 (100㎡당)`이 포함되는지.

입력 출처와 한계를 표시한다. 기존 파싱 레코드 없이 기능 검사 입력으로 확인했다면 전체 파이프라인 검증이라고 보고하지 않는다. 결과 문서의 절대 경로를 보고하고 이번 작업을 종료한다.
