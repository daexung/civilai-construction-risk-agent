# 이번 작업 하나: 같은 방법으로 195쪽 기준이 보존되는지 확인

## 목적

186쪽에서 확인한 `블록 대신 줄 위치로 표 안 글자를 제외하는 방식`이 195쪽의 다른 표에도 통하는지 확인한다. 방법을 변경하지 않고 표 하나만 검사한다.

## 입력

- 앞선 결과: `C:\Users\user\Desktop\PROJECTS\civilai-construction-risk-agent\docs\reviews\parse-basis-loss-single-case-result.md`
- 기준 코드: `baf186f`의 `pipeline/parse.py`
- 대상: 기존 청크 `p195-t3`, PDF 195쪽의 6-3-5 맨홀 거푸집 표
- 확인할 기준 문구: `(개소당)`

## 할 일

1. 186쪽에서 사용한 시제품 방법과 허용 범위 ±2pt를 그대로 재사용한다. 구현 파일이 없으면 앞선 결과에 적힌 방법을 메모리에서 재현하고 그 사실을 적는다.
2. 기존 청크의 해당 쪽 표 좌표와 PDF의 기존 글자층을 읽는다. 새 표 추출은 하지 않는다.
3. 기존 방식과 시제품에 같은 입력을 넣어 `(개소당)`이 남는지, 표 안 글자가 바깥 설명으로 중복 남는지, 주변 주석이 유지되는지 비교한다.
4. 결과를 보고하고 종료한다. 실패하면 원인과 위치를 보고하되 새 규칙으로 고쳐 다시 돌리지 않는다.

## 제약

- 운영 코드·설정·데이터·루트 가상환경을 수정하지 않는다. 커밋·푸시·PR·배포는 금지한다.
- LLM·임베딩·네트워크 API, 운영 서버·DB, 비밀값 파일 읽기는 금지한다.
- 설치·다운로드·새 파싱 실행은 하지 않는다. PDF의 기존 글자층 읽기만 사용한다.
- 검사는 루트 `.venv/Scripts/python.exe`, `AGENT_OFFLINE=1`, `AGENT_LLM=off`, `PYTHONDONTWRITEBYTECODE=1`, `-B`로 한다.
- 시제품 검사는 메모리에서 한다. 결과 문서만 `docs/reviews/parse-basis-loss-second-case-result.md`에 작성한다.
- 제목 필터·청킹·검색·기준 연결은 작업하지 않는다. 다른 표를 추가하거나 후속 작업을 시작하지 않는다.
