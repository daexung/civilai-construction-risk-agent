# 다음 작업: OpenDataLoader와 Docling 실제 비교

## 목표

같은 품셈 표를 현재 PyMuPDF, OpenDataLoader, Docling으로 읽고 어떤 도구를 주력으로 쓸지 추천한다. 기존 PyMuPDF 개선 시제품은 확보된 결과만 비교에 포함하며 더 고치지 않는다.

이전 세션은 OpenDataLoader와 Docling이 설치되지 않아 두 도구를 새 평가 표에 실행하지 못했다. 그 때문에 도구 선택은 아직 끝나지 않았다. 이번 작업은 그 빈 부분을 채우는 것만 한다.

## 설치 승인

현재 사용자의 기본 조건은 읽기 전용이다. 이 문서는 설치 승인을 대신하지 않는다.

사용자가 별도로 허용한 경우에만 저장소 밖 실험 환경에 패키지와 필요한 로컬 모델을 설치·다운로드한다. 저장소 루트 `.venv`를 변경하지 않는다. 별도 환경의 파이썬 실행도 사용자 허용 범위에 포함돼야 한다. 사용자 승인이 없으면 필요한 설치 항목만 보고하고 설치하지 않는다.

이 허용은 로컬 문서 처리 도구에만 적용한다. LLM·임베딩 API, 외부 추론 서비스, 운영 서버·운영 DB 사용은 계속 금지한다. 자동 원격 처리·API 대체 경로는 끈다.

## 실행 범위

1. 설치 승인 범위를 확인하고 두 후보를 실행할 수 있는 별도 로컬 환경을 준비한다. 설치된 버전과 모델·설정을 기록한다. 설치 불가면 원인을 보고하고 다른 후보는 계속 비교한다.
2. 이전 평가 표를 그대로 사용한다. `p185-t0` 정상 표 대조군은 반드시 포함한다.
3. OpenDataLoader의 로컬 모드와 Docling의 로컬 PDF 처리 경로를 실제 실행한다. 모드와 모델을 명시한다. 설치된 버전이 과거 기록과 다르면 구분한다.
4. 추출 결과와 후처리 결과를 따로 비교한다. 기존 문자열 변환기가 새 도구의 구조를 망가뜨리지 않도록 원본 구조를 먼저 평가한다.
5. 숫자·단위·기준 수량·행열 연결·병합 관계·기준과 주석 연결을 검사한다. 숫자 포함 여부나 문장 유사도만으로 정확하다고 판정하지 않는다.
6. 사용자가 원문을 직접 볼 수 있도록 PDF 185쪽의 비교 문서를 먼저 만든다. 현재 PyMuPDF·OpenDataLoader·Docling의 실제 출력을 같은 열 구성의 표로 보여 주고, 비고 안의 작은 표·공유 시공량·6-1-3 참조 문구도 각각 포함한다. 도구가 빠뜨리거나 잘못 연결한 정보를 사람이 채워 넣어 결과를 좋아 보이게 하지 않는다. 불명확하거나 옮길 수 없는 관계는 표시한다. 추정 표시·좌표·내부 행 번호는 본문과 분리된 검사 메모에 둔다. 원본 출력 파일도 보존하고 절대 경로를 링크한다.

저장소 코드·설정·기존 데이터 수정, 커밋·푸시·PR·배포, 비밀값 파일 열람은 금지한다. 저장소 `tmp/` 문서는 읽지 않는다. 실험 파일은 저장소 밖 작업 폴더에 두고 절대 경로를 보고한다. 로컬 실행에 `AGENT_OFFLINE=1`, `AGENT_LLM=off`, `PYTHONDONTWRITEBYTECODE=1`을 적용한다.

## 완료 기준

가능한 두 후보를 같은 표로 실행한 뒤 다음을 한국어로 보고한다. 한자는 쓰지 않는다.

1. 추천 도구와 근거를 먼저 세 줄로 제시한다. 결론이 불충분하면 무엇이 부족한지 명시한다.
2. 후보별 중요 정보 누락, 잘못된 연결, 정상 표 회귀, 기준·주석 오류를 같은 기준으로 비교한다.
3. 원문과 출력을 대조할 대표 사례를 성공·실패 각각 보여 준다.
   - PDF 185쪽 사람이 볼 비교 문서와 후보별 실제 원본 출력의 절대 경로를 제공한다. 최종 점수만 보고하지 않는다.
4. 도구 버전·설정·실행 여부, 정답 초안의 한계, 설치 및 결과 파일 경로를 기록한다.
5. 마지막에 운영 변경 전 다음 작업 하나만 제안한다.

이번에는 도구 선택에 필요한 비교를 끝내고 멈춘다. 운영 반영은 별도 승인과 작업이다.
