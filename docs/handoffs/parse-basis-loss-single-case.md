# 이번 작업 하나: 186쪽의 산출 기준 보존

이 지시서는 이전 `basis-association-offline-pilot.md`의 이번 실행 범위를 대체한다. 이전 지시서의 전체 작업은 실행하지 않는다.

## 목적

186쪽 6-1-3 표의 `(100㎡당)`이 파싱 필터에서 사라지지 않게 하는 시제품을 확인한다.

확인된 원인: 기준 코드 `baf186f`의 `pipeline/parse.py:95-100`은 글자 블록 중심이 표 안에 있으면 블록 전체를 버린다. 이 쪽은 `(100㎡당)`과 표 안 글자가 같은 블록에 묶여 기준도 함께 사라진다.

## 할 일

1. `git show baf186f:pipeline/parse.py`로 기준 코드를 읽는다.
2. 기존 `p186-t0`의 표 좌표와 PDF 186쪽의 기존 글자층을 사용한다. 새 표 추출은 하지 않는다.
3. 블록 전체를 버리는 대신 줄과 위치를 구분해 표 바깥 `(100㎡당)`을 남기는 방법 하나를 메모리 시제품으로 확인한다. 표 안 글자를 바깥 설명으로 중복 남기지 않는지도 이 표에서 확인한다.
4. 기존 방식과 시제품의 남은 글자를 나란히 보고한다.

이번에는 645쪽·195쪽·183개 후보, 제목 필터, 청킹, 검색, 주석·참조 조회를 작업하지 않는다. 다른 표에서도 일반적으로 맞는지는 다음 작업에서 확인한다.

## 제약

- 저장소 코드·설정·데이터·루트 가상환경을 변경하지 않는다. 커밋·푸시·PR·배포는 금지한다.
- LLM·임베딩·네트워크 API, 운영 서버·DB, 비밀값 파일 읽기는 금지한다.
- 설치·다운로드·새 파싱 실행은 하지 않는다. PDF의 기존 글자층 읽기만 사용한다.
- 검사는 루트 `.venv/Scripts/python.exe`, `AGENT_OFFLINE=1`, `AGENT_LLM=off`, `PYTHONDONTWRITEBYTECODE=1`, `-B`로 한다. 서비스·설정 로더를 실행하지 않는다.
- 시제품은 메모리에서 검사하고, 결과 문서만 `docs/reviews/parse-basis-loss-single-case-result.md`에 작성한다.
