# 이번 작업 하나: 제목과 함께 묶인 기준 문구 보존

## 목적

645쪽 `p645-t0`의 `(㎡당)`이 제목 제거 과정에서 사라지지 않게 하는 메모리 시제품을 확인한다.

186·195쪽은 표 안 글자를 제외하는 필터에서 기준이 사라졌다. 이 두 사례의 검사는 반복하지 않는다. 이번 대상은 원인이 다른 제목 필터다.

## 확인된 원인

기준 코드 `baf186f`의 `pipeline/parse.py:91-92`는 제목으로 시작하는 글자 블록 전체를 제거한다. PDF 645쪽은 `4-1-1 먹매김('15년 보완)`과 `(㎡당)`이 같은 블록에 들어 있으므로 기준도 함께 사라진다.

## 할 일

1. 기준 코드는 `git show baf186f:pipeline/parse.py`로 읽는다.
2. 기존 청크 `p645-t0`의 표 좌표와 PDF 645쪽의 기존 글자층을 사용한다. 새 표 추출은 하지 않는다.
3. 제목 판정을 블록 전체 대신 줄별로 하는 방법을 메모리에서 확인한다. 제목 줄은 본문에서 제외하고, 표 밖 `(㎡당)` 줄은 남긴다. 앞선 표 안 글자 제외 방식의 줄 중심·±2pt는 그대로 유지한다.
4. 같은 입력으로 기존 방식과 시제품을 비교한다. 제목이 기존 `read_titles`에서 유지되는지, 본문에 제목이 중복 남지 않는지, 기준은 남는지 확인한다.

이번에는 183개 후보 전체·청킹·검색·주석 연결·운영 적용을 작업하지 않는다. 기준 문구가 남는 것과 해당 표에 최종 연결되는 것을 구분한다.

## 제약

- 저장소 코드·설정·데이터·루트 가상환경을 수정하지 않는다. 커밋·푸시·PR·배포는 금지한다.
- LLM·임베딩·네트워크 API, 운영 서버·DB, 비밀값 파일 읽기는 금지한다.
- 설치·다운로드·새 파싱 실행은 하지 않는다. PDF의 기존 글자층 읽기만 사용한다.
- 검사는 루트 `.venv/Scripts/python.exe`, `AGENT_OFFLINE=1`, `AGENT_LLM=off`, `PYTHONDONTWRITEBYTECODE=1`, `-B`로 한다.
- 시제품은 메모리에서 검사한다. 결과 문서만 `docs/reviews/parse-basis-title-single-case-result.md`에 작성한다.
