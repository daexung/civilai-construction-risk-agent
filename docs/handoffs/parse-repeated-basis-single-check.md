# 이번 작업 하나: 같은 절의 반복 기준이 지워지는지 확인

## 목적

줄별 필터 수정안은 준비됐다. 이번에는 그 이후 `parse_pages`의 동일 문자열 제거가 같은 절에서 반복된 기준을 지우는지 한 사례로 확인한다.

기준 코드: `baf186f:pipeline/parse.py:337-344`. 운영 파일에는 적용하지 않는다.

## 할 일

1. 같은 절에 서로 다른 표 두 개가 있고 각 표 앞에 `(일당)` 기준이 있는 최소 기능 검사 입력을 메모리에서 만든다. 이 입력은 가상 기능 검사이며 실제 PDF 파싱 결과라고 하지 않는다.
2. 기준 코드의 중복 제거 로직을 그대로 적용해 두 번째 기준 레코드가 남는지 확인한다. 새 PDF 파싱은 하지 않는다.
3. 제거된다면 기준 레코드를 문자열 중복 제거에서 보존하는 최소 수정안을 문서에 제시하고, 두 기준이 각각 표 앞에 남는지 메모리에서 확인한다. 일반 설명의 중복 제거 정책 전체를 바꾸지 않는다. 새 라이브러리·쪽별 예외·청킹 변경은 포함하지 않는다.
4. 원문 위치가 서로 다른 같은 문자열은 동일한 출현이 아니라는 이유를 사용자에게 한 문단으로 설명한다.

줄별 필터 검사를 반복하거나 183개 후보를 처리하지 않는다. 제목 오인 가능성 등은 기존 수정안의 한계로 유지하며 이번 검사로 해소됐다고 하지 않는다.

## 제약

- 저장소 코드·설정·데이터·루트 가상환경은 변경하지 않는다. 커밋·푸시·PR·배포는 금지한다.
- LLM·임베딩·네트워크 API, 운영 서버·DB, 비밀값 파일 읽기는 금지한다.
- 설치·다운로드·새 파서 실행은 하지 않는다.
- 검사는 루트 `.venv/Scripts/python.exe`, `AGENT_OFFLINE=1`, `AGENT_LLM=off`, `PYTHONDONTWRITEBYTECODE=1`, `-B`로 메모리에서 한다.
- 결과 문서만 `docs/reviews/parse-repeated-basis-single-check-result.md`에 작성한다.

## 보고와 종료

먼저 표 앞 기준 2개의 보존 여부를 `기존 중복 제거 → 최소 수정안`으로 보여준다. 수정안은 코드 블록으로 제시한다. 실제 파일에 적용하지 않는다.

이번 작업은 반복 기준 보존의 기능 검사만 확인한다. 전체 파이프라인 회귀 검사와 운영 적용은 미실행으로 명시한다. 결과 문서의 절대 경로를 보고하고 종료한다.
