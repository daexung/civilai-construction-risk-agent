# 이번 작업 하나: 고정한 파싱 수정안의 소규모 회귀 검사

## 목적

실제 PDF 186·195·645쪽에서 기준 문구가 파싱부터 청킹까지 전달됐다. 같은 개발 사례의 검사는 끝낸다.

이번에는 **지금까지 이 파싱 필터 수정에 사용하지 않은 최대 6쪽**에서, 수정안 때문에 정상 본문·주석·표가 사라지는지 확인한다. 규칙을 추가하거나 검색·계산을 작업하지 않는다.

## 먼저 고정할 것

- 기준 코드: `baf186f`의 `pipeline/parse.py`, `pipeline/chunk.py`.
- 수정안: `docs/reviews/parse-filter-reviewable-change-result.md`의 함수와 `docs/reviews/parse-repeated-basis-single-check-result.md`의 기준 보존 조건. 다른 수정은 넣지 않는다.
- 읽을 이전 결과: `docs/reviews/parse-to-chunk-three-page-check-result.md`.
- 수정안 코드의 해시와 검사 쪽 번호를 **비교 실행 전에** 기록한다.

## 검사 자료 선택

기존 로컬 처리 자료의 표·절 위치로 후보를 고른다. 이번 필터 개발에 사용한 186·195·645쪽은 제외한다. 다른 이전 작업에서 이미 본 쪽이면 그 사실을 고지한다.

가능하면 서로 다른 부문의 표가 있는 쪽, 줄글·주석이 있는 쪽, 같은 절이 다음 쪽으로 이어지는 구간을 포함한다. 연속 구간은 함께 파싱하며 첫 쪽 이전의 문맥은 확인 범위 밖으로 남긴다. 총 쪽 수는 6을 넘기지 않는다.

쪽 선택 후 결과가 좋을 때까지 다른 쪽으로 교체하지 않는다. 제목처럼 보이는 본문 줄이 선택한 자료에 없으면 그 위험을 검사하지 못했다고 적는다.

## 한 번의 비교

1. 기준 코드와 두 수정안만 반영한 코드를 메모리에 만든다.
2. 선정한 실제 PDF 쪽을 같은 로컬 환경에서 파싱하고 기존 청킹 함수에 전달한다. 파일로 파싱·청킹 데이터를 저장하지 않는다. 부문 정보는 기존 자료에서 명시적으로 전달한다.
3. 표는 제목·쪽·좌표로 대응시켜 숫자·단위·표 내용·구조 상태가 바뀌지 않았는지 비교한다.
4. 줄글은 레코드 개수·ID만 비교하지 말고 원문 내용과 위치로 비교한다. 기존에 남던 본문·주석이 수정안에서 사라지면 해당 줄을 원문에서 확인한다. 실제 제목·표 안 중복 제거인지, 본문 손실인지 구분한다.
5. 추가로 남은 기준·줄글이 어느 위치에서 나온 것인지 보고한다. 모든 추가 글자를 정상 복원으로 단정하지 않는다.
6. 수정안이 본문 속 `숫자-숫자` 참조 줄을 제목으로 지우는 사례가 있는지 확인한다. 확인 가능한 사례가 없으면 미검사로 남긴다.

실패하면 실패 위치와 내용을 제출한다. 이번 확인 결과를 보고 수정안을 고쳐 같은 자료로 반복 실행하지 않는다.

## 제약

- 저장소 코드·설정·데이터·루트 가상환경은 변경하지 않는다. 커밋·푸시·PR·배포는 금지한다.
- LLM·임베딩·네트워크 API, 운영 서버·DB, 비밀값 파일 읽기는 금지한다.
- 설치·다운로드·전체 PDF 재파싱은 하지 않는다. API 없는 로컬 검사로 선정한 최대 6쪽의 파서 함수만 메모리에서 실행한다.
- 루트 `.venv/Scripts/python.exe`, `AGENT_OFFLINE=1`, `AGENT_LLM=off`, `PYTHONDONTWRITEBYTECODE=1`, `-B`로 검사한다. 파일을 쓰는 파이프라인 `main`은 실행하지 않는다.
- 결과 문서만 `docs/reviews/parse-filter-small-regression-result.md`에 작성한다.

## 보고와 다음 결정

첫 부분에 쪽별 `표 값 유지 / 본문·주석 유지 / 새로 남은 기준 / 미확인`을 한 표로 보여준다.

그 다음 `기존 정보의 확인된 손실이 있었는가`를 명확히 적고, 손실이 있다면 원문 위치를 제시한다. 새 표본에서의 검사이며 전체 문서 검증이 아니라는 점을 밝힌다.

결과가 통과하면 이번 수정안의 코드 반영 여부와 실제 적용 전 필요한 데이터·벡터 갱신 범위를 결정한다. 코드 반영과 갱신은 현재 읽기 전용 범위에 포함되지 않으므로 자동으로 실행하지 않는다. 결과 문서의 절대 경로를 보고하고 종료한다.
