# 첫 개발 사례: 콘크리트 타설 노무량

외부 실무자 검토를 개발 시작의 전제 조건으로 두지 않는다. 우선 공개 원문의
조건을 고정한 계산 사례를 만들고, 실무 적용성 검토는 별도로 남긴다.

## 입력과 기대 결과

- 2026년 표준품셈 정오표 1차 반영본, 공통부문 6-1-1.
- PDF 185쪽 / 인쇄 129쪽.
- 철근구조물 100㎥, 인력운반 타설이 가능한 현장으로 가정.
- 소량 타설 위치 산재 및 기타 생산성 조정·할증은 적용하지 않는 개발 예제.
- 일당 시공량 20㎥, 콘크리트공 3인, 보통인부 3인.
- 직종별 총 노무량: 100 ÷ 20 × 3 = 15인·일.

15인·일은 작업자 15명이나 공기 15일을 의미하지 않는다.
이 사례는 공법을 선택하는 판단, 실제 일정, 단가와 금액을 검증하지 않는다.
원문의 공구손료/경장비, 별도 양생 및 표면 마무리 등은 전체 견적 단계에서
별도로 연결해야 한다. 미산정 항목은 0원이 아니다.

## 실행

저장소 루트에서 `python evals/check_estimate.py`를 실행한다.
기존 `data/processed/parsed.jsonl`을 읽으므로 PDF 재파싱, API, DB가 필요 없다.
기준 파일은 `evals/golden_estimate.json`이다.

검사기는 현재 레코드 형식의 정확한 필드를 읽어 작업조, 일당 시공량, 단위를
비교하고 노무량을 계산한다. 값 누락, 중복 레코드, 일당 표기 누락 또는 기준값
변경 시 실패한다. 범용 견적 계산기나 파싱 전체 검증기는 아니다.

## 다음 연결 순서

1. 이 절의 표와 주석, 상위 공통 규칙을 함께 가져오는 청킹·검색을 연결한다.
2. 검색 결과가 위 계산에 필요한 두 직종과 조건을 모두 제공하는지 평가한다.
3. 기준일·출처를 갖춘 직종별 단가를 연결하고 금액 평가 사례를 추가한다.
4. 고정한 조건을 사용자 입력으로 전환하고 누락 조건을 묻는다.

개발용 가정은 실무적으로 확인된 사실로 바꾸어 표기하지 않는다. 실무 검토 전에도
구현과 자동 검증은 진행하되, 지원 조건을 넓힐 때 규칙과 평가 사례를 함께 추가한다.
