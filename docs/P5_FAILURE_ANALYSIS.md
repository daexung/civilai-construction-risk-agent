# P5 24건 원인 분석과 개발 수정

2026-09-25. 최초 P5 평가는 `docs/P5_HOLDOUT_REPORT.md`의 **166/190, G7 미충족** 판정 그대로 둔다. 아래 재확인은 그때 저장한 ODL JSON을 읽은 **개발 검사**다. ODL 추출과 `p5_eval.py`는 다시 실행하지 않았다. 정답은 여전히 잠정이며 실무 검토는 미완료다.

## 330쪽: 16개 규격이 합쳐진 위치

원문 `(9080) 대선` 표에는 분류번호 `0050`부터 `3000`까지 **16개 행**이 있다. 각 행의 형식은 `50ton`부터 `3,000ton`까지 하나씩 대응하며, 내용시간 19,200·계 1,242 같은 숫자도 각 행에 따로 인쇄돼 있다. `9080-`와 `SD`는 이 목록 앞의 공통 표기다.

저장된 ODL 원시 표는 머리글 2행과 본문 1행의 **3×12** 격자다. 본문 첫 칸은 `9080-`와 번호 16줄, 둘째 칸은 `SD`와 형식 16줄, 숫자 칸들은 각각 16줄이다. 둘째 칸은 문단과 목록 노드가 섞여 있어 `odl_tables.split_row`의 `cell_lines`가 좌표를 반환하지 않았고, 어댑터는 본문 행을 나누지 않았다. `assemble.unstack`은 숫자 칸에서 깊이 16을 알았지만 앞의 두 칸은 17줄이라는 이유로 매 결과 행에 전체 내용을 반복했다. 따라서 실패 지점은 **ODL의 행 묶음 → 어댑터의 미분리 → 조립의 17줄 반복** 순서다.

수정은 쪽 번호를 쓰지 않는다. 숫자 칸에 N개의 정렬된 값이 있고, 첫 칸이 `숫자-` 형태의 공통 분류 접두어와 N개 번호를 가지며, 다른 칸도 공통 접두어와 N개 값으로 구성된 경우 접두어를 공유하면서 N개의 레코드로 푼다. 개발 검사에서 16개가 각각 `9080- 0050 | 형식 SD 50ton`부터 `9080- 3000 | 형식 SD 3,000ton`까지 복원됐다.
