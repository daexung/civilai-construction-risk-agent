## 반드시 구현할 계약
1. 단일·다중 공종의 자연어 요청을 동일한 해석 계약으로 처리한다. 목적은 새 견적 / 공종 추가 / 항목 수정 / 조건 답변 / 근거 설명 / 실패 복구 / 명확화로 구분한다. 숫자 카드 답은 기존 ref/revision 검증을 유지하며 LLM을 호출하지 않는다.
2. 해석 결과는 검증 전 제안이다. 대상 item_id 또는 신규 작업, 필드별 값·단위·사용자 원문 근거 위치, 미확정 대상을 구조화한다. LLM은 기존 generate/schema 어댑터와 요청 예산을 재사용하며, 한 사용자 턴 해석은 최대 1회로 제한한다. 반복 도구 선택으로 계산 순서를 정하지 않는다. 기존 QA 검색은 유지한다.
3. 서버가 근거 구절의 존재와 값/단위 일치, 허용 필드, 대상 소속, 충돌을 검증한 뒤에만 상태를 갱신한다. 근거 구절에 8m가 있다는 이유로 폭에 넣는 식의 잘못된 필드 연결도 거부해야 한다. 대상이 둘 이상이면 선택 질문을 하고 수정 전 상태를 보존한다. 해석 실패/모호함은 명확화로 처리하며 추측 기본값, 몰래 규칙 경로로 오해석한 변경, 원래 입력 유실은 금지한다.
4. 명확한 레이블이 붙은 동일 단위 입력(높이 8m, 폭 1.5m)을 각각 연결한다. 기존 scope.confirmed_result의 같은 단위 숫자 일괄 차단을 해결한다. 높이와 폭 없이 `8m, 1.5m`만 있으면 구분을 묻는다. 숫자를 처음부터 물량으로 전부 취급하지 않는다. 공종 미선택 시 원문 사실을 보존하고 선택 후 해당 명세로 매핑한다.
5. 새 견적은 명시적으로 시작하고, 공종 추가는 기존 항목을 보존한다. `콘크리트 물량만 120㎥로 변경`은 그 항목만 갱신한다. 새 공종을 기존 항목 조건으로 오인하지 않는다. 상한은 기존 설정을 따른다. 공종 교체는 기존 선택/호환 조건 계약을 따른다.
6. 유효한 변경 후 적용 범위 → 필요 조건 → 품 계산 → 가격 → 전체 집계의 실행 순서는 코드가 결정한다. 단일/다중 모두 같은 항목 실행 함수를 사용하고, 변경 없는 형제 항목의 입력/계산/결과 revision은 보존한다. 기존 run_turn에 새 분기만 쌓지 말고 해석/검증/실행을 테스트 가능한 모듈 또는 함수로 분리한다. 기존 호환 경로는 이유를 기록한다.
7. `안됐어`는 직전 상태를 기반으로 차단 사유와 가능한 다음 행동을 전달한다. 질문/결과/사유 없는 진행 문구로 끝내지 않는다. BLOCKED(공식 범위), ERROR(처리 오류), 미지원, 조건 부족, PARTIAL(미산정 포함)을 보존하고 화면·복원·Excel에서 의미가 달라지지 않게 한다. 숫자/금액은 서버 결과에서만 가져온다.

## 필수 증거 (각 항목 완료/실패/미실행 표로 기록)
- A: 자동문 견적 후 계단 요청을 새 작업 의도로 처리. 계단 18㎡ 높이8m 폭1.5m 입력을 유실 없이 연결하고, 실제 적용 범위 위반을 즉시 안내. 추가 폭 질문 전에 높이 위반을 안내할 수 있어야 한다.
- B: 계단 높이6m 폭0.9m 정정 → 실제 기존 계산 경로로 재계산; 안됐어 → 이유/다음 행동 보존. 추측으로 값을 낮추지 않는다.
- C: 콘크리트+거푸집 생성 → 명시적 콘크리트 물량 수정 → 형제 항목 보존·합계·XLSX 일치. 이후 다른 공종 추가 시 기존 항목 유지.
- D: 동일 공종 두 항목에 대상 없는 수정 → 대상 선택; 선택 전 입력/금액 불변. 오래된 ref도 거부.
- E: 한 문장의 높이·폭·물량 동시 입력, 단위 변형, 서로 모순되는 값, 잘못된 모델 item/field/evidence 및 다른 필드로 수치 바꿔치기. 애매하거나 검증 실패한 제안으로 세션을 변경하지 않는다.
- F: 정상+차단/전체 차단/기술 오류의 응답이 명확하며 복원 후에도 수정 가능. 화면과 Excel의 값 일치 및 전체 차단의 0원 성공/다운로드 방지.
- G: 실제 generate 인터페이스에 주입한 해석 응답으로 위 공통 경로가 실행됨을 확인. mock은 자연어 모델 성능을 입증하지 않는다고 명시. 실제 서비스 모델 호출은 이번 승인 범위 밖이므로 미실행으로 남긴다.
