# 같은 절의 반복 기준 `(일당)`이 동일 문자열 제거에서 지워지는지 확인 (기능 검사)

기준 코드: `baf186f:pipeline/parse.py:337-343` (`parse_pages`의 동일 문자열 제거). 운영 파일에는 적용하지 않았다.

## 결과: 표 앞 기준 2개의 보존 여부 (기존 중복 제거 → 최소 수정안)

입력은 **가상 기능 검사 입력**이다. 실제 PDF 파싱 결과가 아니다. 같은 절 `9-9-9 가상 절`에 표 두 개가 있고 각 표 앞에 `(일당)` 줄글 레코드가 있다.

입력 순서: `(일당)` → 표 `p1-t0` → `[주] ① 가상 주석입니다.` → `(일당)` → 표 `p1-t1` → `[주] ① 가상 주석입니다.`

| 표 | 기존 중복 제거 | 최소 수정안 |
|---|---|---|
| 첫 번째 표 `p1-t0` 앞 `(일당)` | 남음 | 남음 |
| 두 번째 표 `p1-t1` 앞 `(일당)` | **제거됨** | **남음** |

- 기존 중복 제거 후 순서: `(일당)`, 표 `p1-t0`, `[주] ①…`, 표 `p1-t1`
- 최소 수정안 후 순서: `(일당)`, 표 `p1-t0`, `[주] ①…`, `(일당)`, 표 `p1-t1`
- 참고로 기준 코드 `chunk.py` 의 `make_chunks`에 같은 입력을 넣으면 표 청크 `basis`는 기존이 `p1-t0 = (일당)`, `p1-t1 = None`, 수정안이 `p1-t0 = (일당)`, `p1-t1 = (일당)`이다(청킹은 수정하지 않음).
- 일반 설명 `[주] ①…`의 중복 제거는 두 경우 모두 1건만 남아 정책이 같다.

원인은 기준 코드 337-343행이 `record["text"]`가 같으면 무조건 버리는 것이다. 두 기준 레코드의 글이 `9-9-9 가상 절 | 설명 | (일당)`으로 완전히 같다.

## 사용자에게: 같은 문자열이라도 같은 출현이 아닌 이유

`(일당)`이라는 글이 두 번 보여도, 원문에서는 서로 다른 표 위에 따로 인쇄된 **표마다의 조건**이다. 첫 번째 표의 기준과 두 번째 표의 기준은 우연히 글이 같을 뿐 각각 자기 표에만 적용되는 정보이므로, 글자가 같다는 이유로 하나만 남기면 두 번째 표는 단위 기준을 잃은 채 숫자만 전달된다. 중복 제거가 원래 노린 대상은 같은 쪽에서 같은 내용이 여러 번 추출된 경우인데, 이때는 쪽·위치가 같고 의미도 한 번뿐이다. 반면 위치가 다른 같은 글자는 의미가 각각 따로이므로 같은 출현으로 볼 수 없다. 이 판단은 글자가 같은지만이 아니라 원문에서 어디에 붙어 있는지를 함께 봐야 하며, 위 수정안은 그중 가장 단순한 경우(표 바로 위 기준 표기)만 제거에서 빼는 선택이다.
