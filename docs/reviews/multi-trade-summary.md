# 복수 공종 통합 견적 4단계 결과

## 구현 범위

- `/api/item-labor/{trial_id}/estimate`는 항목별 기존 품·가격 계산을 적용한 뒤 부모 세션에서 `aggregate()`를 실행한다. 공종별 계산은 직접비만 만들고 공사원가계산기는 통합 직접비에 한 번만 실행한다. 기준일은 필수로 받고, 허용된 공통 조건은 명시적으로 받을 수 있다.
- `/common-answer`는 공종 기본값이 충돌해 공통 조건 선택이 필요한 경우 기존 질문 검증을 사용한다. 기본값은 값과 출처(`default_division`/`default`)를 그대로 반환한다.
- `/estimate.xlsx`는 기존 XLSX 생성기를 사용하고 공종별 상세 시트를 추가한다. 각 안정 항목 ID, 작업, 상태, 단위가 있는 수량, 직접비와 미산정 항목을 보존한다. 첫 시트는 부분 합계를 `부분 산정 금액(미산정 항목 제외)`로 표시하고, 재료비 0원과 별도 재료 미산정을 구분한다. 공통 조건은 한국어 필드명·출처와 줄바꿈을 사용하며 행 높이를 조정했다. 단일 공종 금액 문구는 유지한다.
- 작업 결과가 바뀌거나 범위가 다시 확인되면 저장된 통합 견적을 지운다. 다운로드는 최신 통합 견적이 존재하고 가격 산출 항목이 하나 이상일 때만 가능하다. 가격 질문·지원 불가 상태를 보존하고, 공종 계산 실패 때 앞선 임시 결과는 항목 세션에 반영하지 않는다.
- 항목 가격 기준 버전이 서로 다르면 합산을 거부한다. 모든 API 요청은 기존 시험 경로의 로컬 전용·비운영 가드를 통과해야 한다.

## 고정 입력과 사전 기대값

별도 파일 [기대값 기록](multi-trade-summary-expectations.md)을 통합 실행 전에 작성했다. 입력은 `수성페인트 롤러칠 2회 벽면100㎡ + 실내 방수모르타르10㎜ 바닥20㎡`, 기준일은 `2026-10-16`이다. 기존 계산기로 공종별 사전 계산한 직접비는 `w2_5` 727,000원, `w25_27` 390,900원, 합계 1,117,900원이다. 재료량·단가 등 미산정 범위가 남아 부분 산정이며 재료비는 `null`이다.

## 통합 결과

- 상태: `PARTIAL`; 포함 항목 `w2_5`, `w25_27`. 이 상태의 계산서 도급액은 포함 공종만 반영한 참고 금액이며 API에서 `partial_contract_amount`로 반환한다. `contract_amount`와 `complete_contract_amount`는 `null`이다.
- 직접비 합계: 1,117,900원. 사전 기대값과 일치했다.
- 기존 공사원가계산기를 합산 직접비에 한 번 적용한 결과: 순공사원가 1,537,323원, 일반관리비 122,985원, 이윤 249,046원, 총원가 1,909,354원, 부가세 190,935원, 부분 도급 참고액 2,100,289원.
- 공통 조건은 건축 부문 기본 `주택 외 건축`(출처 `default_division`), 기간 `1~6개월`, 업종 `종합건설업`, 규모 `이 견적만`(나머지 세 값은 출처 `default`)으로 반환된다.
- 기준 버전은 노임 `2026H2`, 장비 `2026`, 제비율 `260413`; 기준일과 버전은 API 및 엑셀에 포함된다.

## 검증

- `evals/check_multi_trade_summary.py`: HTTP 범위 확인부터 모의 검색·계산·집계·다운로드까지, 직접비 기대값, 재료 미산정 표기, `PENDING`/질문·부분 직접비/`PARTIAL`/미지원/`NO_RESULT`, 같은 공종 재사용, 기준일 변경에 따른 노임 버전 변경, 공통 조건 충돌과 답변, 가격 버전 충돌·누락, 공통 원가계산기 1회 호출, 재계산 실패 시 원자성, XLSX의 API 금액 일치와 각 시트의 항목 ID·단위·인용을 확인했다.
- 표지 문구 회귀에서도 다중 공종은 `부분 산정 금액(미산정 항목 제외)`와 재료비 참고를, 단일 공종은 기존 `견적금액` 및 AI 검토 배지를 유지하는 것을 확인했다.
- `evals/check_item_labor_trial.py`: 21/21 통과(가드, 항목 독립성, 질문 버전, 재정렬, 수정 무효화 포함).
- `evals/check_estimate_tools.py`: 70/70 통과. worktree에는 생성 파싱/인용 자료가 없어서 기존 저장소 자료를 읽기 전용으로 지정해 실행했다.
- `evals/check_cost_statement.py`: 8/8 통과.
- 검토자가 최신 코드로 별도 실행한 `evals/check_scope_analysis.py` 범위 분석 22/22 및 `evals/test_single_trade_conditions.py` 조건 회귀 11/11도 통과했다.

- 기존 `evals/check_api.py` 전체 회귀는 checkout에 `page_map.json`이 없어 앱 시작 검증이 실패했고, 이어 기존 gate 경로의 `TypeError`로 끝나 통과하지 못했다. 단일 공종 표지 형식은 위의 집중 회귀로 확인했다.
- 새 XLSX 예시: [multi-trade-summary-example.xlsx](multi-trade-summary-example.xlsx). 검사용 생성 파일이며 비밀정보가 없다. API 도급액과 원가계산서 셀, 내역서 물량·단위·직접비, 일위대가와 단가대비표 및 산출근거의 ID·단위·인용을 다시 읽어 비교했다.

## 운영 메모와 한계

이 시험 API는 프로세스 내 메모리 세션을 사용하며 `LOCAL_TRIAL_ITEM_LABOR=on`, 비운영 환경, loopback 요청에서만 동작한다. 운영 라우팅, 영속성, 인증·권한 모델, 실검색 연결은 이 단계에 포함하지 않는다. 질문 대기 중에는 저장된 가격 공종의 직접비만 `partial_estimate`로 반환하며 완성 도급액을 제공하지 않는다. 미지원과 질문 대기만 남고 가격 가능한 공종이 없으면 `NO_RESULT`다. XLSX는 기존 내역서·일위대가·단가대비표·산출근거 시트에 항목 ID와 공종별 단위·근거를 담고, 미산정 재료는 명시적으로 표시한다.
