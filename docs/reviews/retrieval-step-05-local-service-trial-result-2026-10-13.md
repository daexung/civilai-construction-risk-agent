# 검색 5단계 결과: 로컬 서비스 시험 연결 (2026-10-13)

지시서: `docs/planning/claude-step-05-local-service-trial-2026-10-13.md`
범위: 현재 검색 정책(4h 기본)을 **그대로 둔 채** 로컬 서비스 화면·API에 시험 연결. 검색 규칙·청킹·임베딩·파싱은 건드리지 않았고, 원격 연결·커밋·푸시·배포도 하지 않았습니다.

## 1. 한눈에 보기

- 고정한 10문 모두 기대한 상태대로 나왔습니다(API 10/10, 최종 실행). 이 "기대"에는 G02·N19의 **현재 한계가 그대로 포함**되어 있습니다(아래 5절).
- 브라우저 화면으로 정상 답변·확인 필요·근거를 찾지 못함·번호 후보 4가지 흐름과 원문 쪽 이미지 열기까지 확인했습니다. 화면 요청은 모두 `127.0.0.1`로만 나갔고 콘솔 오류는 없었습니다.
- 정상 답변 3문(G01·G03·G08)은 실제 서비스 모델 호출로 설명을 만들고 원문과 대조했습니다. 설명 검증이 실패하면 상태는 그대로 두고 **검증된 원문 표시로 전환**했습니다.
- 모델 설명 단계는 완전히 안정적이지 않습니다. 시험 중 supported 상태 27회 중 21회 모델 설명 통과, 6회 원문 표시 전환(7절). 상태 자체는 한 번도 화면에서 뒤집히지 않았습니다.
- 새로 쓴 유료 호출은 29회·약 $0.06(상한 60회·$2 이내, 단가는 추정). 선택·대조·목록 응답은 4d~4h 저장 응답을 같은 입력일 때만 재사용했습니다.
- 이 결과는 **서비스 연결 시험**이지 검색 정확도·견적 정확성·배포 승인 근거가 아닙니다.

연결 경로: 화면 `/trial` → (CRA 개발 서버가 `/api`를 8010으로 전달) → `local_trial.Engine` → `retrieve.Retriever` → `evidence.Reader` → `select_verified.VerifiedSelector`(4h, SHA `edff2ca3…0626` 변경 없음) → 상태·근거 분류 → 정상 답변 근거만 설명 생성 문맥으로 사용 → 검증 → 응답.

**기존 상담 경로(`/api/chat`)는 쓰지 않았습니다.** 이 경로는 회원 확인·사용량 차감·대화 저장을 거치므로 원격 서비스 설정이 필요하고, 지시서의 금지 사항(원격 연결·사용량 차감)에 걸립니다. 그래서 기존 경로에 옵션을 끼우는 대신 "기본 꺼짐·로컬 전용 별도 경로"를 만들어 시험 화면에 연결했습니다. 운영 인증은 끄지 않았습니다.

## 3. 실행 주소와 켜고 끄는 방법

- 백엔드: `http://127.0.0.1:8010` (독립 앱, Supabase 등 초기화 없음)
- 화면: `http://127.0.0.1:3010/trial`
- 켜기(백엔드): `LOCAL_TRIAL_RETRIEVAL=on python -B -m uvicorn backend.api.local_trial:app --host 127.0.0.1 --port 8010`
- 켜기(화면): `REACT_APP_LOCAL_TRIAL=on`, `CIVILAI_API_PROXY=http://127.0.0.1:8010` 로 CRA 개발 서버 실행(포트 3010).
- 끄기: 옵션을 주지 않으면 `/api/local-trial/*`는 404, `/trial`은 기존 화면(옵션 꺼짐 시험으로 확인: `test_option_off_returns_404`, `test_main_app_has_no_trial_route_when_off`).
- 중지: 이 세션이 띄운 프로세스만 종료하면 됩니다(8010·3010 포트를 쓰는 프로세스). 자동 실행 예약은 만들지 않았습니다.

## 5. 현재 한계를 그대로 보여 준 사례

- **G02**: 질문의 `바르려는데`가 원문 표현과 글자가 달라 정상 근거(6-4-3 표 15㎜ 미장공 0.056)가 "확인 필요"로 보류됩니다. 화면은 이유와 검토용 원문을 보여 줍니다. 이상적인 결과는 supported이며 현재 정책의 불필요 보류입니다.
- **N19**: 원문에 BIM이 없는데 수치지도 작성 표를 가까운 후보로 골라 오는 결과입니다. 화면은 "확인 필요 + 검토용"으로만 보이고 확정 값·계산은 하지 않습니다. 이상적인 결과는 근거를 찾지 못함입니다. 4i에서 두 문제를 함께 푸는 정책이 없다는 결론을 이미 냈고, 이번 단계에서 바꾸지 않았습니다.
- 목록(G14): 범위가 넓어 목록 완전성을 확인하지 못했다고 표시하고 참고 후보는 근거로 쓰지 않았습니다.

## 8. 기존 경로와의 비교

**비교 미실행.** 기존 상담 경로(`/api/chat`)는 회원·비회원 확인, 사용량 차감, 대화 저장을 거치며 원격 서비스 설정이 필요합니다. 지시서가 금지한 원격 연결·사용량 차감 없이는 로컬에서 그대로 돌릴 수 없어 G01·G03·G08의 옛 답변·출처 비교를 하지 않았습니다. 과거 결과를 지어내지 않았습니다. 따라서 "기존 경로보다 좋아졌다"는 주장은 이번 단계에서 하지 않습니다. 비교 가능 범위는 이전 단계(3~4i)의 오프라인 비교 결과에 한합니다.

## 12. 남은 문제

분류: 연결 / 생성 / 검증 / 기존 검색.

1. (기존 검색) G02 불필요 보류, N19 가까운 표 후보 제시 — 현재 정책 한계, 이번 단계에서 수정하지 않음.
2. (생성·검증) 모델 설명이 가끔 검증을 통과하지 못해 원문 표시로 전환됨(27회 중 6회). 특히 `[공동값]` 주석이 길게 붙은 표(G03)에서 인용이 불안정합니다. 전환은 안전하지만 사용자는 값을 원문에서 직접 찾아야 합니다.
3. (생성) 정상 근거 목록에 같은 문맥의 정상 조각이 여러 개(G08은 8개) 보이고 실제 인용은 1개입니다. 화면에는 "답변에 인용" 표시를 달았지만 나머지 정상 조각의 역할 설명은 부족합니다.
4. (화면) 근거가 있어도 질문 조건 칸을 모델이 확인하지 못한 경우("근거 있음" + 원문만 표시)가 있습니다. 배지 문구를 따로 두는 결정이 필요합니다.
5. (기존 검색) 부정 표현, 목록 완전성(G14), 대상 정체성(G09의 호퍼스케일 표현 불일치)은 이전 단계 한계 그대로입니다.
6. 표 안 `[공동값 …]` 주석이 화면 원문 표에 그대로 길게 반복돼 읽기 불편합니다(원문 왜곡을 피하려고 숨기지 않음).
