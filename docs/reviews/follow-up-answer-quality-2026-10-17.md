# 후속 과제: 앵커 적용 질의의 부적절한 확인 요청

상태: 사용자 제보 기록. 현재 계산 자동화 작업은 계속하며, 이 과제는 별도로 처리한다. 코드 수정이나 원인 확정은 아직 하지 않았다.

## 재현 사례

- 질문: `D16 앵커를 설치할 때 기초앵커 품셈을 적용해도 되나요?`
- 사용자가 보고한 응답 시간: 31.6초.
- 응답 상태: `확인 필요`.
- 안내: `확정 답변을 드리기 어려워요. 아래 확인할 것과 원문을 먼저 확인해 주세요. 관련 원문은 검토용으로만 보여 드려요.`
- 문제 문장: `질문의 d16, 되나요이(가) 원문의 어떤 표현에 해당하는지 확인해 주세요.` (사용자 제보에서는 각 토큰에 코드 표시가 붙음.)

## 문제와 조사 범위

1. 의문 표현인 `되나요`가 원문 대응을 확인해야 할 전문 용어처럼 노출된다.
2. `D16`이라는 규격 표현을 어떤 과정에서 추출·정규화·원문 대조하는지 확인해야 한다. 이 기록만으로 D16의 의미나 품셈 적용 가능 여부를 확정하지 않는다.
3. 검색 결과, 답변 후보, 근거 검증과 최종 확인 요청 생성 과정을 추적해 불필요한 확인 요청의 발생 단계를 찾는다.
4. 31.6초 지연은 함께 기록하되, 반복 측정 전 성능 원인을 단정하지 않는다.

## 기대 결과 및 완료 기준

- 일상적인 질문 어미를 기술적 미확인 사항으로 사용자에게 제시하지 않는다.
- 앵커 종류·규격·시공 방법 등 실제 적용 판단에 필요한 조건과 관련 원문을 대조해 답한다.
- D16만으로 판단이 불가능하면 필요한 현장 조건을 구체적으로 질문하며, 토큰을 원문의 표현에 직접 대응시키는 일을 사용자에게 요구하지 않는다.
- 근거가 부족할 때는 부족한 근거 또는 조건을 설명하고, 적용 가능하다고 임의 확정하지 않는다.
- 이 질문과 표현 변형으로 회귀를 확인한다. 조사 전에는 검색·모델·검증기 중 어느 하나의 문제라고 확정하지 않는다.

현재 계산 자동화 작업과 별도이며, 이번 기록으로 구현·모델 호출·배포를 시작하지 않는다.
