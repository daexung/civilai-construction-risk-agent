# 구간별 머리글 필터 확인 결과 (`read_text_blocks`, 코드 수정 없음)

**숫자만 있는 본문 구간이 추가로 제외되는 동작은 가상 입력에서 재현됐다.** 실제 PDF에서 본문 손실이 일어났다는 증거는 아니다. 이미 검사한 9쪽에서는 이 필터가 결과를 바꾼 곳이 0건이었다. 최소 수정 제안은 아래에 있고 파일에는 적용하지 않았다.

## 확인 대상

작업 폴더 `C:\Users\user\Desktop\PROJECTS\_parse-basis-fix-baf186f`의 `pipeline/parse.py` (HEAD `baf186ff5afbd13616169c042c270a1fac750a68`). `read_text_blocks` 안에서 제목·표 안 줄을 뺀 뒤 남은 연속 구간(`run`)마다 다음이 적용된다.

```python
for run in runs:
    text = " ".join(t for _, t in run)
    if RUNNING_HEAD_RE.match(text):
        continue
```

`RUNNING_HEAD_RE`는 `^(제\d+장(\s|$)|\d+$)`다. 이 필터가 걸리는 것은 **정수만으로 된 구간**(예: `3`, `12`)과 `제N장`으로 시작하는 구간이다. `0.34`처럼 점이 있는 숫자는 걸리지 않는다.

## 왜 있는가, 블록 단위 판정과의 차이

- **블록 단위 판정(기존 그대로):** 줄을 합친 블록 전체 글에 `RUNNING_HEAD_RE`를 적용한다. 쪽 번호 블록(`130`)과 머리글 블록(`제4장 목공사`)을 거른다. 기준 코드의 판정과 같다.
- **구간별 판정(추가):** 줄별 제외로 블록이 쪼개진 뒤 **남은 줄만** 다시 검사한다. 기준 코드는 제목으로 시작하거나 중심이 표 안인 블록을 통째로 버렸기 때문에, 그 안에 우연히 있던 쪽 번호성 정수 줄도 함께 버려졌다. 줄별 판정으로 바꾸면 이 정수 줄이 남은 구간으로 새어 나오므로, 이를 막으려고 구간별 판정을 추가했다.
- **차이:** 블록 단위는 "블록 전체 글이 머리글 모양인가", 구간별은 "제외 후 남은 글이 머리글 모양인가"이다. 제외 후에야 정수만 남는 경우는 구간별 판정에서만 걸린다. 제외 줄이 없는 블록은 구간 글이 블록 글과 같아 두 판정 결과가 같다.
- **약속과의 관계:** 승인 지시서는 쪽 머리글 판정을 바꾸지 않도록 했는데, 구간별 판정은 그 판정을 새 대상(남은 구간)에 확장한 것이다. 이 점을 지시서와 다른 동작으로 본 지적은 타당하다.

## 판단과 최소 수정 제안 (적용하지 않음)

1. 승인 지시서의 "쪽 머리글 판정은 바꾸지 않는다"와 일치한다. 블록 단위 판정은 그대로 남는다.
