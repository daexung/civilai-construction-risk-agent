이번에 확인해 둔 **표 30개의 결함과 수식 1곳을 수정하고, 수정본으로 982쪽 전체 결과를 다시 생성했다.** 실제 코드와 교정 자료가 있으며, 계획만 작성한 상태가 아니다. 누락 표를 복구한 것과 계산에 필요한 행 대응을 확정한 것은 구분한다. 복구 표 중 6개는 행 대응 보류가 남아 있다.

## 수정 방식과 범위

ODL 전체 원시 출력은 다시 만들지 않았다. 이미 보관한 출력을 기본 입력으로 사용했다. ODL에서 빠진 것으로 확인한 24개 표 영역만 PyMuPDF로 보충했다.

일반 규칙으로 해결할 수 있는 설명·머리글·목록 문제는 코드에서 고쳤다. 특정 문서의 훼손 칸과 수식은 `out/corrections.json`에 교정 전 내용, 원문 위치, 교정 내용을 기록했다. PDF와 원시 출력의 해시가 다르거나 교정 전 내용이 다르면 적용을 거부한다. 교정 후에도 원래 출력과 교정 근거를 보관한다.

복사한 후보 코드에서 변경한 기존 파일은 `assemble.py`, `structure_store.py`, `structure_export.py`다. `source_corrections.py`를 새로 추가했다. `parse.py`, `chunk.py`, `odl_tables.py`, `structure_rules.py`, `table_guard.py`는 기준선 그대로다. 청킹 실행과 임베딩은 이번 작업에 포함하지 않았다.

## 어떻게 확인했는가

확인 항목은 **68개 통과, 실패 0개**다. 이 수치는 이번 변경의 확인 범위이며 전체 정확도가 아니다.

- 결과·전달 확인 53개: 누락 복구, 교정 칸, 머리글과 목록, 수식, 식별자와 원문 연결, 보류 표시 유지.
- 적용 제한 확인 9개: 다른 원문 버전과 예상 내용 불일치 거부, 일반 표 머리글 보호, 짧은 공동 값과 기존 비고 문장 유지.
- 최종 확인 6개: 생성 코드 일치, 기존 칸 위치 보존, 8개 칸 외 변경 없음, 확인한 표 30개 존재, 보류 표의 행 연결 표시 유지, 복구 칸 숫자 차이 없음.

출력을 읽기 전에 고정한 비교 쪽은 57·116·251·338·449·503·602·641·712·815·873·961쪽이다. 최종 레코드는 수정 전과 모두 같다. 57쪽은 본문 표가 없는 쪽이다. 다른 쪽의 원문 그림과 첫 표의 주요 내용도 대조했다. 815쪽은 초기 실패를 고치는 데 사용했으므로 수정 후 독립 평가로 세지 않는다. 이 비교가 모든 칸의 의미를 승인하는 검사는 아니다.

초기 변경에서는 머리글 조건이 넓어 다른 표에 영향을 주고, 일부 비고 출력 형식도 달라졌다. 전체 차이를 확인한 뒤 기존 음영 머리글을 우선하고 적용 조건을 좁혔다. 짧은 공동 값의 열 이름도 유지하도록 제한했다. 초기 확인 자료를 보관했으며 최종 결과는 위 제한을 반영한 코드로 다시 생성했다.

## 남은 문제는 무엇인가

이번에 제시한 추출·전달 결함은 교정했다. **모든 표를 자동 견적 계산에 써도 된다는 뜻은 아니다.**

현재 보류 표는 283개다. 기존 277개와 새로 복구한 6개를 합한 수이며 모두 오류라는 뜻은 아니다. 여러 행에 걸친 이름의 적용 범위, 줄임 코드 연결, 행과 칸의 대응, 일부 머리글 가정 등이 남아 있다. 새 복구 표의 보류 6개는 500쪽 1개, 501쪽 1개, 502쪽 2개, 537쪽 1개, 538쪽 1개다.

일부 상위 절 제목 미확인과 다른 수식의 해석은 이번 수정 범위 밖이다. 원문 글자와 칸이 보존됐다는 사실만으로 그 값의 적용 조건까지 확정하지 않는다. 보류 목록은 `out/remaining_review.json`에 있다.

다음 작업의 입력으로는 이번 수정본의 원문 보관 자료와 레코드를 사용할 수 있다. 청킹 단계에서는 원문 위치와 보류 상태를 함께 전달해야 한다. 계산은 보류 상태를 확인하고 사용을 제한해야 한다. 남은 모든 보류를 없애기 위해 파싱 규칙을 계속 넓히는 일을 다음 기본 작업으로 정하지 않는다.
