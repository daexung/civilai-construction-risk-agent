## 무엇을 고쳤나

| 대상 | 이전 | 수정 결과 |
|---|---|---|
| 생략된 분류 코드 | `7430-1100` 다음 행이 `1300`으로만 표시 | 같은 원문 분류 번호 칸과 확정된 행 대응을 근거로 `7430-1300`을 표시. 원래 `1300`과 앞자리 칸, 변환 근거도 보관 |
| 기종 이름 | `수동 싱글 드럼 더블 드럼`이 모든 하위 행에 표시 | 여러 문단을 포함한 병합 이름 칸을 감지하고 `[이름 적용 범위 미확정]`으로 표시. 원래 칸과 문단별 이름 후보·좌표는 그대로 보관 |
| 보류 전달 | 위 표에 문제가 있어도 `flags=[]`, 표 레코드·청크가 `ok` | 이름 또는 코드 미확정 사유를 표에 기록하고 모든 표 레코드와 청크에 `uncertain`, 계산 사용 보류로 전달 |

코드 변환은 열 이름이 `분류 번호`일 때만 한다. 같은 원문 칸 안의 앞선 완전한 코드와 같은 자리수의 끝 번호만 연결한다. 새 완전한 코드가 나오면 그 앞자리를 사용하고, 다른 칸·다른 표·다른 쪽으로 앞자리를 넘기지 않는다. 자리수가 다르거나 행 대응이 미확정이면 보류한다. `0050` 같은 앞쪽 0은 유지한다.

숫자 칸과 원문 이름 칸은 덮어쓰지 않았다. 표시용으로 연결한 코드와 이름 보류 표시는 원문과 별도 정보다. 내보낸 연결 자료의 `parts`에는 변환 전 `source_text`와 변환 근거 `semantic`이 있다. 원래 칸의 글·병합·좌표·분리 정보는 이전 결과와 동일하다.

겹치는 쪽과 표가 있으므로 위 표 수를 서로 다른 표 수 또는 문서 전체 비율로 합치지 않는다. 세 묶음 모두 기존에 개발에 사용한 자료다.

관련 확인 항목 114개가 최종 실행에서 통과했고 실패는 0개였다. 구성은 원시 입력 보존 24개, 청킹 전달 30개, PDF 글자층 대조 9개, 이번 이름·코드 변경과 범위 확인 51개다. 114개는 정확도나 공종 수가 아니다.

확인한 핵심 내용:

- 원래 칸의 글·숫자·좌표·병합·분리 기록이 직전 결과와 같음
- 185쪽 63·55가 각각 공동 칸 하나로 남고 세 직종 레코드와 연결됨
- 555쪽 본문 13행과 의심 숫자, 표 전체 보류 유지
- 이전 12·13쪽의 반복 주석과 기준을 포함한 모든 레코드 표시 글·구조 상태 동일
- 코드 변환에 사용한 앞자리 칸이 같은 원문 칸 출처이고, 표시 코드와 변환 근거가 일치함
- 앞쪽 0, 앞자리 변경, 다른 칸, 다른 열, 불확실 행, 자리수 불일치, 앞자리 없는 경우 확인
- 이름·코드 보류가 저장 결과, 모든 표 레코드, 기존 청킹 결과와 계산 사용 상태에 전달됨

- 두 구현 파일의 diff 공백 검사에서 문제 없음

첫 검사 실행은 새 확인 코드가 공동 값의 필드 이름을 `raw`로 잘못 읽어 중단됐다. 실제 필드인 `text_raw`로 수정한 뒤 최종 실행은 통과했다. 이를 제품 코드의 파싱 실패로 집계하지 않았다.
