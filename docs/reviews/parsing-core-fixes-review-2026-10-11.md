# 핵심 파싱 수정 결과 검토

작성일: 2026-10-11

## 판단

이번 묶음 수정은 결과를 제출하고 종료한 상태다. 파싱 전체 완료와 운영 채택을 뜻하지 않는다. 기존 개선을 유지하면서 행 분리 근거, 머리글, 기준과 주석, 쪽 경계 관계를 보강한 후보로 보관할 수 있다.

결과 보고서 전체와 주요 코드 변경, 생성 기록 코드, 저장된 확인 결과를 읽었다. 새 파싱 실행, 검사 재실행, PDF 그림 대조는 하지 않았다. 저장된 결과는 개발·회귀 94개와 별도 확인 28개이며 실패 기록은 없다. 이 숫자로 원문 정확도를 판단하지 않는다.

## 확인한 개선

- 이미 나눈 행을 조립 단계가 다시 추측하지 않도록 명시적인 행 상태를 전달한다. 확정 분리는 어댑터가 맡고, 조립의 후보 분리는 보류로 전달한다.
- PDF 글자 기준선과 쪽 크기를 사용하고, 머리글 음영 판정을 보관과 조립에서 함께 사용한다.
- 소제목 기준, 다음 쪽 주석, 이어지는 표의 관계를 보관한다. 위치에 따른 연결은 확정으로 표시하지 않는다.
- 생성 번호에 PDF와 부문 정보 등 결과에 영향을 주는 입력 해시가 들어간다.
- 별도 확인에서 결함을 수정한 뒤 그 자료를 독립 평가로 주장하지 않은 보고 방식은 적절하다.

## 우선 보완할 부분

보고서에서 밝힌 기종 이름의 적용 범위와 분류 코드 앞자리 누락은 의미에 영향을 주는 미해결 문제다. 319쪽 표의 저장 결과를 읽어 보니 세 표 모두 `flags=[]`이며 구조 문제 표시가 없는 상태다. 보고서에 문제를 적은 것과 뒤 단계가 읽는 결과에 보류 상태를 전달한 것은 다르다.

따라서 이 두 문제를 해결하거나, 판단이 어려운 대상에 구체적인 보류 사유를 붙여 레코드와 청킹 전달 결과까지 유지해야 한다. 이름 범위를 근거 없이 나누거나 코드 앞자리를 추측해서 채우면 안 된다. 현재 `ok`는 행 분리 등의 구조 표시이며 전체 의미가 검증됐다는 뜻으로 사용하면 안 된다.

수정 뒤 독립 확인도 아직 없다. 다음 작업을 결정한다면 위 두 문제의 해결 또는 보류 전달을 한 번에 묶고, 코드를 고정한 뒤 제한된 새 자료로 한 번 확인하는 범위가 적절하다. 기존 구현을 다시 만들거나 전체 검사를 무조건 반복할 필요는 없다. 이 제안은 다음 작업 실행 승인이 아니다.

글자 표와 수식 표, 의심 숫자, 범위 밖 제목은 근거 없이 확정하지 말고 보류 또는 미확인으로 유지한다. 모든 예외를 해결할 때까지 무제한 수정하는 방식은 권하지 않는다.

## 시간이 걸린 이유

보고서의 ODL 추출 시간은 개발 13쪽 약 21초와 별도 확인 5쪽 약 26초다. 후처리는 각 세트 약 0.4~1.0초다. 그러므로 25분 이상 걸린 작업의 대부분을 추출 속도 탓으로 설명할 수 없다. 환경 위치 조사, 여러 파일 수정, 원문 대조와 별도 확인에서 발견한 네 결함의 수정이 포함돼 있었다. 단계별 작업 시간은 없으므로 정확한 비중은 알 수 없다.

## 현재 단계

핵심 파싱 코드 묶음 수정 결과 제출 → 결과 검토 중이다. 남은 의미 오류와 그 상태 전달, 수정 뒤 독립 확인을 처리할 범위를 결정해야 한다. 전체 문서 생성, 청킹 개선, 임베딩은 시작하지 않는다.
