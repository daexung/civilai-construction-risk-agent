## 비용이 커진 이유

검토 대화는 구현용 모델보다 새 입력과 출력 단가가 20배, 캐시 입력 단가가 10배다. 검토 대화의 캐시 입력만 표준 요율로 약 425.28크레딧이다. 긴 과거 대화와 도구 결과를 포함한 입력을 계속 처리한 영향이 크다. 캐시 적중은 무료를 뜻하지 않는다.

검토 대화에서 실행 도구 입력에 wait_threads가 들어간 기록 175건, read_thread 39건, send_message_to_thread 88건을 확인했다. 이는 도구 입력별 이름 포함 횟수이며 실제 내부 API 호출 수와 동일하다고 단정하지 않는다. 별도의 wait 도구 호출도 153건이었다. 진행 확인과 결과 재조회가 잦았고, 도구 실행이 중간에 반환되면 다시 기다리는 과정이 추가 모델 처리를 만들었다. 기다리는 시간 자체가 비용이라는 뜻은 아니다.

구현 쪽도 회귀 실패 수정과 재실행이 길어 출력이 늘었다. 일부 검토는 실제 결함을 찾아 필요했으나, 자주 상태를 확인하는 운영 방식까지 필요했던 것은 아니다.

## 즉시 조치와 이후 방식

- 구현 작업 중단을 전달했고, 해당 대화가 대기 상태이며 실행 중인 검사나 별도 세션이 없음을 한 번 확인했다.
- 수정은 보존했다. 현재 회귀 검사는 D28 자료 단계에서 미완료다. 새 커밋이나 배포는 하지 않았다.
- 자동 진행 확인을 중단한다. 구현 완료 보고 시에만 검토하고 중간 반복 조회는 하지 않는다.
- 다음 작업은 짧은 인계 자료를 사용하는 새 Luna 대화에서 범위를 정해 한 번에 처리하는 방식을 권한다. 이 조사에서 새 대화는 만들지 않았다.
- 검토는 최종 변경과 실패 요약을 중심으로 한 번 수행한다. 환경 문제와 검사 실패를 반복 해결할 때는 작업 범위를 다시 제한한다.

자동 승인 검토도 사용량 한도로 실패했다. 이전 기능 로그 읽기 명령은 실행되지 않았으며, 해당 거부를 우회하거나 재시도하지 않았다. 정확한 차감액은 계정의 크레딧 사용 내역에서 별도로 확인해야 한다.
