# 파싱 최종본 정리 결과

작성일: 2026-10-11. 사용자가 중간 자료 정리, 커밋, PR 생성을 요청한 범위다. 개발 순서와 지표를 먼저 기록하고 필수 자료 보존과 검증을 마친 뒤 중복 폴더를 정리했다.

## 결과

실행 위치를 `experiments/parsing-final` 한 곳으로 모았다. 기존 날짜별 작업 폴더 일곱 개는 로컬에서 제거했다. 이 폴더들은 미추적 자료였으므로 Git 변경 목록의 삭제 파일로 나타나지 않는다.

| 항목 | 정리 전 | 정리 후 |
|---|---:|---:|
| 파싱 작업 폴더 | 7개 | 최종본 1개 |
| 해당 파일 수 | 2,868개 | 72개 |
| 해당 자료 용량 | 약 1,334.0MB | 약 577.9MB |
| 확보한 공간 | — | 약 756.1MB |

용량은 1MB를 1,048,576바이트로 계산했다. 정리 후 수치는 코드·출력·원시 입력·비교 기준·보관 압축 파일을 포함한다. 이후 재생성으로 출력이나 로그 크기가 바뀔 수 있다.

## 무엇을 보존했는가

- 최종 파싱 코드 12개와 문서 버전에 묶인 교정 자료를 보존했다. 코드와 교정 자료의 원래 바이트를 변경하지 않았다.
- ODL 원시 출력, 부문 정보, 원문 PDF, 현재 출력과 두 비교 기준을 보존했다. 다른 중간 폴더를 읽던 실행·검증 경로를 최종 폴더 안으로 옮겼다.
- 이전 코드·소규모 기록·검토 그림은 내용 해시별로 중복을 제거해 `local/prior-review-artifacts.zip`에 보관했다. 압축 파일은 약 88.1MB다. 각 원래 파일과 보관 항목의 대응은 정리 목록에 있다.
- 개발 이력, 단계별 지표, 최신 생성 버전, 본문 복구 목록과 기존 검증 결과, 60·65·72쪽 원문 대조 그림을 보존했다.
- 다시 만들 수 있고 비교 기준으로 필요하지 않은 대용량 중간 출력과 중복 복사본을 정리했다.

파싱 입력과 원문 연결이 들어 있는 현재 `out/`과 필수 로컬 자료 `local/`은 유지하면서 Git에서 제외했다. 새 저장소 복제본에서 전체 검증을 하려면 이 로컬 자료를 별도로 복원해야 한다. 이 PR은 대용량 자료의 원격 백업을 대신하지 않는다.

## 실행과 검증 코드의 정리

파싱 규칙은 추가 수정하지 않았다. 실행 경로와 확인 스크립트만 정리했다.

- 필수 교정 자료를 생성 출력인 `out/`에서 분리해 `corrections.json`으로 보존했다. 원래 파일 내용과 해시는 같다.
- 실행 전에 필수 입력이 있는지 확인하고, 비어 있는 `out/`도 만들 수 있게 했다.
- 기존 확인 스크립트 중 실패를 출력하고도 정상 종료하던 경로는 실패 종료 코드를 반환하도록 했다.
- 본문 623개 목록은 짧은 문구만 담고 있다. 같은 쪽에 문구가 반복되거나 다른 긴 문장이 같은 문구로 시작하는 경우가 있어, 이전의 첫 항목 임의 선택을 제거했다. 같은 쪽·상위 구조에서 더 긴 목록 문구를 구분하고, 반복 묶음의 개수와 원문 순서를 확인한다. 개수 불일치나 원시 항목 중복 대응은 실패 처리한다.
- 문서·원시 출력·엔진·교정 전 내용에 대한 기존 적용 제한은 유지했다. `.gitattributes`로 코드와 교정 JSON의 바이트를 보존해 운영체제별 줄 끝 변환으로 해시가 달라지지 않도록 했다.

검사 개수는 정확도나 공종 수가 아니다. 원시 출력 이후의 전달 확인을 최초 PDF 추출 전체의 정확성으로 해석하지 않는다.

## 남은 문제와 운영 상태

수식 조각, 설명 소속 미확정 76개, 표 뒤 설명 후보 142개, 목차의 검색 사용 여부, 758쪽 원문 수량 조건은 기존대로 남겼다. 각 숫자의 뜻과 후속 처리 위치는 개발 이력에 기록했다. 보류와 후보 관계를 확정 계산 근거로 사용하지 않는다.

최신 수정본의 청킹·임베딩·실제 서비스 확인과 운영 코드·데이터 교체는 이번 작업에 포함하지 않았다. PR의 목적은 검증된 파싱 수정본과 개발 기록을 저장하고 실행 위치를 정리하는 것이다.
