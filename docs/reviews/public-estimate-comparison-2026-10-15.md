# 공개 단가 자료와 운영 서비스 비교

확인일: 2026-10-15, 한국 시간. 서비스 코드는 변경하지 않았다.

## 결론

다중 공종을 늘리기 전에 고칠 구체적인 운영 문제를 찾았다. 롤러칠의 요청 횟수가 계산에 반영되지 않고, 방수모르타르의 불필요한 외벽 입력과 숫자 검증 때문에 완료가 막힌다. 창호 충전은 계산과 엑셀 전달이 된다. 전체 서비스 정확도나 실사용 수요에 대한 평가는 아니다.

## 사용한 자료

- 울산교육청, 2026년 상반기 시설공사 일위대가, 건축 파일.
- 원문 안내: https://use.go.kr/user/bbs/BD_selectBbs.do?q_bbsDocNo=20260423131438030&q_bbsSn=2009
- 원본 첨부: https://use.go.kr/component/file/ND_fileDownload.do?q_fileSn=874870&q_fileId=604d81e0-5b34-4cdf-a877-120bb4d073b9
- 시트: `공종별내역서`, 열 A 품명, B 규격, C 단위, E 재료 단가, G 노무 단가, I 경비 단가, K 합계 단가.
- 실제 현장의 완성 견적서가 아니라 단가 자료다. 원본 수량은 비어 있으므로 시험에서 1㎡ 또는 1m를 지정했다. 실제 공사 수량이라고 해석하면 안 된다.
- 최초 후보였던 경기도 천둔교 내역서는 금액이 비어 있어 금액 정답 자료로 사용하지 않았다.
- 원본 두 파일은 변경 없이 `tmp/public-estimate-review/`에 보관했다. 해시는 `comparison-check.json`에 있다.

## 시점과 포함 범위 분리

운영은 2026년 하반기 노임을 사용했고 공개 자료는 상반기 자료다. 기존 로컬 상반기 노임 파일 `data/raw/labor_rates/2026H1_v1_team.csv`로 운영의 투입 인원만 다시 계산하면 다음과 같다. 운영 서비스를 과거 기준으로 다시 실행한 결과는 아니며, 독립된 계산 대조다.

- 창호 충전: 미장공 0.014 × 277,276 + 보통인부 0.004 × 172,068 = 4,570.136원. 공개 노무 단가 4,570원과 원 단위에서 일치한다.
- 롤러칠 1회: 도장공 0.012 × 263,017 + 보통인부 0.002 × 172,068 = 3,500.340원.
- 위 롤러칠 2회: 7,000.680원으로 공개 노무 단가 7,000원에 가깝다. 단가 시점 차이만으로 운영의 약 절반 품량을 설명할 수 없다.
- 공개 파일에는 직종별 투입량, 제조사 도료량, 원가계산 세부 근거가 없다. 해당 부분 전체의 정답을 검증한 것은 아니다.
- 운영은 두 완료 사례에 간접비·이윤·부가세를 더해 각각 6,821원, 8,801원을 표시한다. 공개 단위 직접비와 이 도급액을 직접 비교하면 안 된다.
- 공개 경비 0원이 실제 작업의 경비가 항상 0이라는 뜻은 아니다. 운영은 인용 주석의 인력품 2%를 적용했다.

## 엑셀 확인

- 두 완료 사례의 엑셀 다운로드 모두 HTTP 200.
- `내역서` 6행의 수량, 노무비, 경비, 직접 합계가 API의 물량 기준 참고 금액과 일치했다.
- `견적서` 합계가 API 원가계산서 도급액과 일치했다. 롤러 6,821원, 창호 8,801원.
- 셀 오류 값은 두 파일 모두 0건이었다. 이는 계산 내용의 정확성이나 수식 재계산 성공을 뜻하지 않는다.
- 조건 수정 뒤 과거 답변에서 다운로드하는 버전 문제, 로그인 저장·복원, 모바일 UI는 이번에 시험하지 않았다.
- 잘못된 1회 롤러 계산도 그대로 엑셀에 전달된다. 다운로드 성공과 업무에 쓸 수 있는 정답은 다르다.

## 실행 범위와 보관

- 공개 운영 API의 비회원 대화 3개에서 총 11개 채팅 요청을 보냈다. 이는 모델 호출 횟수가 아니다. 모델 호출 비용은 따로 집계하지 않았다.
- 숫자 오류와 동일 거절의 재시도도 모두 기록했고 성공으로 합산하지 않았다. 이용 한도를 우회하지 않았다.
- 이 활동은 개발자의 공개 자료 시험이며 외부 사용자의 수요로 집계하면 안 된다. 대화와 실행 기록은 삭제하지 않았다.
- 질문과 원본 행은 최초 응답 전에 `cases.json`에 기록했다. 정식 독립 평가 세트는 아니다.
- 응답: `roller-turns.json`, `window-turns.json`, `waterproof-turns.json`.
- 출력: `roller-service-export.xlsx`, `window-service-export.xlsx`.
- 숫자·엑셀 대조: `comparison-check.json`, 원문 이미지: `roller-source-note.png`.
- 비회원 세션 정보는 같은 임시 폴더에만 보관한다. 보고서나 Git에 넣지 않는다.
- 코드 수정, DB 직접 변경, 커밋, 배포는 하지 않았다. API가 정상적으로 저장한 시험 실행 기록은 남아 있다.

## 다음 작은 작업

1. 요청한 칠 횟수를 저장·질문·계산·엑셀까지 전달한다. 1회와 2회를 같은 조건에서 비교한다.
2. 실내 방수에서 외벽 층수·높이를 요구하지 않도록 조건을 구분하고, 0 이상 정수의 검증과 질문 표현을 바로잡는다.
3. 위 세 질문을 동일하게 다시 실행한다. 그 뒤 범위를 넓힌다. 파싱 전체 재개나 다중 공종 개발로 확대하지 않는다.
