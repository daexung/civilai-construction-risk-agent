## 연결 사용 방법

| 표 | 내용 |
|---|---|
| `chunk_sources` | 조각 → 검색 입력 행(`search_records`) → 원문 레코드·노드. 역할: `body`(원문 인용), `context_subheading`, `context_basis`, `scope_quote` |
| `chunk_cells` | 표 조각 → 원문 칸(`cell`과 공동값 `shared_value`, 합계 63,318행) |
| `chunk_links` | 대상 종류별 열(`target_chunk_id`, `target_node_id`, `target_section_id`, `target_edge_id`) 중 하나만 채운다 |
| `chunk_exclusions` | 검색 조각에서 뺀 입력과 사유 |

`chunk_links`의 연결 종류와 수:

- 소속·계층: `in_section` 5,764, `work_chunk` 4,665, `heading_node` 1,099, `parent_section` 1,099
- 표: `table_node` 2,469, `basis` 1,131, `parent_table`·`parent_cell` 각 39, `note_table_of` 544(미확정), `continues_candidate` 106(미확정)
- 설명: `related_table` 1,773(미확정 위치 근거, 길어깨는 교정 근거), `continues_part_of` 8
- 참조: `reference` 241. `confirmed=true`는 "출발 문장이 이 조각에 있음"이라는 뜻이다. 대상 상태는 `edges.target_status`, 후보는 `edge_candidates`에서 읽는다. 적용 여부는 저장하지 않는다.

예시 경로(검증에서 실제 조회):

- 185쪽 주석 조각 `r:…full-p185:n18949#0` → `reference` → `rel3600` → 대상 공통 6-1-3(확인).

## 검증

결과를 보기 전에 `checks/expected_chunks.json`을 썼다. `checks/verify_chunks.py --reload` 결과는 34개 통과, 실패 0이다.

- **처음 실행에서 실패 2개가 나왔고, 둘 다 검사 가정의 문제였다. 출력은 바꾸지 않았다.**
  - 185쪽 참조 검사: 조각 ID에 노드 번호가 들어 있다고 가정했다. 실제로는 그 주석이 앞 주석(`n18949`)에서 시작하는 묶음 안에 있다. 조각 원문 출처로 찾도록 고쳤다.
  - 555쪽 주석 표 검사: 사전 기대값에 555쪽의 주석 표 1개만 적었다. 원본 관계에는 556쪽 세 개를 포함해 4개가 있다. 사전 기대 파일은 고치지 않았다. 원본 관계 4개와 맞춰 보도록 검사를 고쳤고, 네 개 모두 미확정 연결이다.
- **실제 사례**:
  - 길어깨 세 표와 설명
  - 185쪽 공동값 4칸, 칸 안 표, 6-1-3 참조
  - 555쪽 13행 순서와 주석 표 4개
  - 758쪽 보류와 두 값
  - 501·502쪽 교정 표 7·7·13행과 글
  - 참조 상태 구별: 모호한 9-1-4는 후보 3개, `1-2-4/7.`은 하위 항목 노드까지
- **데이터 보존**:
  - 원문 릴리스 행 수가 적재 장부와 같다.
  - 입력 해시가 같다. DB 검색 입력과 `search_records.jsonl`이 같다.
  - 원문 글이 그대로다. 표 레코드가 정확히 한 번씩 들어간다.
  - 기준 관계 1,055건(교정 제외 후)이 걸린 표의 모든 조각에 기준이 있다.
  - 공동값 칸이 모두 연결돼 있다.
  - 교정과 맞지 않는 15건을 쓰지 않았다.
  - 소속 미확정 설명은 표에 붙이지 않았다.
  - 나눈 표의 모든 부분에 같은 문맥이 반복된다.
  - 외래 키가 검증 상태다.
- **재현·트랜잭션**:
  - 같은 입력으로 다시 생성하면 ID·내용·연결이 같다.
  - `chunk_links` 적재 직후 일부러 실패시키면 되돌아가고 이전 정상 묶음이 `complete`로 남는다.
  - 다시 적재해도 행 수·내용 해시가 같다.
- **원문 릴리스 확인**: `checks/verify_db.py`(재적재 없이)는 49개 통과였다.
- 검사 수는 정확도가 아니다. 조각이 의미상 잘 나뉘었는지는 위 사례와 규칙으로만 확인했다. 전체를 사람이 읽은 것은 아니다.
