### 남은 것

- **검색(후보 찾기)은 이번 범위가 아니다.** 이번 조회는 고정 청크 ID를 시작점으로 한다. 질문에서 청크를 찾는 Recall은 측정하지 않았다.
- **참조 대상이 상위 묶음인 24건은 자동으로 펼치지 않는다.** 하위 절 목록만 주고 `unresolved(group_target_not_expanded)`로 표시한다. 질문에 맞는 하위 절을 고르는 일은 다음 단계다.
- **모호 6건·부분 15건·없음 1건은 그대로 미확정이다.** 후보만 보여 주고 선택하지 않는다.
- 소속 미확정 설명 87개, 수식 부호가 남은 조각 79개, 보류 표 1개는 `normal_calculation_basis=false`로 표시할 뿐 의미를 확정하지 않았다.
- 토큰 수는 추정(`ceil(글자 수 / 1.5)`)이다. 실제 모델 토큰 수와 예산 기본값 4,000이 적절한지는 임베딩·답변 단계에서 확인해야 한다.
- 질문에 맞는 필수 조건이 무엇인지 판단(적용 여부, 계산 가능 여부)은 아직 하지 않는다.

### 새로 발견한 것

- **참조는 대부분 설명(주석)에서 시작하고 설명은 표에 위치 근거로만 붙어 있다.** 표만 선택해도 6-1-3 참조에 도달하지만 그 경로는 `미확정 소속 설명을 거침(via_unconfirmed_membership)`으로 표시한다. 185쪽 표 → 주석 ② → 공통 6-1-3 경로가 이 경우다.
- **두 진입점 검사에서 실제 누락을 찾았다**(개발 사례). 185쪽 주석에서 시작하면 관련 표는 오지만 그 표의 칸 안 작은 표가 빠졌다. 위치 근거로 붙은 표의 부모·자식(구조 확정) 표도 함께 읽도록 고쳤다.
- **청크 단위 참조 연결은 청크 하나에 여러 참조가 있다.** 참조 241개의 출발 조각은 189개다. 한 조각의 참조를 모두 따라가면 한 번에 읽을 대상이 많아져 예산이 먼저 찬다.
- **교정과 맞지 않는 15건은 이미 청킹에서 쓰이지 않아 조회 연결에 0건이다.** 제외 장치는 시험용 관계 ID로 작동을 따로 확인했다(실제 15건에서 걸러진 것은 0건).
- **추가 후보 9건 중 하나(490쪽)는 소속 미확정 설명에서 출발한다.** 대상은 확인(resolved)이지만 출발 글이 정상 근거가 아니므로 조회 결과도 정상 계산 근거 아님으로 표시한다.
- 부수 수정: `src/query.py`의 `references_from`이 기존 참조만 읽던 제한을 풀어 추가 후보를 `origin`으로 구분해 읽게 했고, `section_nodes`가 순서 번호 없는 교정 노드를 놓치지 않게 했다. 원문 검사 `verify_db`는 그대로 통과한다.

## 참조 제한·미확정 처리

| 상태 | 조회 동작 | 표시 |
|---|---|---|
| `resolved` | 확정 대상(role=target)의 조각을 읽음 | 대상 조회 가능일 뿐 적용 승인 아님, `applicability=unknown` |
| `partial` | 확인한 절을 읽음 | `partial_target`: 못 찾은 하위 항목 이름을 명시 |
| `ambiguous` | 후보 목록만 | `ambiguous_target`, 자동 선택 없음, 후보 사유 유지 |
| `missing`·`external` | 따라가지 않음 | `missing_target`·`external_target` + 이유 |
| 대상이 상위 묶음 | 하위 절 목록만 | `group_target_not_expanded` |
| 깊이 한도 | 따라가지 않음 | `depth_limit` + 출발 청크→연결→대상 경로 |
| 예산 초과 | 완결된 조각 단위로 제외 | `excluded(reason=budget)` + ID·크기·남은 예산 |
| 위치 근거(미확정) 설명·주석 표 | 확인할 문맥으로 읽음(`check_context`) | 연결 상태 `position_evidence_unconfirmed`, 확정으로 바꾸지 않음 |
| 소속 미확정 설명 | 자동으로 붙이지 않음(대상 절 안에서) | `membership_unconfirmed_not_auto_read` |

- **참조 241개 집계**(전체 의미 검수 아님): 모두 출발 청크 하나와 상태를 추적할 수 있었다. 기존 232건은 `resolved` 210 / `partial` 15 / `ambiguous` 6 / `missing` 1 그대로이고, 추가 후보 9건은 `origin`으로 구분된다. `ambiguous`·`missing`·후보 역할은 한 건도 조각으로 따라가지 않았다.
