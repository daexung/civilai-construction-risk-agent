# 파싱 본문 누락 수정 결과

작성일: 2026-10-11. 이번 작업은 파싱의 본문 누락 수정만 했다. 청킹·임베딩·배포·커밋·푸시는 하지 않았다.

## 먼저 알아야 할 결과

- **원인**: 보관 단계(`structure_store.py`)가 맨 위 항목과 맨 위 목록의 바로 아래 항목 글만 읽었다. ODL `text block` 안의 글과 목록 항목 아래의 하위 글(문단·하위 목록·글 상자)은 그 안의 표만 찾고 글은 버렸다. 원시 출력에서 이 자리에 있는 글은 **947개**다. 이전에 보고된 623개는 그 일부다.
- **결과**: 947개 중 **933개를 본문 레코드로 복구**했고 **14개는 정상 제외**(이미 표로 전달됐거나 쪽 바닥 띠 표기)했다. 설명 없는 누락은 0개다.
- **이전 목록 623개**: 복구 **616**, 정상 제외 **7**, 미해결 **0**.
- **레코드**: 22,548 → **23,481**(+933). 원시 글 하나가 레코드 하나가 되며 합치거나 나누지 않았다. 늘어난 933은 623개 목록 안 616개와 목록 밖 317개를 더한 수다.
- **기존 표**: 2,328개 모두 내용·행과 칸 연결·상태가 같다. 기존 레코드 22,548개도 글과 연결 정보가 같고, 바뀐 것은 실행 번호뿐이다(아래 '기존 결과와의 비교').
- 758쪽 Shot Blast의 `0.215`와 `0.415`는 둘 다 남아 있고 보류를 유지한다.

## 실제로 고친 것

새 폴더 `experiments/parsing-body-text-completeness-2026-10-11`에서만 고쳤다. 이전 작업 폴더, 운영 `pipeline`, 운영 데이터는 건드리지 않았다.

| 파일 | 고친 내용 |
|---|---|
| `pipeline/structure_store.py` | 목록 항목·글 상자 안의 하위 글을 원문 순서대로 읽는 경로를 추가했다. 항목 안의 표는 기존 규칙 그대로, 원래 위치 순서에 맞춰 만든다. 내보내지 않은 글은 사유를 기록한다. |
| `pipeline/structure_export.py` | 새 본문의 상위 항목, 깊이, 같은 항목 안 표 뒤 위치를 연결 정보와 관계로 내보낸다. |
| `run.py` | 제외 기록(`skipped_text`)을 `store.json`에 저장한다. |
| `verify_resume.py` | 비교 범위를 조정했다(아래). |
| `body_text_audit.py`(새 파일) | 원시 글 전체 추적, 623개 대조 목록, 수정 전 비교를 만든다. |

새 본문을 읽는 규칙은 다음과 같다. 특정 쪽이나 특정 문장을 위한 예외는 없다.

- **순서와 상하 관계**: 원시 출력의 순서대로 읽는다. 각 글에 원시 항목 id, 쪽, 위치, 제목 경로, 상위 항목 id 목록(`nesting.container_odl_ids`), 깊이(맨 위 항목 바로 아래가 1)를 남긴다.
- **소속**: 원시 출력에서 바로 위 항목을 상위로 기록한다(`list_child`, 원문 대조로 확정한 것은 아님). 가까운 표의 주석으로 붙이지 않는다. 같은 항목 안에서 표 뒤에 놓인 글은 `follows_table_in_item` **후보** 관계만 둔다(142건, 확정 아님). 상위 항목에 글이 없거나 글 상자 안 글이면 **미확정**(`unassigned_body`, 76건)으로 둔다.
- **부모·자식 중복**: 글 위치의 중심이 부모 영역 안이고 글자가 부모 글에 들어 있을 때만 같은 원문으로 보고 다시 내보내지 않는다. 이번 자료에서 이 조건에 맞는 글은 **0건**이다. 가장 비슷했던 490쪽 수식 글자(`2급 :` 항목 아래의 숫자 글자)는 위치가 부모 밖이라 따로 남겼다.
- **다른 위치의 같은 문장**: 지우지 않는다. 예: 490쪽 두 계산 예의 `(4) 수준측량은 [토목부분] 9-2-3의 2급 수준측량`은 두 번 모두 남았다(같은 쪽에 같은 글이 두 번 나오는 경우 15묶음).
- **이미 전달된 글**: 표 영역 안이고 줄마다 그 표 칸 글에 있으면 다시 넣지 않는다. 쪽 머리·바닥 띠의 부문 표기·쪽 번호는 맨 위 단계와 같은 규칙으로 뺀다. 표·제목·기준으로 이미 나간 글은 다시 넣지 않았다.
- **문맥 상태 유지**: 새 글은 열린 표, 주석 구간, 기준 대기, 쪽 첫머리 상태를 바꾸지 않는다. 그래서 기존 표의 기준·이어짐·주석 연결이 그대로다.
- 원문에 없는 문장이나 적용 조건을 만들지 않았다. 글은 원시 출력 그대로다.

### 원문 직접 대조

PDF 쪽 그림(`review/page60.png`, `page65.png`, `page72.png`)과 출력 레코드를 맞춰 봤다.

- **60쪽**: `6. 다음에 열거하는 것의 체적과 면적은 …공제하지 아니한다.` 아래 `가.`~`아.` 8개가 원문 순서대로 나오고, 모두 6번 항목의 하위 글(깊이 2)로 연결된다. `7.`·`8.`은 기존처럼 그 뒤에 온다.
- **65쪽**: `4. 토취장 및 골재원` 아래 `가.`·`나.`·`다.`·`마.`·`바.`·`사.`·`아.` 7개가 나온다. `라.`가 없는 것은 **원문 자체에 라 항목이 없기** 때문이다. `다.`의 세 줄 전체(마지막 문장 `…발생량에 대해서는 무대…로 한다.`까지)가 한 레코드에 있다.
- **72쪽**: `5. 인력운반(기계설비)` 아래 `가. 기본공식`, 변수 설명(`A : 인력운반공의 노임` … `t : 준비작업시간(2분)` 6줄), 1회 운반량, 도로상태별 왕복평균속도 4개, `※ 도로상태 구분은 토목부분 참조`, `나. 경사지 운반 환산계수(α)`, 표 뒤의 `경사지 환산거리 a×L`이 순서대로 나온다. 변수 설명 글은 원문과 같다.

### 기존 검증의 비교 범위 조정

`verify_resume.py`의 "기준·주석·제목이 완전히 같다" 검사는 본문 추가와 순서 번호 변화로 실패하게 돼 있었다. 출력 오류가 아니라 검사 가정 때문이므로 다음처럼 좁혔다.

- 기준·제목: 순서 번호만 빼고 같아야 한다.
- 기존 주석: 순서 번호만 빼고 같아야 한다. 하나라도 사라지거나 바뀌면 실패한다.
- 새 주석: 하위 글 표시와 원시 위치가 있는 것만 허용한다.
- 표 레코드 비교, 원문 해시, 교정 자료 해시, 거부 확인 등 나머지 검사는 그대로다. 해시 조건이나 원문 기준은 바꾸지 않았다.

실행 결과: `verify_resume.py` 확인 항목 915개 통과, `source_window_audit.py` 대상 286개 표 원문 영역 빠진 글자 0, 숫자 칸 7,062개 위치 차이 0, `check_guards.py` 통과, `body_text_audit.py` 통과. 이것은 정확도 점수가 아니라 정해 둔 조건을 확인한 결과다.

## 남은 문제

1. **수식 조각**: 새 본문 중 129개, 기존 본문 중 137개에 수식 글꼴 전용 부호가 들어 있다. 72쪽 기본공식처럼 식이 조각으로 나뉘어 읽기 어렵다. 원시 글은 보존했지만 식으로 읽히지 않는다. 224쪽처럼 원문 그림을 대조하는 식 교정이 필요하다.
2. **소속 미확정 76개**: 주로 측량 쪽(465쪽 이후)의 글 상자 안 계산 조건이다. 어느 계산 예나 표에 속하는지 정하지 않았다.
3. **표 뒤 후보 142개**: 같은 항목 안 표 뒤에 놓인 `[주]` 등이 그 표의 주석일 가능성이 높지만 확정하지 않았다.
4. **목차 줄**: 기존처럼 본문으로 나간다(이번에 255개 추가). 목차를 근거 검색에서 뺄지는 청킹 단계에서 정해야 한다.
5. 기존 누락 표 보충 교정이 지운 원시 글 13개는 원시 줄이 여러 칸에 걸쳐 낱말 단위로만 확인했다(275·308·500·745·750·791쪽). 이번 수정과 무관한 기존 동작이다.
6. 758쪽 Shot Blast 수량 조건은 그대로 미해결이다.
