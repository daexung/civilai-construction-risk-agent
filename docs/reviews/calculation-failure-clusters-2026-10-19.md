# 계산 실패 공통 원인 분리 (2026-10-19)

범위: 최신 full-run 실패 목록을 읽고 대표 사례를 source chunk와 명세 대조. 현재 저장된 basic-run 실패 195건 전체에 원인을 재할당한 문서는 아니다.

## 1. 단위 별칭 결함 — 공통 수정 및 영향 범위 재검사 완료

- 최소 재현: 기계설비 13-7-2·13-7-3. 사용자 입력 단위 `ton`, 원문 분모 `톤`; `conversion()`가 같은 질량 단위로 정규화하지 않아 기본 조합이 미해결.
- 공통 수정: `per_unit.conversion()`에서 입력·표 분모에 같은 별칭 정규화를 적용. 제곱/부피 단위처럼 다른 차원은 계속 거부.
- 영향: ton-family per-unit 후보 48건 선택 재검사. 저장 baseline에 비해 13-7-2·13-7-3 두 항목만 fail→pass, 나머지 46개 status 불변.
- 독립 검증: PDF p.824, PDF page index 879의 13-7-2와 13-7-3 톤당 표를 별도 전사한 기대값과 대조; 전체 노동행, 인용, 방향별 t/ton/톤↔kg 환산 확인. 상세 해시·집계는 `evals/runtime_validation/incremental-unit-cluster-2026-10-19.json` 및 `evals/check_korean_ton_unit_conversion.py`.

## 2. 축 선택자 오류처럼 보이는 원문 구조 손실 — generic normalization 불가

대표 실패: `2026-정오표1차/기계설비/13-1-1/플랜트배관설치`, 선택 명세의 오류는 p.779 표(`p779-t0`)에서 행 `6`, 열 `용접식`이 없다는 것이다.

표 추출은 p.779의 13-1-1을 여러 table chunk(`p779-t0`, `p779-t1`)로 분할하고, 이후 페이지도 p.780–p.786의 다수 조각으로 나눈다. 현재 실행 명세는 p779-t0에서 직경 6 한 행만 보존하며 `unit_rate_table`은 한 표와 `diameter` 행·`joint_type` 열만 선택한다. 실제 p.723 페이지 이미지는 표에 배관 종류, 구경, 실내/실외, 용접/나사, 직종이라는 계층 축이 있고, 용접은 직종별 여러 열, 나사는 다른 직종 구성을 가진다는 것을 보여준다. 즉 `용접식`은 해당 표 객체의 열 이름이 아니고, 여러 표를 하나의 row/column selector로 처리할 수 없다. 인접한 `p787-t0`은 재질 할증 선택표다.

판정: selector 문자열을 퍼지 매칭하거나 `joint_type`을 임의로 직종 열로 바꾸지 않는다. 이는 값 표기 정규화가 아니라 source table reconstruction 및 multi-axis/multi-table specification gap이다. 필요한 작업은 전체 절 표의 material/type/diameter/location/joint/trade/단위 분모 crosswalk, 이미지에 따른 병합 머리글 복원, 각 셀 locator와 독립 기대값 작성, 그 뒤 재사용 가능한 다중 원문표 선택 계약의 검토다. 현재 item은 fail 유지.

## 3. 다른 미해결 `unresolvable` 원인

기본 실패의 `unresolvable` 라벨은 단일 결함이 아니다. 저장된 실행 실패의 대표 항목·기존 분류에서 확인된 군집은 다음과 같다.

- `per_unit`: row/column selector가 현재 source labels와 맞지 않음; 품의 기준 분모 미기재/미파싱; 한 항목에 복합 물량 단위; 표 셀 자체가 범위 또는 비수치 문구.
- `lookup_only`: 여러 표 중 같은 입력으로 유일한 셀이 나오지 않음. 이는 arbitrary first-match를 허용할 근거가 아니다.
- 여러 일당·단위당 명세: 표 구조 손실 또는 `quantity_input`이 실제 declared fields가 아닌 설명 문자열을 참조.
- 판정 규칙: source page, locator, expected input axes와 셀 대응이 확인되기 전에는 계산기 공통 완화나 추정 매칭을 추가하지 않는다. 각 failure를 source/parse, spec mapping, executor capability, policy/open source로 나눠 queue에 유지한다.

이 분리는 기본 실행 실패 건수를 원문 정확도 통과로 바꾸지 않는다. 전체 소스 규칙 분모는 아직 미확정이다.

## 4. 다축 lookup의 불가능한 조합을 질문에서 제거

대표 실패: 건축 1-2-3 `철골세우기 장비의 작업능력`은 2개의 독립 enum으로 Cartesian 입력을 만들면 24쌍이 나온다. PDF p.573 표 `p629-t0`에는 그중 8쌍만 정의되어 있다. 저장 실행은 첫 조합을 계산했지만 뒤따른 16개 미지원 조합 때문에 항목을 실패로 기록했다. 이 값은 행·열을 잘못 고른 사례가 아니라 선택지 간 종속성을 명세 질문에 반영하지 못한 실패다.

공통 수정: `lookup()`은 입력된 표 축에서 다음 enum의 원문상 유효 선택지를 만들고, 가능한 표 셀로 유도되는 축을 한 번에 하나씩 질문한다. 마지막 축은 정확히 한 셀로 해석되는 값만 제공한다. 기존 셀 조회는 그대로 유일한 일치만 계산하고, 임의 조합은 계산하지 않는다. 독립 원문 확인은 PDF 페이지 이미지를 직접 읽고 8개의 장비·건물 유형 쌍과 처리능력을 별도로 전사해 `evals/check_lookup_dependent_domains.py`에서 값, 단위 `ton/일`, `p629-t0`의 행·열·인용 위치와 대조했다. 불가능한 굴착기/기타 조합은 계속 미해결이며 결과를 만들지 않는다.

변경된 lookup 코드를 적용해 기존 59 lookup 후보만 대화형 선택 경로로 재검사했다. 저장된 Cartesian 기본 실행의 9 pass / 50 fail은 14 pass / 45 fail로 바뀌었고, fail→pass 5건은 건축 1-2-3, 공통 8-5-3/8-5-4, 토목 3-2-2/7-4-4다. 이 다섯 건의 basic 실행 가능성이 원문 전체 셀 정확성 검증을 뜻하지 않는다. PDF p.573의 1-2-3 8셀은 별도 전사 검증했지만 나머지 네 절의 원문 셀 전체 대조는 미완료라 활성 승격 여부는 보류한다. 나머지 45건은 실패 유지되며 세부 원인은 기계 가격 표의 추출 누락, 여러 표/축의 복합 관계, 비수치·범위 셀 등으로 나뉜다. 재검사와 기준 해시는 `evals/runtime_validation/incremental-lookup-cluster-2026-10-19.json`에 기록했다.

이 변경은 합성 입력 평가의 질문 경로를 원문 표의 가능 조합에 맞춘 것이다. 앞서 보고한 687/195/174/2에 이번 5건과 기존 ton 별칭 2건의 focused delta를 적용한 현 기본 실행 partition은 692/190/174/2다. 이는 1,058 draft proxy의 실행성 합산이며 전체 규칙 정확도 수치가 아니다. PDF 독립검증은 1개 섹션/8셀만 추가되었고, 합산 부분 케이스 증거는 85개 섹션/189개 사례다. 전체 규칙 검증 0, 공식 규칙 분모 미확정은 유지한다.

## 5. 원문 부호 요율이 증감률로 선언되지 않은 경우 — 공통 명세 연결 완료

공통 2-6-1과 유지관리 1-2-11은 원문 조정표에 `-17%/+11%`, `-30%/-20%/-`를 두지만 spec coefficient에 `signed_percentage_change`가 없었다. 런타임은 값을 기준 시공량에 곱할 계수로 읽어 음수 일당량을 만들거나 `-`에서 계산 가능한 값이 없어 기본 실행을 거부했다. 이는 원문값을 바꿀 문제가 아니라 이미 지원하는 부호 변경률 규칙과 명시적 무변경 선택을 spec에 연결하는 문제였다.

원문 PDF p.45와 p.863의 표 그리드 및 요율 셀을 확인했다. 공통 2-6-1은 `quantity_input=volume` 누락도 함께 보완하고, 가운데 간격 `-`를 무변경으로 선언했다. 유지관리 1-2-11은 연 3회 이상 `-`를 무변경으로 선언했다. 해당 두 절은 높이×간격 9조합 및 기계종류×횟수×그물망 12조합을 별도 계산했다. 잔디깎기의 8%/7% 공구손료·경장비율은 기계 종류별 조건부 cost rule로 연결하고 12가격 경로에서 요율, 인용 셀, 노무비 소계 산출을 확인했다. 두 항목을 active 기본 실행 gate에 반영했다.

관련 독립 결과: `evals/runtime_validation/signed-daily-output-rates-source-audit-2026-10-19.json`. 2-6-1의 별도 [주]인 재료비 기준 5%는 현재 비용 엔진의 `labor_subtotal` 기준으로 바꾸지 않았고 여전히 미산정이다. 이번 증분 이후의 현재 gate와 해시는 handoff §16 및 `incremental-lookup-cluster-2026-10-19-followup2.json`을 기준으로 한다. 전체 규칙 정확성으로 일반화하지 않는다.
