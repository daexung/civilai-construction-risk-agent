# 적용 범위 핫픽스 — Sol 최종 검토

## 위치와 구현 담당

- 브랜치 codex/hotfix-conversation-20261101, HEAD 43a3b4acf4238681df40408cbe644dd9fc6e3a8c. 변경은 미커밋이다.

- 같은 Claude 세션 736d8718-a688-4022-8a9c-f4cdd2c8ef41을 재개해 사용했다. 초기 연결 실패 프로세스는 종료했고 중계 터미널 인코딩 오류를 UTF-8로 바로잡았다. 별도 하위 에이전트는 사용하지 않았다.
- 계산 확대 브랜치8593269는 섞지 않았다. 커밋·푸시·머지·배포·운영DB·서비스 모델/임베딩 호출은 없다. Claude 코딩 세션 호출과 서비스 API 비용을 구분한다.

## 최종 변경

1. 공종 선택 후 조건 질문에 현재 명세의 구조화된 적용 제한·별도 계상 안내를 표시한다. 추가 확인 카드를 만들지 않는다. 승인 모듈 handled_conditions가 해결한 제한은 제외한다.
2. 확보된 값으로 차단이 확정되면 무관한 필수 조건·단위 불일치·할증 질문을 계속하지 않는다. 최종 계산의 기존 검사도 유지한다.
3. 항목의 차단 사유·관련 필드·근거를 단일/다중 응답에 보존한다. 고정 진행 문구가 결과 없음의 이유를 가리지 않게 한다.
4. 규칙 평가 오류와 단가 버전 충돌은 ERROR, 산정 대상 없음은 NO_RESULT로 구분한다. 공식 범위 초과와 혼동하지 않는다.
5. 차단 카드에 사유·기준·근거를 표시하고 값을 낮추라는 일반 힌트를 제거했다.
6. 같은 단위의 필드는 명세 질문에서 읽은 라벨이 명시된 경우에만 수정한다. “높이를6m로정정해줘”의 값이 추출돼도 범위밖 라우팅으로 버려지는 결함도 고쳤다. 라벨없는6m는 임의 배정하지 않고 동일 라벨의 상충값은 모호성으로 처리한다.
7. 조건/공종 변경 시 과거 적용 범위 안내를 초기화하고 현재 유효 명세에서 다시 만든다. 설명형 blocked 선언은 적용 제한 목록에서 제외한다.

계산식·높이6m/폭0.9m 기준을 변경하지 않았다. 현재 조건 수정은 기존 대화 경로로 동작한다. 새로운 조건 수정/공종 재선택 버튼을 완성했다고 집계하지 않는다.
