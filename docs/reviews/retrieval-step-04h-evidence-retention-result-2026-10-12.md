# 검색 4h단계 결과: 잘못된 근거 제외와 전달 누락의 구조 보완 (실험용 경로)

작성일: 2026-10-12. 4g 독립 평가에서 드러난 네 문제(① 부재 대상 오판, ② 추가 대조 모델의 판단만으로 정답 근거가 제외되는 경로, ③ 소속 미확정 설명만 선택될 때 필요한 표 전달 누락, ④ 목록 완전성 표시의 모순)를 구조적으로 보완했다. 저장된 응답으로 먼저 검증하고, 필요한 사례만 소량 호출한 뒤 설정을 고정하고 기존 60문+4g 20문을 확인했다. 파싱·청킹·문서 임베딩·원문 릴리스·DB·운영 코드는 바꾸지 않았다. 새 독립 평가·서비스 연결·원격 연결·배포·커밋·푸시는 하지 않았다.

> 4g 20문은 이번 수정에 사용했으므로 **개발·회귀 자료**다. 4g의 최초 독립 결과(18/20 통과, 필수 11/13)와 고정 기록은 그대로 보존했고, 아래 결과를 독립 성공으로 세지 않는다.

## 2. 질문 원문과 약한 낱말 판정

- 질문 어절(`surface`)을 그대로 보존하고 어간·꼬리는 `analysis_confidence: weak`로만 기록한다. 부재 판정에는 약한 분석의 앞부분을 원문 전체 또는 직접 선택한 근거 글에서 찾아 쓴다. 동일성 판단의 사실로 쓰지 않는다.
- 요청 역할: `spec_connector`(`400㎜짜리`의 `짜리`처럼 수치·단위 바로 뒤), `request`, `target`, `task`, `negation`, `condition`, `number`, `division`. 작업·부정·단위·조건은 지우지 않는다.
- 새 어미 목록을 늘리지 않았다. 4f에서 추가한 닫힌 부류 문법(약한 분석용)은 그대로이며 새 형태소 서비스·임베딩·파서는 없다. 정적 검사가 실행 코드에서 질문 ID·조각 ID·절 번호 상수·`짜리`·`호퍼`·`스케일`·`계량기` 등 실패 낱말을 찾지 못했다.
- `호퍼스케일`은 잘린 `호퍼스케`가 아니라 `호퍼스케일`로 기록된다. 한글 표기와 표의 영문 `HopperScale`의 동일성은 글로 확인할 수 없으므로 보류(`target_term_unconfirmed`)는 유지한다. **표현을 알아봤다는 이유만으로 보류를 해제하지 않는다.**

## 3. 대조 모델의 근거 제외 권한 제거

- `target_compare`는 `mode: advisory`다. 경고·이유·원문 위치를 기록할 뿐 주·보조 근거를 제거하지 않고, 연쇄 제거와 자동 `not_found` 경로(`target_excluded`, `target_different`)를 삭제했다.
- 판정 후보 식별자가 `C07.1`처럼 줄 식별자 형식이어도 같은 후보로 읽는다. 형식 오류가 결과를 바꾸지 않는다(가상 입력 검사). G03의 잘못된 대조 응답을 유효한 후보 형식으로 바꾼 입력, G09 `different`, `same`, 호출 실패를 모두 시험했다.
- 경고가 있으면 `needs_confirmation`(검토용 강등)이 되지만 근거는 남는다. `same`이라고 해서 보류를 해제하지 않는다.
- 유효하지 않은 ID·버전 불일치와 확인된 다른 표 제목·소속 경계는 계속 거부한다.

## 4. 설명에서 필요한 표를 구조로 조회

- G09의 [주] `n109525`는 DB에 소속 관계가 없다(소속 미확정). 같은 절에서 문서 순서상 바로 앞 설명(비고 `n109522`)이 표 `o109468`과 `related_table` 관계를 가진다. 선택한 설명이 `membership_unconfirmed`이면 앞 설명 연쇄(최대 2개)를 거슬러 처음 만나는 표를 소유 후보로, 연쇄 설명과 함께 검토용 원문에 둔다(상태 `owner_unconfirmed`). 같은 절의 다른 표를 모두 더하지 않는다.
- G09 최초 응답과 반복 응답 2건을 각각 재생(선택 응답은 캐시, 대조만 새 호출)했다.

| 실행 | 선택 근거 | 정상 답변 근거 | 검토용 원문 | 상태 |
|---|---|---|---|---|
| 최초(`final-g20`) | [주] ① | 없음 | 표·비고·[주] | needs_confirmation |
| 반복 2 | [주]·표·비고 | 없음 | 표·비고·[주] | needs_confirmation(대조 경고 1) |

- 모델의 선택 집합은 반복마다 다르지만(모델 변동) 전달되는 검토용 원문과 상태는 일관됐다.
- G10: 규칙 `n13876`에서 기존 `related_table` 조회로 표 `o13841`이 읽힌다. 대조 모델의 판정과 무관하다.
- 원문 버전·제목 경계·길어깨 관계 제외는 건드리지 않았다. 정답 ID를 넣는 규칙은 없다(정적 검사).

## 10. 로컬 검토 도구 준비와 자동 답변·계산의 구분

- **제한된 로컬 검토 도구로의 시험**: 근거 원문을 사람이 읽고 확인하는 용도로는 4g 지원 유형(규격 명시 값·품, 제외·참조 규칙, 명확한 목록, 자료 없음, 번호 모호)에서 이번 수정으로 정답 근거 제외 경로와 전달 불일치가 제거됐다. 정상 답변 근거와 검토용 원문이 구분돼 표시된다.
- **자동 답변·계산**: 가능하지 않다. 검토용 원문은 자동 답변·계산에 쓰지 않고, 부정·수식·소속 미확정 조건, 부재 대상 탐지 누락, 모델 변동, G02 같은 불필요 보류가 남아 있다. 근거 있음은 계산 적용 승인이 아니다.
- 다음에 필요한 것: 새 질문으로 코드·설정을 고정한 독립 평가. 이번에는 질문을 만들거나 실행하지 않았다.
