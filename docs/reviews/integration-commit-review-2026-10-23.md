# 통합 변경의 커밋 구성 검토 — 2026-10-23

작업 브랜치: `codex/calculation-integration-20261023`. 이번 작업은 파일 분류·주요 의존성 검토 및 결함 재현이며 전체 변경의 코드 정확성 검토 완료가 아니다. 기존 staging은 그대로이고 커밋은 만들지 않았다.

## 커밋 구성안

| 순서 | 구성 | 함께 검토할 내용 |
|---|---|---|
| C1 | 공통 실행·상담·높이 UI 통합 | backend/frontend 변경 전체, formula/lookup/generated/policies/quantity_units, 승인 모듈, 계산 계약·Python 실행 어댑터, 대응 상담·집계·Excel 검사 |
| C2 | 원문·명세·요율 복구 | 수정 명세, source chunks, 인덱스·검증 보고, 원문 조립/인용 검증, 요율 추출기·요율, 승격·변환 스크립트·원문 기대값 검사 |
| C3 | 명세 생성·수정 및 배포 구성 | authoring 파이프라인·설정·후보/격리 검사, 별도 sandbox worker, Docker 및 번들 파일 목록 |
| C4 | 계획·인계·검토 기록 | 현재 기준 문서와 재현에 필요한 최소 결과 기록 |

C1과 C2는 하나의 통합 후보로 검증한다. formula가 generated를 import하고 compute/tools가 이를 선택하며, 가격·API·숫자 UI에도 여러 변경이 겹친다. 높이/장비/lookup을 파일 이름만으로 각각 독립 완성 커밋으로 나누지 않는다. C3 배포 파일 목록은 C1의 실행 의존성과 연결돼 있으므로 이력 분리가 독립 배포 가능성을 뜻하지 않는다. 필요하면 후속 hunk 검토로 더 나눌 수 있지만 이번에는 기존 staging을 재구성하지 않았다.

`evals/runtime_validation/git-commit-review-2026-10-23.json`에 모든 현재 변경 경로·해시·구성안을 기록했다. 경로 기반 분류이므로 tests/fixture의 최종 귀속은 import와 사용처를 확인해야 한다. 개수나 해시가 달라진 파일은 커밋 직전 다시 확인한다.

## 커밋 준비 전에 고칠 항목

### R1. 미산정 공사가 있어도 OK로 표시되는 가격 결과

`backend/agent/tools/calc/price.py:410`은 `spec.not_calculated`를 `category=None`으로 unpriced에 넣는다. 같은 파일 499행은 category가 있는 항목만 partial로 세므로 실제 누락 공사도 조회 참조값처럼 취급된다.

오프라인 최소 재현: 현재 노임표에서 인력 한 줄을 정상 가격 계산하고, 명세 not_calculated에 공사 한 항목을 추가했다. 물량 10에서 금액 2,183,160원이 계산되고 unpriced 1건이 남았으나 status=OK, partial=False였다. 기대 동작은 해당 미산정 범위를 표시하고 PARTIAL을 유지하는 것이다. 빈 입력이나 모델 실패로 생긴 현상이 아니다. 코드 수정은 아직 하지 않았다.

수정 방향: 조회·참조값과 실제 미산정 공사를 명시적으로 구분한다. category가 없다는 이유만으로 실제 미산정 항목을 제외하지 않는다. 조회 전용, 장비식 중간 Q/cm, 실제 누락 비용, 전체 산정 완료를 각각 확인해야 한다.

### R2. 장비 요율 확장에 맞지 않는 기존 회귀 검사

`evals/check_equipment.py:28`은 펌프차 추출 결과가 전체 저장 요율 파일과 같고 기계가 정확히 8개라고 가정한다. 현재 저장 파일에는 로더·굴착기 요율이 추가돼 이 조건은 유효하지 않다. 이는 가격 산식 오류가 확인됐다는 뜻은 아니며 회귀 검사 계약을 갱신해야 한다는 뜻이다.

기존 펌프차 8개 규격의 독립 기대값은 유지하고 저장 파일의 해당 하위 집합과 비교해야 한다. 신규 기종은 별도 원문 검사를 유지한다. 단순히 len 검사나 금액 검사를 지워 통과시키지 않는다. 공용 .venv에는 pdfplumber와 pypdf가 없어 이번에는 이 검사 전체를 실행하지 않았다. 공유 price 변경 검증에 필요한 의존성 준비와 펌프차 재검사는 남아 있다.

## 커밋에서 제외하거나 별도 선택할 자료

- `user-flow-validation-2026-10-20/api.env`, 서버 로그·lock·로컬 실행 자료는 로컬 보존한다. 값은 열람·출력하지 않았다.
- runtime_validation의 실패 응답·원문 이미지·과거 평가 자료는 일괄 add하지 않는다. 공개가 필요한 결과 요약 및 재현 입력만 검토해 고른다. 원본은 이미 백업돼 있다.
- `tmp_8_1_3_page.txt` 등 원문 추출 임시 파일과 결과 xlsx는 사용처·재생성 가능성을 확인한 뒤 처리한다. 삭제하지 않았다.
- 기존 staged 22개는 과거 통합 시점 상태다. 그중 13개에 추가 unstaged 수정이 있으므로 현재 index를 그대로 커밋하면 최신 완성 상태가 포함되지 않는다.

## 실행과 검증 범위

전체 검사·모델·브라우저·원문 전수 검사를 반복하지 않았다. 이번에는 R1 가격 결과를 로컬 최소 입력 두 형태(빈 자원량/가격 있는 인력량)로 재현하고, 주요 import·배포 목록·검사 의존성을 확인했다. 기존 제품 코드를 고치지 않았다. 후속 작업은 R1 수정과 R2 회귀 검사를 완료하고, 정해진 구성으로 선택 staging·최종 diff 검토를 한 뒤 사용자 커밋 지시에 따라 이력을 남기는 것이다.
