## 구현

[scope.py](../../backend/agent/estimate/scope.py)는 견적 요청을 위치가 포함된 구절로 나눠 작업·바탕·조건·제외·미확정 상태를 보존합니다. 몇 가지 알려진 작업 표현을 규칙으로 인식하지만, 알 수 없는 연결 구절이나 작업과 연결되지 않은 조건은 원문 그대로 미확정에 남깁니다. 같은 공종도 서로 다른 위치와 수량이면 별도 항목으로 보존합니다. 분석 결과는 언제나 `not_ready`이며 자동으로 계산 계획을 만들지 않습니다.

`confirm_analysis(text, analysis, decisions)`는 모든 구절과 바탕·조건 span에 대한 명시적 선택을 요구합니다. 확인증은 분석 버전, 전체 원문 해시, 분석 해시, 전체 선택 목록과 선택 해시에 묶입니다. `confirmed_result(...)`는 확인증을 다시 검증하고, 확인 내용이 달라지거나 원문이 바뀌면 거부합니다. 이 확인증은 로컬 무결성 확인일 뿐 별도 사용자 인증이나 위변조 방지 보안을 증명하지 않습니다. 여러 작업은 목록으로 반환하고 기존 단일 작업 계산 계획은 만들지 않습니다.

확인된 단일 작업은 기존 `EstimateSession` 입력 형식으로 바꿉니다. `source_plan.original_request`에는 전체 요청을 남기고 `items[0].request_text`에는 선택한 작업 구절과 확인된 조건만 구성합니다. 제외한 공종과 수량은 작업 검색 입력에 다시 들어가지 않습니다. 바탕과 조건의 원문 좌표는 `source_spans`에 보존합니다. 분석 함수는 기존 상담 흐름에서 호출하지 않습니다.

선택형 `analyze_request_with_model(text, generate=...)`는 기존 모델 클라이언트를 재사용할 수 있고 모의 함수를 주입할 수 있습니다. 기본 상담은 호출하지 않습니다. 모델 출력은 원문 위치·작업 분류·작업별 수량·단위·바탕·제외 내용을 대조합니다. 누락은 미확정으로 되돌리고, 위치/값이 틀리면 거부합니다. 모델 형식 오류나 호출 실패도 확인을 요구하며 계산 준비 상태로 승격하지 않습니다.

## 사용과 검사

Python 3.14.6과 저장소의 기존 라이브러리를 읽기 전용으로 사용했습니다. Python 실행기가 가리키는 uv 런타임 경로는 사라졌다는 경고를 출력했지만 명령은 실행됐습니다. 기존 회귀는 worktree에 없던 인용 쪽 대응표와 PDF를 원본 저장소에서 읽기 전용으로 참조해 완료했습니다. 원본 파일을 복사하거나 수정하지 않았습니다. `PYTHONPATH` 첫 경로는 늘 이 worktree로 두었습니다.

분석 JSON 출력:

```powershell
python -m backend.agent.estimate.scope "조적벽에 수성페인트 2회 100㎡"
```

독립 확인 흐름과 테스트:

```powershell
python evals/check_scope_analysis.py
```

분석 결과의 `scope_spans`를 사용자에게 보여 주고 span마다 선택을 받아 `confirm_analysis`에 넘깁니다. 반환된 `confirmation`과 같은 원문·분석을 `confirmed_result`에 넘길 때에만 단일 작업 계획이 만들어집니다. 테스트 코드가 이 흐름을 모의 선택으로 재현하며 외부 모델을 부르지 않습니다.

## 한계와 배포 판단

이 모듈은 운영 연결용 완성 라우터가 아닙니다. 작업 인식은 제한적이며 분리 기호 없는 복합 문장과 문맥상 생략된 공종은 미확정으로 남을 수 있습니다. 인용·근거 검증은 의미가 맞다는 증명이 아니므로 사용자 범위 확인이 필수입니다. 단일 작업을 기존 세션에 전달한 모의 검사는 통과했지만, 전체 대화/API와 연결하지 않았습니다. 다중 작업 계산·합산·금액·엑셀도 만들지 않았습니다.

다음 검토는 사용자 확인 UI에서 전체 구절과 대안·조건을 이해할 수 있는지, 그리고 확인 뒤에도 작업/수량이 검색과 계산에서 바뀌지 않는지에 한정하면 됩니다. 확인 UI와 운영 연결 전에는 사용자 견적에 사용하지 않아야 합니다.
