## 결론

표 후처리와 원문 보존의 핵심 결과는 이번 첫 작업의 목적에 맞는다. 555쪽 가짜 작업 행 제거, 185쪽 공동 값 연결, 807쪽 반복 기준·주석 보존, 변경 없는 청킹 호출과 불확실 상태 전달을 코드와 저장된 결과에서 확인했다.

다만 새 생성 번호를 만드는 함수에 입력 하나가 빠져 있다. 이 부분을 보완한 뒤 첫 작업을 마무리하는 것이 권장 판단이다. 새 표본 검사, 행 대응 전면 정리, 다음 쪽 주석 구현을 추가할 필요는 없다.

전체 파싱 완료, ODL 운영 채택, 계산 명세 승인으로 판단하지 않는다.

## 핵심 변경의 판단

| 변경 | 판단 |
|---|---|
| 555쪽 작업명 줄바꿈의 가짜 행 제거 | 수정된 `unstack`에서 글자 칸끼리의 줄 수 일치만으로 행을 늘리지 않는다. 저장 결과와 보고의 23건 → 13건 설명이 이에 대응한다 |
| 이미 분리한 행의 재분리 방지 | 어댑터에서 분리된 행은 조립 단계가 다시 나누지 않게 했다. 판정이 두 모듈에 남아 있다는 한계는 보고됐다 |
| 185쪽 공동 값 | 칸 식별자와 적용 레코드를 연결한다. 글에 반복 표기돼도 같은 칸을 가리키는 구조다 |
| 반복 기준과 주석 보존 | 새 내보내기 경로에서 원문 항목마다 식별자·위치를 유지한다 |
| 숫자 훼손과 행 대응 문제 | 기록된 문제를 레코드와 청크의 불확실 상태로 전달한다. 구조 정상 표시와 계산 승인도 구분한다 |
| 기존 청킹 입력 | 요구 필드를 만들어 기존 `make_chunks`를 호출하고, 별도 연결 자료로 칸·주석·기준을 추적한다 |

이 판단은 지정된 자료의 코드와 결과에 한정한다. 전체 문서의 오류를 모두 발견한다는 뜻은 아니다.

## 보고에서 추가 변경으로 표시한 부분

### 951쪽 비고 문장 복구

병합된 비고 라벨 칸을 실제 비고 내용으로 잘못 읽던 경로를 고쳤다. 특정 쪽 번호에만 맞춘 예외가 아니라 원래 라벨 칸과 내용 칸을 구분하는 변경이다. 숫자와 주석을 잃지 않게 한다는 승인 목적과 직접 관련되므로 유지하는 것이 타당하다.

### 숫자 칸이 없는 표의 본문 보존

185쪽 작은 정의 표를 포함해 기존 정리 결과가 비어 있던 표의 글을 전달하기 위한 변경이다. 본문을 보존하는 목적에 해당한다. 첫 행을 머리글로 가정한 결과를 `uncertain`으로 전달하므로 확정된 표 해석으로 받아들이지 않는다.

가정이 맞는지를 모든 표에서 확인한 것은 아니므로 파서 채택의 근거로 과대 해석하지 않는다. 이번 범위에서 원래의 빈 결과로 되돌릴 이유는 없다.

### 값 없이 끝나는 라벨 행 보존

diff에는 이 변경도 있다. 실제 12쪽에서 발생한 사례는 없고 가상 입력으로 확인한 것으로 보고됐다. 내용 보존이라는 같은 목적에 해당하며, 실제 원문 개선 사례와 구분해서 기록한다.

## 보완이 필요한 한 가지

대상:

`C:\Users\user\Desktop\PROJECTS\_table-structure-preservation-2026-10-10\checks\run_export.py`

`generation()`의 43~45줄에서 입력 기록에는 ODL JSON과 `page_map.json`의 해시가 모두 들어가지만, 생성 번호를 만드는 `key`에는 ODL 해시·처리 쪽·코드 해시만 들어간다.

같은 파일의 59~60줄에서는 `page_map.json`을 읽어 청크의 부문을 정한다. 따라서 이 입력이 바뀌면 청크의 부문이 달라질 수 있지만 생성 번호는 그대로다. 다른 결과를 같은 생성 번호로 식별할 수 있는 문제다.

현재 입력이 고정된 결과에서 실제로 자료가 섞였다는 증거는 없다. 코드상 그 가능성이 확인된 것이며, 이번에 새로 만든 생성 기록의 의미를 명확히 하기 위한 보완이다.

수정 방향:

- 생성 번호의 근거에 `page_map.json`의 내용 해시를 포함한다.
- 기록하는 입력 해시와 생성 번호를 만드는 입력 해시가 일치하게 한다.
- 실제 부문 정보 파일은 변경하지 않는다.
- 같은 입력이면 같은 생성 번호, 부문 정보 내용이 바뀌면 다른 생성 번호가 나오는지를 작은 기능 확인으로 검증한다.
- 현재 입력의 결과를 다시 저장하면 보관 결과·레코드·청크·연결 자료의 생성 번호도 일치하게 갱신한다.

표 후처리 코드는 이 보완 때문에 다시 고칠 필요가 없다. PDF 새 표본, 전체 89개 검사 반복, 추가 파싱도 필요하지 않다. 식별자 변경을 제외한 현재 결과의 내용이 유지되는지만 확인하면 된다.
