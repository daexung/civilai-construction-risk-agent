# 검색 4c단계 결과: 근거 선택 방식 소규모 비교 (4b 방식 · 서비스 언어 모델 · 재순위는 미실행)

작성일: 2026-10-12. 같은 질문 12개와 같은 후보 자료로 **기존 4b 방식**과 **기존 서비스 언어 모델**(`gemini-3.5-flash-lite`, 서비스 설정 그대로)을 비교했다. **전용 재순위 모델(Voyage)은 키가 없어 미실행**으로 기록했다. 파싱·청킹·문서 임베딩, 원문·벡터, 운영 코드는 바꾸지 않았고(작업 전후 해시·DB 지문 같음), 전체 선택기 교체·서비스 연결·배포·커밋·푸시는 하지 않았다. 호출은 20회, 비용 약 $0.14로 지시서 상한(2달러, 50회) 안이었다.

## 먼저 알아야 할 것

### 추천: **언어 모델 채택 후보 (조건부)**. 재순위와의 우열은 확인하지 못했다.

- 같은 후보에서 4b가 실패한 3건을 언어 모델이 맞췄다(V09 금지 표 혼입, V11 정답 질문 거부, V20 자료 없음 누출). 3회 반복해도 같았다.
- 그러나 **두 방식 모두 V12(소속 미확정 설명이 필요한 표)를 틀렸고**, 언어 모델은 4b가 지킨 **부분 참조 상태(V17)를 확정으로 올려** 표시했다. 그대로 4b를 대체할 수준이 아니다.
- 재순위 모델은 실행하지 못했으므로 "언어 모델이 재순위보다 낫다"는 결론은 낼 수 없다.

### 완료한 것

1. **작업 전후 보존 기록**: 변경 목록, 코드·설정·평가·출력 파일 해시, DB 지문을 작업 전(`preservation_before.json`)과 후(`preservation_after.json`)에 남겼고 모두 같다.
2. **질문 12개와 기대값을 모델 호출 전에 고정**(`expectations_fixed.json`). 원문 대조로 기대값 수정은 없었다.
3. **공통 후보·문맥을 한 번 만들고 해시로 고정**(`candidates/`, `candidate_index.json`). 후보는 기존 결합 검색 결과 그대로이며 정답을 보고 보충하지 않았다.
4. **언어 모델 20회 호출**(12문 첫 응답 + V09·V11·V12·V20 반복 각 2회). 전부 성공, 재시도 0, 형식 오류 0, 반환 식별자 오류 0.
5. 보고서의 모든 지표는 저장된 응답과 고정 기대값에서 코드로 계산했다(`evaluate.py`, `make_tables.py`). 모델의 자체 채점은 쓰지 않았다.

### 남은 것

- **V12(병원건물 요율)는 두 방식 모두 실패**: 답은 소속 미확정 설명에 기대는 표(80/50)인데, 둘 다 일반업무용 건물 표(75/30)를 주 근거로 고르고 `supported`로 표시했다. 언어 모델은 3회 모두 같은 방향으로 틀렸다.
- **언어 모델의 상태 판단은 믿을 수 없었다**: V17에서 참조 대상 상태가 `partial`로 적혀 있는데도 `supported`로 답했다. 상태는 코드가 원문 조회기의 미확정 표시에서 정하는 쪽이 안전해 보인다(아직 구현하지 않음).
- **목록은 아직 불완전**: V02에서 언어 모델이 `2-4-6`을 어디에도 고르지 않았다(후보에는 있었음). 4b는 `2-4-8`·`2-4-11`을 놓쳤다. 서로 다른 절을 놓쳤다.
- **재순위 비교는 미실행**: Voyage 키가 `.env`와 프로세스 환경에 없다(이름만 확인, 새 키·계정 발급은 하지 않음).
- 인용 검사에서 27개 중 4개가 원문과 글자 그대로 일치하지 않았다(아래).

### 새로 발견한 것

- **후보 누락은 없었다.** 조각 질문의 필수 15조각 중 14개가 후보 목록에 있었고 1개(V16의 매트부설 표)는 연결 문맥에만 있었다. 목록 질문의 필수 절 9개는 모두 후보 조각에 포함돼 있었다. 즉 이번 12문에서 틀린 것은 후보 검색이 아니라 선택이다.
- **4b가 고른 조각은 전부 이 후보 목록 안에 있었다.** 4b는 전체 조각을 점수로 비교하지만 12문에서는 후보 목록과 연결 문맥 밖의 조각을 고르지 않았다. 그래서 후보 목록을 공통으로 쓴 것이 4b에 불리하지 않았다.
- **구조 연결 조회가 선택 오류를 일부 가렸다.** V05·V16은 두 방식 모두 선택 집합에 필수 표가 없었지만 선택한 설명의 연결을 따라 최종 문맥에는 들어왔다(표의 "선택 안 됐지만 조회로 도달").
- **금지 표 혼입은 "빠뜨림"이 아니라 "섞임"이다.** 검색 순서 상위 3개를 그대로 읽으면 필수 조각이 7문에서는 전부(V17은 3개 중 2개) 들어오지만 V05·V11·V12·V15·V16에서 금지 조각이 함께 들어온다. 선택 단계의 일은 섞인 표를 걸러내는 것이다.
- **출력 형식은 안정적이었다**: JSON 파싱 20/20, 후보에 없는 식별자 0건, 별칭 대신 실제 ID를 쓴 경우 0건.

### 다음 한 가지 (제안, 시작하지 않음)

**언어 모델 선택기 + 코드가 정하는 근거 상태**를 한 가지 구성으로 정하고, 지금 12문을 개발 자료로 돌린 뒤 **새 독립 질문 20개를 먼저 고정**해 평가하는 단계를 두는 것이다. 재순위 비교가 필요하면 Voyage 키를 준비한 뒤 이 폴더의 고정된 후보·문맥(`candidates/`)으로 한 번만 실행하면 된다. 어느 쪽도 지시 전에는 시작하지 않는다.

## 공통 후보와 문맥

### 후보 생성 (변경 없음)

기존 결합 검색(`retrieve.Retriever.search(…, 'hybrid')`, 코드 SHA `6c7d120e…`, 설정 SHA `71792e8f…`)의 `fused` 목록을 순서·점수 그대로 후보로 썼다(방식당 20개 후 파생 조각 중복 제거, 질문당 23~40개). 질문 벡터는 4b 평가에서 저장된 캐시만 썼고 임베딩 호출은 0회다. 정답을 알고 후보를 보충하지 않았다.

### 문맥 보강 (4c에서 새로 붙인 것. 두 방식에 똑같이 전달)

| 후보마다 | 내용 | 원천 |
|---|---|---|
| 위치 | 부문·절 번호·절 제목, 상위 묶음 제목 | 원문 DB 절 |
| 단위 기준 | 표 본문의 `기준: (…)` 줄 | 조각 본문 |
| 소제목 | 본문 `소제목:` 줄, 표 앞 소제목은 문서 순서상 바로 앞 짧은 설명 조각의 마지막 줄(위치 근거로 표시) | 4b 선택기가 쓰던 구조 |
| 본문 | 조각 원문 그대로(자르지 않음) | `chunks.text` |
| 조각 상태 | `ok` / `membership_unconfirmed` 등과 주의 문구 | 청킹 상태 |
| 연결 | 같은 절 주변 설명·표(필수·확인 문맥 단계): 관계 종류, 연결 상태(`position_evidence_unconfirmed` 등), 정상 계산 근거 여부 | `evidence.Reader` 깊이 1 |
| 참조 | 원문 문장, 대상 상태(`resolved`/`partial` 등), 대상 절, 적용 여부(`unknown`). **참조 대상 원문은 넣지 않음** | `Reader.references` |
| 연결된 주변 자료 | 후보 목록에 없지만 연결된 조각의 본문(질문당 4~31개) | `Reader` |

- 구분: 후보 **목록**은 4b와 같은 검색 결과이고, **문맥**만 4c에서 보강했다. 4b 선택기는 후보 문맥 없이 전체 조각 점수로 선택했으므로, "문맥 보강의 효과"와 "모델 교체의 효과"는 이번 표에서 분리되지 않는다(4b 점수는 이미 같은 소제목·기준 특징을 사용했다).
- 입력 크기: 질문당 글자 수 12,691~52,641, 입력 토큰 8,104~36,913. 가격표에서 이 모델의 입력 한도 수치는 확인하지 못했지만 가장 큰 입력(36,913토큰)도 오류 없이 처리돼 분할·절단이 필요 없었다. 원문을 자르지 않았고 분할 정책은 적용되지 않았다.
- 재순위 API용 자동 잘림(`truncation`)은 호출하지 않았으므로 해당 없음이다.

## 질문별 해설

- **V09 (같은 절 다른 표)**: 4b는 혼합토사 일당 표(640)와 보통토사 표(930)를 모두 주 근거로 읽었다. 언어 모델은 3회 모두 640 표만 주 근거로, 인용도 원문과 일치했다. 후보 문맥에 앞 소제목 "나. 혼합토사 (일당)"과 "가. 보통토사 (일당)"이 각각 붙어 있었다.
- **V11 (낱말 불일치)**: 4b는 "서양식"이 자료 어휘에 없다고 보고 `not_found`로 거부했다. 언어 모델은 3회 모두 `mech 7-1-2` 표(위생공 0.694)를 골랐고, 3회차는 순위 상위 5 안에 소변기 표가 들어왔지만 선택에는 넣지 않았다.
- **V12 (소속 미확정 + 다른 표)**: 두 방식 모두 일반업무용 표를 주 근거로 골랐다. 언어 모델은 일반업무용 설명을 병원건물 근거로 읽었다(1회차는 설명 끝의 제목 줄 "나. 병원건물"을 인용). 소속 미확정 설명(`n4313#0`)은 후보 2번이었지만 상태 표시("membership_unconfirmed")를 따르지 못했다.
- **V17 (부분 참조)**: 4b는 `needs_confirmation`을 유지했고 언어 모델은 참조 줄에 `partial`이 적혀 있는데 `supported`로 답했다. 필수 조각 3개는 모두 문맥에 들어왔다.
- **V02 (목록)**: 후보에 6개 절이 모두 있었으나 두 방식 모두 일부를 못 골랐다. 목록 완결성은 선택기 하나만으로 해결되지 않으므로, 절 목록을 직접 조회하는 단계가 필요하다는 4b 결론이 유지된다.
- **V20 (자료 없음)**: 언어 모델은 3회 모두 `not_found`, 주 근거 0, "풍력발전 품 검색 필요"를 기록만 했다. 4b는 `needs_confirmation`으로 공종 1개와 대안 1개를 내보냈다.
- **V05·V16**: 두 방식 모두 선택 집합에는 필수 표가 일부 없었지만 선택한 설명의 연결과 참조를 따라 최종 문맥은 완전했다.
- **V01·V07·V15·V19**: 두 방식 모두 정상. V15의 언어 모델 인용 1건은 `[공동값 …]` 표기를 빼고 옮겨 엄격 검사에서 불일치로 셌다.

## 한계

- **표본**: 12문, 개발 자료(4b 평가에서 이미 본 질문). 12문 중 5문은 4b 실패 사례를 일부러 넣었다. 전체 정확도·독립 평가 성공이 아니다.
- **프롬프트·모델 1개**: 프롬프트를 결과를 보기 전에 고정했고 조정하지 않았다. 다른 지시문·모델에서는 결과가 다를 수 있다.
- **반복 3회**: 4문에서만 측정했다. 온도 0에서도 순위·보조 근거가 달랐다.
- **4b 비교의 공정성**: 문맥 보강(소제목·연결 상태 줄)을 모델에 글로 주었다. 4b는 같은 특징을 점수로 썼다. 효과를 분리하려면 별도 실험이 필요하다.
- **구조 조회의 영향**: V05·V16은 두 방식 모두 연결 조회가 선택 오류를 가렸다. "선택 집합"만 보면 모델이 더 나쁘게, "최종 문맥"만 보면 더 좋게 보일 수 있어 둘을 따로 적었다.
- **상위 k 지표**: 목록·자료 없음에는 구조적으로 적합하지 않아 보조로만 썼다.
- **비용·지연**: 20회 소규모 측정이다. Vertex 단가는 가격표 본문을 읽지 못해 Gemini API 표준 가격을 썼다.
