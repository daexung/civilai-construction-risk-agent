# 4g 부속 기록: 4f 개발 사례 F03의 기대값 오류와 불필요 보류

작성일: 2026-10-12. 4g 지시서 §3에 따라 4f 개발 사례 F03을 원문으로 다시 읽고 기대값 오류와 불필요 보류를 따로 기록한다. 최초 기대와 최초 결과는 그대로 두었고(`pilots/step04f/dev_cases_4f.json`, `eval_dev_live-f.json`), 상세 기록은 `experiments/retrieval-v1/pilots/step04g/f03_correction_04g.json`에 있다.

## 최초 기대와 최초 결과

- 질문: `아스팔트 포장을 절삭하지 않고 덧씌우기만 하려면 품이 어떻게 돼?`
- 최초 기대(결과를 보기 전 고정): 근거 절은 유지관리 2-1-3·2-1-4·2-1-6·2-1-7, 상태는 `needs_confirmation`(부정 조건 확인 불가), 활용형 때문에 보류하지 않음.
- 최초 결과: 상태 `needs_confirmation`(`negation_unverified`), 주 근거 유지관리 2-1-8 소파보수(표층). 기대 절에 없어 **미달**로 집계했다(4f 보고서).

## 원문 확인

| 확인 | 내용 |
|---|---|
| 기대 절 2-1-3·2-1-4·2-1-6·2-1-7 | [주]가 모두 **절삭을 포함한** 작업(절삭 후 재포장)을 기준으로 한다. 질문의 조건("절삭하지 않고")과 반대다. 제목만 보고 만든 기대였다 |
| 실제 규칙 | 유지관리 2-1-8 소파보수(표층)의 [주] ⑦ "절삭없이 아스팔트를 덧씌우는 경우에는 포장공 1인, 파쇄기 1대를 제외하고, 시공량은 25%를 증하여 적용한다." (조각 `r:complete-82c206c61e21:full-p934:n135787#0`) |

| 원문 DB 전체 | "절삭없이·절삭 없이·절삭하지·덧씌우기…않·없" 표현을 가진 조각은 위 하나뿐 |

## 분류

- **기대값 오류**: 최초 기대의 근거 절이 틀렸다. 시스템이 고른 2-1-8 ⑦이 원문상 질문 조건에 맞는 규칙이다. 이 정정은 현재 검색 결과에 맞춘 것이 아니라 PDF 934쪽과 원문 DB 글에 근거한다.
- **불필요 보류**: 선택된 근거 글이 부정 조건을 그대로 담고 있는데도 4f 코드는 부정 표지가 있으면 항상 `needs_confirmation`으로 둔다(부정 조건 확인 기능 없음). 기능 한계이며 4g에서도 고치지 않는다.
