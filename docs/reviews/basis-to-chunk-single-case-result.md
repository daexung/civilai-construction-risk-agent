# 186쪽 `p186-t0` 보존 기준의 청크 전달 확인 (단일 사례)

**보존한 기준이 기존 청킹 함수로 표에 연결됐다.** 단, 기존 파싱 레코드 없이 기능 검사 입력으로 확인한 결과이며, 전체 파이프라인 검증이 아니다.

## 비교

| 항목 | 기존 입력 | 시제품 입력 (기준 줄 보존) |
|---|---|---|
| 파싱 레코드에 `(100㎡당)` 존재 | **없음** | **있음** (`6-1-3 표면 마무리 \| 설명 \| (100㎡당)`) |
| 표 청크 `p186-t0`의 `basis` | `None` | `'(100㎡당)'` |
| 검색용 글에 `기준 (100㎡당)` 포함 | **아니오** | **예** |

`p186-t0` 검색용 글(`text`):

- 기존 입력: `6-1-3 표면 마무리` / `미장공 | 단위 인 | 수량 0.34`
- 시제품 입력: `6-1-3 표면 마무리` / `기준 (100㎡당)` / `미장공 | 단위 인 | 수량 0.34`

## 입력 출처와 한계

- **기준 줄 레코드(시제품):** PDF 186쪽의 기존 글자층과 기존 표 좌표(`tables.json`의 p186-t0, p186-t1)에 앞서 확인한 줄별 필터를 적용해 만들었다. 레코드 형식은 `parse_pages`와 같이 `{title} | 설명 | {글}`, `kind=text`, `table_id=None`, `bbox=None`이다. 절 제목은 기준 코드의 `read_titles`·`title_above`로 정했고 결과는 `6-1-3 표면 마무리`이다. 줄 위치(y 213.4)가 표 위쪽(227.3)보다 위라서 원문 순서상 표 바로 앞에 넣었다. 기준을 청크에 직접 대입하지 않았다.
- **파싱 레코드 원본이 없다.** 로컬에 `parsed.jsonl`이 없고 `data/processed/chunks.jsonl`만 있다. 그래서 기존 청크 `p186-x0`, `p186-t0`, `p186-x4`의 줄에서 레코드 5개(전체 레코드 15~19)를 **복원**해 기능 검사 입력으로 썼다. 원래 파싱 레코드를 재현한 것이 아니다. 복원 입력에서 `structure`는 청크가 `ok`·불확실 레코드 없음이라 `ok`로 두었다.
- **복원 입력의 타당성:** 기존 입력을 `make_chunks`에 넣은 결과가 저장된 세 청크(`kind`, `section`, `division`, `basis`, `structure`, `text`, `source`)와 모두 같았다. `record_ids`는 5개 부분집합이라 0부터 다시 매겨져 비교에서 제외했다. 복원한 줄글 레코드 4개도 PDF 줄별 필터 결과와 글자가 같다(앞 쪽 마지막 제목 `6-1-2 현장비빔타설`을 이어받은 경우 포함).
- **표와 기준의 연결은 정답으로 넣지 않았다.** 기준 레코드를 표 앞에 두기만 했고 연결은 기준 코드 `make_chunks`의 `pending_basis` 규칙(같은 절·같은 쪽의 바로 앞 기준 표기)이 했다.
- **함수 호출:** 기준 코드 `baf186f:pipeline/chunk.py`의 `make_chunks(records, PDF, {186: '공통'})`를 메모리에서 실행했다. 부문은 `data/processed/page_map.json`에서 `page_divisions`로 읽어 명시적으로 넘겼고, 서비스·설정 로더는 실행하지 않았다.

## 부수 확인

- 시제품 입력에서 표 외 청크의 글자는 기존과 같다. 줄글 청크 어디에도 `(100㎡당)`이 남지 않는다(`BASIS_RE`가 줄글 흐름에서 끊어 다음 표의 조건으로만 쓴다).
- 표 본문 줄(`미장공 | 단위 인 | 수량 0.34`)은 두 입력에서 같다. 숫자·주석은 고치지 않았다.
- 청크 ID 변화: 기준 레코드가 쪽 안에서 레코드 하나를 더하므로 뒤따르는 줄글 청크 ID가 `p186-x4` → `p186-x5`로 바뀐다(`page_ordinals` 규칙). 내용은 같다. 청크 ID를 참조하는 곳이 있으면 영향이 있을 수 있어 별도 확인이 필요하다.

## 하지 않은 것

- 청킹 함수 수정, 운영 코드 반영, 계산·임베딩·검색, 183개 후보 전체 검사.
- 실제 파서(`parse_pages`)와 `find_tables`의 새 실행. 따라서 시제품 레코드가 전체 파이프라인에서 같은 위치·같은 절로 나오는지는 확인하지 않았다.
- 다른 표(195쪽 `(개소당)`, 645쪽 `(㎡당)`)의 청크 전달.
