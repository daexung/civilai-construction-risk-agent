# 답변 평가

답변 하단의 👍/👎는 `POST /api/answer-feedback`를 통해 Supabase `public.answer_feedback`에 저장한다. 첫 번째, 네 번째, 일곱 번째 등 답변에서 평가 안내 문구를 표시하고 나머지 답변에서는 아이콘을 유지한다. 👎는 이유 선택이 필수이며 설명은 선택 사항이다. 화면에 질문·답변도 전송된다는 안내와 개인정보처리방침 링크를 제공한다.

서버가 생성한 `answer_id`를 기준으로 한 답변에 평가 한 개를 저장하며 변경할 수 있다. 회원의 답변은 소유한 대화의 실제 assistant 메시지에서, 비회원의 답변은 비밀 임시 세션과 서버 메모리의 실제 응답에서 찾는다. 클라이언트가 전달한 질문·답변 텍스트는 받지 않는다. 선택한 질문 본문 최대 10,000자, 답변 본문 최대 20,000자, 평가 이유와 추가 의견 최대 1,000자만 저장한다. 전체 대화, 이메일, raw IP, 계산 상태는 첨부하지 않는다.

비회원 대화를 로그인 후 회원 대화로 가져오면 기존 평가도 해당 계정·대화에 연결한다. 회원 대화를 다시 불러오면 저장된 평가를 응답에 붙여 선택 상태를 복원한다. 새 평가 생성과 변경은 별도 한도(비회원 IP 해시당 하루 10회, 회원 Google 식별자 해시당 하루 40회, 전체 하루 2,000회)를 적용하며, 동일한 내용의 재전송은 중복 집계하지 않는다. 기존 견적 사용량과 일반 피드백 제한을 소모하지 않으며 AI API를 호출하지 않는다.

RLS를 켜고 `anon`, `authenticated`의 테이블 접근을 차단했다. 운영자는 Supabase Table Editor에서 `answer_feedback`의 `rating`, `reason`, `comment`, `question`, `answer`를 검토할 수 있다. 회원 계정·대화 삭제 시 FK cascade로 연결된 평가를 삭제한다. 서버 유지보수 작업은 최초 접수 후 90일보다 오래된 평가와 7일보다 오래된 평가 제한 날짜를 정리한다. 비회원 임시 세션이 만료되거나 서버가 재시작되면 기존 임시 답변의 새 평가는 접수할 수 없다.

마이그레이션: `20261006000600_answer_feedback.sql`.
로컬 검증: 로컬 Supabase DSN을 지정하고 `evals/check_answer_feedback.py` 실행. 실제 AI 호출 없이 소유권, 유효성, 중복·변경, 복원, 제한, 접근 권한, 실패 처리, 삭제 cascade를 검사한다.
