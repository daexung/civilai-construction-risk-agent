## 먼저 닫을 작은 확인 한 가지

2c에서 `checks/compare_releases.py`에 추가한 `db.write_manifest(new)` 경로는 아직 실행하지 않았다. 비교 출력 저장 후 해시 목록이 갱신되는 실제 경로를 격리된 임시 출력 위치에서 실행해 확인한다. 기존 완료 자료 폴더와 검사 기록을 덮어쓰지 않는다.

이 비교 도구의 기존 검사는 1b의 제목 세 개 보완을 전제로 한다. 내용이 같은 두 릴리스에 그 기대값을 적용해 실패한 것을 새 데이터 결함이라고 판단하지 않는다. 원래 적용 대상과 기대값을 유지하면서 미확인 저장 경로를 확인한다. 기록을 새 실행 폴더에 남기고 임시 파일의 누락·해시 불일치가 0인지 확인한다. 전체 데이터 재생성 작업으로 확대하지 않는다.

## 구현할 조회 기능

기존 `EvidenceStore`를 보완하거나 얇은 조회 모듈로 이어간다. CLI와 코드 호출이 가능하도록 한다. 입력은 청킹 묶음 ID, 청크 ID 목록, 참조 깊이, 문맥 예산이다. 임베딩 없이 고정 청크 ID로 검증한다.

1. **원문 조회:** 청크의 검색용 문맥과 원문 본문을 구별해 반환한다. 레코드·노드·칸과 PDF 쪽·위치·부문·절을 추적한다. 표는 칸과 행 묶음, 공동 값의 원문 식별자와 적용 범위를 유지한다. 120자 미리보기를 근거 전체로 사용하지 않는다.
2. **부모와 주변 설명:** 나뉜 표의 원래 표와 필요한 행 묶음·기준·설명을 조회한다. 관련 설명에서 나온 다른 표도 연결 상태와 함께 조회할 수 있게 한다. 같은 절의 모든 글을 무조건 필수 근거로 붙이지 않는다. 확정 소속과 관계 후보를 구별하고, 후보 설명은 별도 표시한다.
3. **교정 우선:** 길어깨 보완 제목·기준을 포함하고 `superseded_relations` 15건은 실제 조회에서도 제외한다. 교정 제목·기준은 문서 순서 번호가 없으므로 숫자 순서 범위 조회만으로 빠뜨리지 않는다. 원본 잘못된 소속을 다시 따라가지 않는다.
4. **명시적 참조:** 청크의 참조 출발점을 통해 기존 232건과 추가 후보 9건 모두 조회한다. 현재 `references_from`은 기존 참조만 읽는 제한이 있으므로 보완한다. 원문 문장 전체, 조건 원문, 출처, 대상 상태와 후보를 유지한다.
5. **참조 상태:** `resolved`는 대상 조회 가능함을 뜻하며 공사 적용 승인이 아니다. `partial`은 확인한 절을 조회하되 못 찾은 하위 항목을 명시한다. `ambiguous`는 후보를 보여 주고 자동 선택하지 않는다. `missing/external`은 자료 없음·범위 밖으로 반환한다. `applicability`는 이 단계에서 `unknown`을 유지한다. 조건이 비었다고 무조건 적용으로 바꾸지 않는다.
6. **탐색:** 기본 1단계, 최대 2단계 참조를 지원한다. 방문한 대상과 연결을 추적해 순환과 중복을 막되, 서로 다른 원문 위치의 같은 문장을 삭제하지 않는다. 깊이 제한·예산 제한·미확정 대상은 각각 이유와 경로를 기록한다.
7. **문맥 예산:** 전체 조회 자료와 답변에 넣을 문맥을 구별한다. 선택한 청크의 원문, 기준·필수 조건을 우선하고 표 행이나 조건 문장 중간을 조용히 잘라내지 않는다. 예산을 넘으면 완결된 묶음 단위로 제외하거나 해당 근거를 과대로 표시한다. 제외한 ID와 이유를 남긴다. 전부 담지 못했으면 근거가 완성됐다고 표시하지 않는다. 토큰 수가 추정이면 계산 방법을 명시한다.

결과는 JSON으로 재현 가능하게 반환한다. 최소한 선택 청크, 원문·부모·기준·설명, 참조 경로와 후보, 인용 출처, 미확정·보류·수식 상태, 포함·제외 목록, 사용한 버전을 포함한다. 관계의 `confirmed` 하나로 대상 확인과 적용 여부를 함께 판단하지 않는다. 소속 미확정 설명 87개와 수식 부호가 남은 조각 79개를 정상 계산 근거로 둔갑시키지 않는다.

## 검증과 평가 준비

결과를 보기 전에 고정 사례별 필수 근거, 붙으면 안 되는 근거, 기대 참조 상태와 제한 시 행동을 기록한다. 기존 개발·회귀 질문은 재사용한다. 이번은 고정 청크를 시작점으로 한 근거 조회 검사이며 검색 Recall이나 답변 정확도 평가가 아니다.

필수 실제 사례:

- 길어깨 364~366쪽: 기계 작업의 제목·일당·표·설명을 읽고 인력 작업 근거를 잘못 붙이지 않음.
- 185쪽: 공동 값·단위·기준·설명·작은 표와 6-1-3 참조를 출처와 조건까지 조회.
- 나뉜 큰 표: 선택 부분과 원래 표의 연결, 필요한 머리글과 기준, 행 순서와 공동 값 유지.
- 555쪽: 13행과 기존 보류, 556쪽을 포함한 주석 표 후보의 미확정 상태 유지.
- 501·502쪽 교정 값·수식, 758쪽 서로 다른 값과 보류 유지.
- 같은 절 번호가 여러 부문에 있는 참조, 하위 항목 참조, 부분 확인, 여러 후보, 대상 없음, 추가 후보 출발점.
- 소속 미확정 설명, 긴 설명의 120자 이후 내용, 순서 번호 없는 교정 노드, 작은 문맥 예산.

순환과 깊이 제한은 실제 사례가 없으면 의미 있는 작은 가상 그래프로 확인한다. 위험한 후보가 정상 근거에 섞이지 않는지 검사한다. 참조 241개 전체에 출발 청크와 상태 추적이 가능한지 집계하되 전체 의미 검수라고 표현하지 않는다. 근거가 실제 원문과 같고 이번 조회가 원문·청킹 데이터와 과거 기록을 바꾸지 않았는지 확인한다.

다음 검색·임베딩 평가용 새 질문 20개와 정답 근거도 결과를 보기 전에 별도 고정한다. 공종 목록 4, 규칙 4, 품 4, 단일 견적 근거 3, 여러 공종 근거 3, 자료 없음 2로 구성하고 여러 부문·참조 조건·공동 값·수식 미확정을 포함한다. 새 질문은 이번 구현 조정에 사용하지 않고 이후 독립 평가에 남긴다. 기존 질문과 중복되지 않게 한다. 근거가 불명확한 항목은 억지 정답을 만들지 않는다.
