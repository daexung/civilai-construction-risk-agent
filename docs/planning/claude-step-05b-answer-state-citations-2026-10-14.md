## 1. 검색 상태와 답변 상태 분리

검색 결과의 `supported/needs_confirmation/not_found`는 그대로 기록한다. 별도 `answer_status`와 이유를 추가하고 사용자에게 보이는 주 배지는 답변 상태에 맞춘다.

| 상황 | 답변 상태 표시 |
|---|---|
| 질문의 조건에 대응한 설명이 원문 검증을 통과 | 답변 확인 |
| 관련 표는 있지만 질문 조건에 맞는 값·조건을 확인하지 못함 | 질문 조건 확인 필요 |
| 생성·형식·인용·숫자·예산 검증 실패로 원문만 표시 | 원문 확인 필요 |
| 검색 단계의 소속·수식·범위 등 미확정 | 확인 필요 |
| 검색 결과에서 맞는 근거를 찾지 못함 | 근거를 찾지 못함 |
| 실행 한도 또는 서버 오류 | 별도 오류 안내 |

검색이 `supported`여도 자동으로 ‘답변 확인’이 되지 않는다. 모델이 값을 못 찾았다고 한 것만으로 실제 PDF 전체에 값이 없다고 확정하지 않는다. ‘읽은 자료에서 질문 조건에 맞는 값을 확인하지 못했다’고 표시한다. 필요한 규격·단위·적용 조건이 빠졌으면 확인할 항목을 남기고 다른 행의 값을 대신 쓰지 않는다.

예: 철판 0.5㎜·규격 250㎜ 질문은 관련 덕트 표를 찾았더라도 ‘질문 조건 확인 필요’이며, 0.6㎜ 또는 다른 규격의 값을 대신 답하지 않는다. 원문은 계속 열어 볼 수 있어야 한다.

‘답변 확인’은 이 시험에서 원문 검증을 통과한 설명이라는 뜻이다. 모든 의미가 자동 증명되거나 견적 계산 적용을 승인한 뜻으로 표시하지 않는다. `applicability=unknown`을 유지한다.

## 2. 모델은 원문 위치를 선택하고 인용문은 코드가 가져오기

답변 생성 입력의 정상 답변 근거에 기존 원문 줄·표 행의 식별자를 제공한다. 모델의 인용 출력은 자료와 줄/행 위치 식별자로 바꾼다. 원문 글 자체를 모델이 복사하거나 바꿔 쓰게 하지 않는다. 실제 인용과 출처는 코드가 해당 위치의 원문에서 가져온다.

자료·위치 존재, 위치의 소속, 원문 버전, 실제 모델에 제공한 위치인지 확인한다. 현재 `build_context`는 일부 표에서 선택 행만 제공하면서 검증용 `chunk_text`는 전체 본문을 보관한다. 새 검증은 제공하지 않은 다른 행까지 허용하지 않도록 한다. 필요한 행·설명이 빠졌으면 조회 범위를 조용히 확장하거나 모델에 주지 않은 위치를 수락하지 않는다.

표 인용에는 행 이름·열 이름·단위 기준을 함께 보존한다. 공동값의 실제 값과 연결은 유지한다. 파이프라인의 긴 공동값 표지는 필요한 관계 정보로 분리해 표현할 수 있지만 원문 자료를 수정하거나 공동값을 새 값으로 만들지 않는다. 선택하지 않은 행이나 같은 절의 다른 표를 답변에 섞지 않는다.

떨어진 구간은 별도 인용으로 표시한다. 잘못된 ID를 임의의 비슷한 ID로 맞추지 않는다. 접두어 보정이 필요하면 실제 제공 목록에서 정확히 하나의 자료로만 대응될 때 수락하고 기록한다.

답변 본문에 포함된 값이 인용문이나 질문에 존재한다는 검사만으로 질문 조건과 행 대응을 보장했다고 하지 않는다. 값·품 답변은 사용한 표 행·열·단위·질문 조건 대응을 기록한다. 가짜 값이나 다른 행 값도 문맥에 있다는 이유로 통과하지 않는지 확인한다. 모델이 선택한 위치 자체의 의미가 틀릴 수 있으므로 실제 사례는 원문 표와 직접 대조한다.

검토용 원문·진단 후보는 답변 생성 입력이나 답변 인용에 넣지 않는다. 검색 단계의 확인 필요를 생성 모델이 해제하지 않는다.

## 3. 실패 전환 유지

생성 실패·시간 초과·검증 실패·원문 예산 초과는 원문 표시로 전환할 수 있다. 이 경우 답변 상태는 ‘원문 확인 필요’이며 실패 사유와 원문을 남긴다. 값·조건을 못 확인한 경우와 전송·검증 실패를 같은 이유로 합치지 않는다.

전환을 모델 답변 성공으로 세지 않는다. 과거 27회 중 6회 전환에는 수정 전 형식 실패가 포함돼 있으므로 이번 최종 코드의 결과와 별도로 보고한다. 검증을 느슨하게 해서 성공률을 올리지 않는다. 답변 결과와 출처 카드·‘답변에 인용’ 표시가 실제로 일치해야 한다.

사용자 화면에는 내부 오류 코드·모델 버전·DB 식별자를 주 설명으로 노출하지 않는다. 기술 기록은 로그나 접힌 시험 정보에 보관하고 사용자에게는 확인할 내용을 쉬운 말로 보여준다.

## 4. 시험 범위

새 실행과 검사·로그·원장은 `experiments/retrieval-v1/pilots/step05b/`에 기록한다. 기존 5단계 기록을 덮어쓰지 않는다.

실제 호출 전에 다음 기대 행동을 원문과 기존 상태로 고정한다.

- G01·G03: 정확한 품 값·단위·표 행과 원문 위치 인용.
- G08·G10: 참조와 조건 설명의 정확한 원문 위치, 다른 표 혼입 없음.
- 자유 질문 0.5㎜·250㎜: 조건 확인 필요, 다른 규격 값의 대체 없음.
- G02·G09·N19: 기존 확인 필요와 검토용 원문 유지.
- G16·G19: 근거 없음과 부문 대안 표시 유지.

가상 입력으로 없는 줄·다른 자료 줄·모델에 미제공한 행·다른 행의 수치·위치 없는 인용·시간 초과·검증 실패를 확인한다. 모델 없이 가능한 상태 처리 검사를 먼저 한다. G03의 공동값 인용은 최종 동일 구성에서 총 세 번 확인하고, 다른 정상 사례는 필요한 소수 호출만 한다.

최종 설정 고정 후 위 사례를 한 번 확인한다. 실제 브라우저에서 답변 확인·질문 조건 확인 필요·원문 확인 필요·기존 확인 필요·근거 없음의 표시를 확인한다. 원문 쪽 이미지와 부문·절·쪽·인용 위치를 함께 대조한다. 강제로 실패시킨 경우는 가상 검사로 표시하고 실제 모델 실패율에 넣지 않는다.

검색 80문이나 파싱 전체를 다시 검사하지 않는다. 관련 백엔드·화면 검사와 빌드, 옵션 꺼짐 회귀만 적절히 수행한다. 모델 결과가 실패하면 추가 프롬프트 조정을 반복하지 말고 원인과 범위를 보고한다.
