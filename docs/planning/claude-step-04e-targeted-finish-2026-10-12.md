## 1. N08: 거부된 근거를 안전하게 보존

4d의 N08 응답·거부 사유·실제 근거 조회 출력과 기존 4b의 5/5 결과를 먼저 비교한다. 필수 세 조각이 입력에 없는지, 모델이 안 골랐는지, 잘못된 대상 근거 때문에 거부됐는지 각각 기록한다.

원문에서 존재가 확인되고 선택한 설명 또는 표와 구조상 연결된 주석 표·수식 미확정 설명은 정상 계산 근거와 별도로 확인용 문맥에 보존할 수 있다. 모델이 잘못 제시한 대상 근거는 거부하되, 그 거부가 독립적으로 유효한 원문 조회 경로까지 없애지 않도록 구분한다. 기존 근거 조회의 후보 연결 경로를 우선 사용한다.

거부된 모든 표를 무조건 다시 넣지 않는다. 다른 대상 표나 관련 없는 경쟁 표는 진단 정보로만 남기며 최종 답변 문맥에 섞지 않는다. 없는 식별자·잘못된 버전·다른 자료의 위치는 그대로 거부한다. N08 이름이나 정답 식별자를 실행 코드에 넣지 않고 같은 구조의 보류 자료에 적용되는 규칙으로 구현한다.

N08의 기대는 관련 규칙·표·설명을 읽을 수 있게 제공하고 수식·소속 미확정 상태를 유지하는 것이다. 확인용 문맥 포함, 검증된 주·보조 선택, 계산 가능 여부를 따로 집계한다. 확인용 후보를 추가했다고 정확히 선택하거나 계산 가능해졌다고 보고하지 않는다. V12에서 일반업무용 표 혼입 방지가 유지되는지 함께 확인한다.

## 2. 번호만 있는 질문: DB에서 부문별 후보 확인

사용자가 절 번호만 주고 부문이나 구별되는 제목을 주지 않았다면 기존 절 색인에서 같은 번호의 본문 절을 조회한다. 번호 형식을 일반 규칙으로 처리하고 `6-1-3`을 하드코딩하지 않는다.

여러 부문에 실제 절이 있으면 각 부문·절 제목·출처를 대안으로 반환하고 부문 선택 필요를 표시한다. 검색 1위나 모델 선택 한 개로 범위를 확정하지 않는다. 사용자 질문 또는 기존 요청 문맥이 부문을 명확히 지정하면 그 범위를 적용한다. 목차·상위 묶음을 실제 작업 절과 혼동하지 않는다.

Q13과 다른 번호의 모호한 사례, 부문을 명시한 정상 사례를 확인한다. 구조 조회만으로 처리할 수 있으면 모델을 호출하지 않는다. 대안 목록을 모두 정답 작업이나 계산 적용 대상으로 표시하지 않는다.

## 3. 낱말 부재: 거부의 충분조건에서 제외

`term_absent_in_corpus`만으로 검증된 주·보조 근거를 비우고 `not_found`로 바꾸는 경로를 보완한다. 원문에 질문 낱말이 그대로 없는 것은 부족 신호이지 대상이 없는 증명이 아니다.

기존 동의어와 모델의 대상 근거 위치를 활용해 의미상 같은 대상인지 확인한다. 다른 대상의 표를 같은 대상으로 억지 해석하지 않는다. 동의어 또는 구어체의 동등성을 확인할 수 없으면 확인 필요와 부족한 대상을 표시한다. 자료 없음 질문에서는 관련 없는 후보를 정상 근거로 보내지 않는다. 자료 전체가 아닌 실제 읽은 범위를 명시한다.

원문으로 기대값을 확인한 동의어·구어체 정상 질문과 비슷한 표현의 자료 없음 질문을 소수의 개발 사례로 추가한다. 결과를 보기 전에 기대 행동을 고정한다. 이들은 독립 평가가 아니다. 기존 자료 없음 5문과 V11 정상 질문도 함께 확인한다. 특정 실패 단어를 차단 목록으로 추가하지 않는다.
