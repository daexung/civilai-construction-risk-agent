# 파싱 개선을 끝내기 위한 실행 계획

작성일: 2026-10-11
상태: 사용자 검토용 기획. 구현과 전체 처리는 아직 시작하지 않았다.

이 문서는 앞으로의 파싱 진행에 대해 이전 상태 문서와 추가 수정 제안보다 우선한다. 과거 작업 지시서는 실행 이력으로 보존한다. 사용자가 이 계획을 승인하면 소넷에게 전달할 실행 지시서를 이 범위로 작성한다.

## 1. 잘못된 진행 방식과 이번 변경

이전 문서에도 완료 조건과 예외 보류 원칙은 있었다. 그러나 실제로는 일부 쪽을 고친 뒤 다음 일부 쪽에서 발견한 문제를 추가 수정으로 연결했다. 전체에서 얼마나 문제가 생기는지, 어느 수준이면 다음 단계로 갈지, 후보를 포기할 조건이 무엇인지 실제 결정에 적용하지 못했다. 이 기획과 진행 관리는 Codex의 책임이다.

이번에는 다음 순서로 끝낸다.

**현재 후보의 상태 전달 보완과 고정 → 전체 982쪽 별도 생성과 점검 → 필요한 경우 한 차례만 보완 → 채택 범위 결정 또는 후보 탈락.**

전체를 보지 않은 채 새로운 다섯 쪽을 고르는 작업을 반복하지 않는다. 이번 계획의 끝은 반드시 결정이다. 후보가 실패해도 실패 보고와 접근 변경 판단으로 이 작업을 종료한다.

## 2. 대목표와 현재 중목표

대목표는 표준품셈을 근거로 여러 공종의 품과 공사비를 계산하고, 근거·가정·단가를 확인할 수 있는 실무용 Excel까지 만드는 서비스다.

전체 진행은 다음과 같다.

| 단계 | 완료할 결과 |
|---|---|
| 파싱 | 문서 전체의 원문·표·기준·주석·위치와 오류 상태를 다음 단계에 전달 |
| 청킹과 근거 연결 | 질문에 필요한 표와 조건, 필수 주석과 참조 원문을 함께 찾을 수 있는 묶음 |
| 임베딩과 검색 | 위 묶음을 색인하고 관련 공종·규칙을 찾는 결과 비교 |
| 계산과 견적 대화 | 검증된 계산 지식, 사용자 조건, 단가를 연결해 항목별 계산과 합산 |
| Excel과 운영 전환 | 같은 계산 결과를 실무 문서로 만들고 기존 서비스의 데이터·ID·복구 절차와 연결 |

현재 중목표는 **청킹 설계를 진행할 파싱 입력을 확정하는 것**이다. 모든 표의 계산 의미를 파싱 코드가 자동 해석하게 만드는 것은 완료 조건에 넣지 않는다. 값과 이름의 연결을 틀리게 확정하는 문제는 파싱 단계에서 해결하거나 보류해야 한다.

## 3. 재사용할 자산과 기준 코드

주력 후보는 **ODL 추출 + PDF 글자 위치 확인 + 현재 보관·후처리 코드**로 고정한다. 이는 전체 시험에 사용할 후보 선택이며 운영 채택은 아니다. 다른 도구의 새 비교는 이번에 추가하지 않는다. 이미 확보한 원문 칸, 공동 값, 반복 주석, 행 분리 기록과 위치를 재사용할 수 있기 때문이다.

시작 코드는 다음 폴더의 최종 결과다.

`C:\Users\user\Desktop\PROJECTS\_parsing-core-fixes-2026-10-11`

환경은 마지막 실행 기록에서 가져온다. 전체 디스크를 다시 검색하지 않는다.

## 4. 파싱이 전달할 결과와 사용 상태

원문 보관과 행으로 정리한 결과를 함께 전달한다. 다음 단계는 한 줄 글만 읽고 모든 판단이 끝났다고 간주하면 안 된다.

각 표에는 문서 버전·쪽·좌표·원래 칸·제목·기준·주석 관계, 판정 근거와 문제 목록이 있어야 한다. 원문 글자, 정리한 이름이나 코드, 정리 근거를 구별한다. 계산식이나 금액 적용 판단은 별도 단계다.

| 상태 | 뜻 | 다음 단계에서의 처리 |
|---|---|---|
| 구조 입력 후보 | 현재 검사에서 차단 사유가 없고 원문으로 돌아갈 수 있음 | 청킹 개발 입력으로 사용. 원문 정확성이나 계산 승인을 뜻하지 않음 |
| 해석 보류 | 값과 이름의 연결, 코드, 머리글 또는 소속을 확정하지 못함 | 원문 묶음과 사유를 보관. 확정된 작업 행·완전한 코드처럼 사용하지 않음 |
| 추출 실패 | 쪽이나 영역의 결과를 만들지 못했거나 중요한 원문을 잃음 | 실패 위치를 기록하고 정상 출력에서 제외 |

이 상태는 보관 자료, 내보낸 레코드, 후속 연결 자료에서 일관돼야 한다. 위치로 연결한 주석은 원래의 미확정 관계를 유지한다. 관계가 추정이라는 이유만으로 표 안의 모든 숫자가 훼손됐다고 표시하지 않고, 문제가 있는 판단과 사용 범위를 구체적으로 제한한다.

## 5. 실행은 세 묶음으로 제한한다

### 첫째: 알려진 문제의 상태 전달과 코드 고정

목적은 새 해석 규칙을 늘리는 것이 아니라 현재 알려진 오류가 정상 자료로 섞이지 않게 하는 것이다.

- 병합된 분류 칸에 여러 이름이 있고 각 이름의 적용 행을 결정하지 못하면 `이름 적용 범위 미확정`을 남긴다. 전체 이름을 모든 행의 확정 이름으로 쓰지 않는다. 원래 칸은 보관한다.
- 분류 코드가 줄여 적혀 있는데 완전한 코드를 정할 근거가 없으면 원문 코드와 `코드 연결 미확정`을 남긴다. 끝자리만으로 완전한 식별자를 만들지 않는다.
- 글자 표, 수식 표, 의심 숫자, 제목 미확인 등 기존 보류가 뒤 단계까지 유지되는지 이번 변경에 필요한 범위만 확인한다.
- 쪽 번호에 따라 특별 처리하는 규칙 대신 해당 구조의 특징으로 보류한다. 자동으로 가려낼 수 없는 경우 포함하는 표 유형을 넓게 보류하고 그로 인한 범위 손실을 집계한다.
- 전체 실행용 입력·출력 경로, 오류 기록과 재개 방법을 준비한다. 코드와 사용 상태 규칙을 고정한 뒤 다음 묶음으로 간다.

여기서 이름 범위 추론이나 코드 자동 완성 기능을 새로 개발하지 않는다. 이미 있는 일반 규칙으로 근거가 충분한 경우를 제외하면 보류가 기본이다. 이 단계의 완료는 알려진 문제의 상태가 결과까지 전달되고, 고정된 실행본이 만들어진 것이다.

### 둘째: 전체 문서 별도 생성과 한 번의 품질 점검

전체를 한 번 처리해 문서 종류와 실패 규모를 확인한다. 지금까지 전체 처리 금지였던 범위를 넓히는 제안이며, 계획 승인 후 실행 지시서에 명시한다.

제안 출력 폴더:

`C:\Users\user\Desktop\PROJECTS\_parsing-release-candidate-2026-10-11`

문서의 1~982쪽을 대상으로 ODL 원시 출력을 별도 보관하고, 고정한 후처리를 문서 순서대로 적용한다. 한 번의 전체 시험 생성 안에서 자원 때문에 나눠 처리할 수 있지만, 각 쪽의 처리 기록과 앞 쪽 문맥을 유지해야 한다. 분할 경계를 새 문서 시작처럼 처리하면 안 된다. 해당 연결을 구현하지 못하면 한 문서로 처리하거나 실행 불가 사유를 보고한다.

실행 중 새 오류를 발견해도 즉시 규칙을 바꾸지 않는다. 오류 유형·영향 범위·원문 위치를 한 목록으로 모은다. 정상 완료한 원시 추출은 재사용하고 후처리 변경 때문에 ODL을 다시 실행하지 않는다. 파일 손상이나 실행 실패가 난 구간만 한 번 재시도한다.

전체 자동 점검은 다음에 한정한다.

1. 982쪽 각각이 처리·내용 없음·실패 중 무엇인지 설명되는가. 빈 출력은 원문 쪽의 글자·표 영역 신호와 대조하고 이유 없이 정상으로 두지 않는다.
2. 추출한 표와 글이 보관 결과로 전달됐는가. ODL 결과만 분모로 삼지 않고 기존 표 영역 감시와 PDF 글자층 신호로 누락 의심 쪽도 찾는다. 이 감시는 모든 누락을 보장해서 찾는 검사가 아니다.
3. 원문 칸과 행·숫자·단위·공동 값의 출처가 남고, 후처리에서 빠지거나 근거 없이 중복됐는가.
4. 알려진 보류 사유가 레코드와 후속 연결 자료에도 남는가.
5. 절 미확인, 머리글 가정, 미확정 분리, 이름·코드 미확정, 추출 실패가 전체와 부문별로 얼마나 있는가.

자동 결과만으로 의미가 맞다고 판단하지 않는다. 원문 그림과 결과를 대조하는 표는 **새 표 24개**로 제한한다.

- 12개: 문서 본문을 앞에서 뒤까지 여섯 구간으로 나누고 각 구간에서 두 개를 고정된 추첨으로 선택한다. 현재 상태가 정상인 표도 포함하며, 보류 여부로 유리한 표만 고르지 않는다.
- 12개: 여러 행에 걸친 공동 값, 한 칸에 쌓인 행, 쪽 경계 표·주석, 글자·수식·복잡한 머리글의 네 유형에서 각 세 개를 선택한다. 일부 유형이 없으면 없는 사실과 대체 규칙을 기록한다.
- 이미 코드 개발에 쓴 표는 회귀 사례로 별도 유지하고 새 표 24개에서 제외한다. 과거 사용 여부를 확인하지 못한 표는 독립 표본이라고 부르지 않는다.
- 표와 필요한 앞뒤 문맥을 함께 대조한다. 숫자의 존재뿐 아니라 어느 이름·단위·기준에 연결됐는지, 불필요한 주석이 붙었는지 확인한다. 원문 이미지와 판정 근거를 남긴다.
- 추첨 방법과 예비 표 24개까지 결과를 읽기 전에 고정한다. 예비 표의 의미 대조는 필요할 때만 수행한다. 원시 추출에 들어 있다는 것과 개발에 사용했다는 것은 구별한다.

24개라는 수는 이번 의사결정을 위한 작업량 상한이다. 전체 정확도를 추정할 충분한 통계 표본이라는 뜻이 아니다. 소넷의 원문 대조는 자동 작업 결과이며 실무자 승인이라고 표현하지 않는다.

### 셋째: 한 차례 보완 또는 즉시 결정

첫 전체 결과가 아래 기준에 맞으면 추가 코드 수정 없이 이번 파싱 입력을 확정한다.

기준에 맞지 않으면 원인을 한 번에 모아 일반 규칙 결함을 **한 차례만** 보완할 수 있다. 대상은 원문 소실, 잘못된 행 대응, 보류 전달 실패처럼 후속 사용을 막는 결함이다. 표마다 개별 예외를 쓰거나 새 도구를 설치하지 않는다.

보완 뒤에는 기존 원시 출력을 재사용해 후처리를 다시 생성하고, 변경 영향 확인과 미리 남긴 예비 표 24개 대조를 한 보고로 제출한다. 첫 평가 표는 개발 자료로 바뀐 것으로 기록한다. 예비 표에서도 차단 결함이 발견되면 세 번째 수정에 들어가지 않고 후보 탈락 또는 사용 범위 축소 판단을 제출한다.

| 최초 실무 흐름 | 콘크리트 타설·거푸집·철근 가공조립 각각에서 적어도 하나의 완결된 근거 묶음을 청킹 개발에 사용할 수 있음. 계산 가능 승인은 후속 단계 |
| 결과 재사용 | 고정된 버전과 입력으로 결과를 설명할 수 있고, 후속 단계가 보류와 추정을 구별할 수 있음 |

사용 범위 수치의 목적은 어려운 표를 전부 보류해 놓고 성공이라고 선언하는 것을 막는 것이다. 분모는 전체 원시 출력의 본문 표 조각 목록으로 고정하고, 표 역할 변경이나 표 병합으로 통과 비율을 높이지 않는다. 표 누락 의심 영역과 부문 미확인 항목은 별도로 공개한다. 이 비율은 정확도가 아니다.

처리 결과는 세 가지 중 하나로 끝낸다.

1. **청킹 개발로 진행:** 위 조건을 충족. 사용 가능한 범위와 예외 목록을 함께 인계한다. 전체 파싱 입력 준비 완료라고 표현한다.
2. **범위를 정해 진행:** 특정 표 유형이나 부문에 실패가 집중됐고 제외 범위가 명확함. 전체 파싱 완료라고 부르지 않고, 제공 가능한 공종과 빠지는 기능을 제시해 범위 축소를 결정한다.
3. **후보 채택 보류:** 정상처럼 보이는 중요한 오류가 계속 나오거나, 보류가 넓어 필요한 범위를 다루지 못함. 현재 후보의 추가 예외 수정은 종료한다. 실패 유형을 근거로 대체 추출·해석 방식을 검토한다. 새 비교 실험을 자동으로 시작하지 않는다.

목표는 무조건 성공 판정을 내는 것이 아니라, 한정된 작업 뒤 다음 결정을 가능하게 하는 것이다.

## 7. 시간과 작업 증가를 통제하는 방식

전체 실행 시간은 아직 측정하지 않았다. 작은 표본의 추출 시간으로 전체 완료 시간을 약속하지 않는다. 아래는 성능 예상이 아니라 작업을 무한히 늘리지 않기 위한 예산이다.

- 첫 묶음 준비와 전체 결과의 1차 검토는 소넷의 작업 시간 합계 60분을 예산으로 둔다. 순수 추출 대기는 따로 기록한다.
- 전체 ODL 추출 대기는 30분을 상한으로 둔다. 상한에 닿으면 완료 구간과 실행 상태를 보관해 비용·진행률을 보고하고, 무기한 기다리거나 자동 재시작하지 않는다.
- 필요한 한 차례 보완과 그 결과 확인에는 추가 45분을 상한으로 둔다. 시간 안에 완료할 수 없으면 끝난 척하지 않고 현재 후보의 미완료 사유와 다음 선택을 제출한다.
- 예산 때문에 원문 대조나 상태 전달 확인을 생략하고 통과 처리하지 않는다. 미완료는 미완료로 결정한다.
- 10분마다 현재 단계, 완료량, 발견한 차단 사유와 남은 일을 짧게 보고한다. 30분 동안 같은 문제에 매달렸다면 보류나 실행 불가로 분류한다.
- 최종 결과는 하나의 보고서로 모은다. 사소한 수정마다 새 지시서와 새 승인 요청을 만들지 않는다.

실행 지시서에는 시작 시각과 단계별 소요 시간을 기록하도록 넣는다. 사용자가 기다린 시간까지 알 수 있도록 대기와 실제 수정·검토 시간을 구별한다.

## 8. 최종 산출물과 책임

소넷이 제출할 것은 다음 네 묶음이다.

1. 고정된 코드와 실행 기록, 원시 출력, 파싱 보관 결과와 후속 입력
2. 전체·부문·오류 유형별 사용 범위와 보류·실패 목록
3. 원문과 결과를 함께 볼 수 있는 새 표 대조 기록 및 기존 핵심 사례의 변경 영향
4. 위 세 결정 중 하나를 추천하는 짧은 최종 보고서

Codex는 그 결과가 미리 정한 기준에 맞는지 검토하고 결정안을 낸다. 결과를 읽은 뒤 소목표를 계속 추가하지 않는다. 명백한 새 차단 사유가 발견되면 기준 위반으로 설명하고, 남은 보완 횟수 또는 후보 탈락 규칙을 적용한다.

사용자는 서비스 범위 축소, 접근 교체, 운영 반영 같은 제품 결정을 한다. 반복 검사 개수나 함수별 구현 방법을 사용자가 매번 판단하도록 떠넘기지 않는다.

## 9. 다음 단계와 이번 승인 범위

통과하면 다음 중목표는 **표·기준·필수 주석·참조를 함께 읽는 청킹과 근거 연결**이다. 이미 만든 근거 묶음 시제품을 재사용한다. 그다음 임베딩과 검색을 비교하며, 계산 명세·서버 계산·여러 공종·단가·Excel 순으로 제품 기능을 연결한다.

현재 승인 요청의 대상은 이 실행 계획이다. 과거 허용 범위와 달라지는 부분은 전체 982쪽의 별도 로컬 추출·결과 생성, 전체 점검, 제한된 새 원문 대조다. 승인 뒤 소넷 실행 지시서를 작성한다. 원본 코드·데이터 교체, 임베딩 API, 운영 반영, 커밋·배포는 이 계획에 포함하지 않는다.

이 기획을 작성하는 동안 문서와 기존 실행 기록만 읽었으며, 구현·파싱·검사는 실행하지 않았다.
