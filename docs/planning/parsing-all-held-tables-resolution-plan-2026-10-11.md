# 남은 보류 표 전체 해결 계획

이번 목표는 남은 보류 표 286개를 모두 원문으로 확인하고, 실제 오류는 교정하며 정상인데 보류된 사유는 근거를 확인해 해제하는 것이다. 보류 표시만 없애거나 청킹으로 넘겨 해결한 것으로 세지 않는다. 이 문서는 검토할 계획이며 아직 구현을 시작한 것은 아니다.

최신 기준선은 `experiments/parsing-recovered-completeness-2026-10-11`이다. 해당 폴더의 전체 출력·코드·교정 자료와 PDF 버전을 고정하고 시작한다. 대상은 `out/remaining_review.json`의 표 286개다. 기존 표 277개와 복구 표 9개를 합한 수다.

## 문제별 해결 방법

| 보류 사유 | 해당 표 수 | 처리 방법 |
|---|---:|---|
| 행 대응 확인 필요 | 144 | 원문 가로 선·글자 위치·문장 뜻으로 한 행 안의 줄바꿈, 서로 다른 행, 여러 행의 공통 칸을 구분. 확정한 행 구조를 적용하고 출력 행과 원문 연결 확인 |
| 이름 적용 범위 미확정 | 81 | 상위 묶음 이름과 하위 행 이름을 구분하고 이름마다 적용 행을 기록. 한 이름의 줄바꿈과 별도 이름을 구분. 단위·정의·설명 표에는 그 역할에 맞게 연결 |
| 코드 연결 미확정 | 48 | 원문의 완전한 번호와 줄임 번호의 관계를 확인. 앞자리 근거가 있으면 원문 번호와 완전한 번호를 함께 보관. 다른 품목·표의 앞자리를 추측해서 넘기지 않음 |
| 머리글 가정 | 6 | 실제 머리글 끝과 본문 시작을 원문으로 지정하고 단위·범위와 값의 연결 확인 |
| 칸 경계 넘음 | 1 | 82쪽 원문을 대조해 글자가 실제로 잘못 들어갔는지 확인. 실제 오류면 칸·글자 위치 교정, 정상 돌출이면 확인 근거 기록 |
| 행 이름 구분 미확정 | 1 | 68쪽 상위 이름과 `기계실`·`옥내일반`을 분리해 각 행의 값에 연결 |
| 굵은 계단선 미반영 | 8 | 275~277쪽 원문 선과 번호 표시, 관련 주석·출력별 표를 함께 대조. 선이 구분하는 적용 범위를 각 행·열의 값에 연결하고 근거 보관 |

한 표에 여러 사유가 있어 위 표 수를 더하면 286개와 같지 않다. 관리 단위는 중복 없는 표 286개이며 사유별 확인은 모두 해야 한다.

## 진행 순서

### 1. 전체 작업 목록과 원문 기준 만들기

286개 표 모두를 한 작업 목록으로 관리한다. 표 식별자, 쪽, 보류 사유, 원문 그림, 기대 구조, 수정 결과, 확인 근거, 미해결 이유를 기록한다. 표마다 모든 사유를 해결했는지 추적한다.

원문 그림에는 표 전체와 관련 제목·단위·주석을 포함한다. 다음 쪽으로 이어지거나 다른 표를 참조하면 필요한 원문을 함께 확인한다. 이미 잘못 복구된 영역을 원문 전체라고 가정하지 않는다.

각 표가 값 표인지, 정의·단위·설명 표인지 구분한다. 설명 표를 억지로 수량 계산 표로 만들지 않는다. 계산 대상이 아닌 표도 내용과 연결을 정확히 보관하는 것으로 그 표의 문제를 해결한다.

수정 결과를 보기 전에 원문 기준의 기대 행·이름·번호·머리글·적용 범위를 기록한다. 자동 판정 후보를 실제 기대 결과로 그대로 사용하지 않는다.

### 2. 공통 문제는 유형별로 처리

각 유형 안에서 같은 구조인 표를 묶는다. 몇 개의 대표 표에서만 통과했다고 나머지를 승인하지 않는다. 공통 규칙을 적용한 모든 대상 표를 원문 기준과 대조한다.

처리 우선순위는 행 구조와 머리글, 이름과 번호 연결, 적용 조건 순으로 둔다. 행과 열의 구조가 정해져야 이름과 번호가 올바른 값에 연결된다. 굵은 선이 필요한 표 8개는 별도 적용 조건 자료로 처리한다.

원문 근거로 공통 처리가 가능한 경우에만 규칙을 추가한다. 줄 수가 같거나 가장 가까운 이름이라는 이유만으로 확정하지 않는다. 머리글·부문·품목이 바뀌면 번호와 이름의 이어받기가 끊어지는지도 확인한다.

### 3. 남은 예외는 표별 교정 자료로 마무리

공통 규칙으로 확정할 수 없는 표는 원문을 직접 보고 표별 교정 자료를 만든다. 기존의 문서 버전 확인, 수정 전 내용 확인, 원문 위치 보관 방식을 재사용한다. 예외 하나 때문에 범용 판정 기준을 계속 넓히지 않는다.

원래 글자·칸과 교정 후 읽기용 내용을 구분해 보관한다. 이름을 여러 행에 적용하거나 줄임 번호를 완전한 번호로 만들 때도 원문 근거와 적용 행을 남긴다. 칸 식별자가 바뀌면 전후 대응과 기존 교정 자료를 함께 갱신한다.

굵은 계단선은 이미지 첨부만으로 해결됐다고 세지 않는다. 관련 주석에 적힌 장비 출력과 선의 구분을 연결하고, 어떤 값에 어떤 적용 조건이 있는지 구조로 전달한다. 원문 계산 결과를 재계산해 바꾸는 작업은 하지 않는다.

### 4. 전체 출력과 변경 영향 확인

최신 후보를 복사한 전용 폴더에서 수정한다. 기존 원시 출력과 PDF를 재사용하며 새 출력은 별도로 생성한다. 운영 코드·자료와 이전 후보를 덮어쓰지 않는다.

모든 대상 표에서 원문 글자·위치, 원문 칸, 이름·단위·값·번호·적용 조건, 출력 레코드와 근거 연결을 비교한다. 내용이 빠진 경우뿐 아니라 칸 하나에 몰림, 다른 행·열 연결, 잘못된 반복도 확인한다.

보류 해제는 실제 구조와 출력에 교정이 적용된 뒤에 한다. 확인 기록만 작성하거나 표시만 제거한 결과는 해결로 세지 않는다.

전체 982쪽 출력을 생성하고 기존에 완료한 수정이 유지되는지 확인한다. 대상 밖 변화는 목록화하고 원문으로 확인한다. 기존 출력과 같다는 사실은 변경 영향 확인이며 그 내용 자체가 정확하다는 증거와 구분한다. 새로 확인된 실제 오류는 별도 목록에 추가하고 최종 판단에서 숨기지 않는다.

## 완료 판단

각 표는 아래 상태 중 하나로 기록한다.

- 정상 확인 완료: 보류 원인을 원문으로 확인했고 실제 구조와 출력이 맞음.
- 교정 완료: 잘못된 구조나 연결을 고쳤고 원문 기준과 출력이 맞음.
- 미해결: 근거 부족 또는 오류가 남음. 완료로 세지 않음.

**286개 각각의 모든 보류 사유에 확인 또는 교정 완료 기록이 있어야 이번 목표를 완료했다고 보고한다.** 필요한 항목은 표의 역할에 따라 다르지만 원문 내용 보관과 올바른 연결은 모든 표에서 확인한다. 미해결을 추측으로 채우거나 단순히 보류를 해제해 목표를 달성하지 않는다.

원문 자체가 모호하거나 충돌한다면 해당 위치와 충돌 내용을 구체적으로 제출한다. 불가능한 확정을 약속하지 않으며, 문제가 남은 상태를 완료로 보고하지 않는다.

이번 완료가 전체 문서의 모든 계산값과 견적 산식의 검증을 뜻하지는 않는다. 값의 사용 조건 보관과 계산 로직의 정확성 검증은 구분한다. 현재 알려진 보류를 해소한 입력을 기준으로 다음 청킹 단계를 계획한다.

## 작업 결과로 받을 자료

- 표 286개 전체 작업 목록과 표별 해결 결과.
- 원문 그림과 기대 구조, 수정 전후 결과, 근거 연결.
- 공통 규칙과 예외 교정 자료, 버전 확인과 적용 거부 확인.
- 최종 전체 출력과 코드·자료 버전.
- 대상 밖 변경 목록, 새로 확인한 문제와 실제 미해결 목록.

결과 보고서는 쉬운 한국어로 해결한 표 수, 남은 표 수, 남은 이유부터 적는다. 검사 개수를 정확도로 표현하지 않는다. 진행 보고는 유형별로 닫은 문제와 남은 문제를 중심으로 한다. 일부 표 완료를 전체 파싱 완료라고 표현하지 않는다.

청킹·임베딩·운영 전환은 이번 작업에 포함하지 않는다. 계획 승인 뒤 오퍼스에게 위 범위의 구현 지시서를 전달한다.
