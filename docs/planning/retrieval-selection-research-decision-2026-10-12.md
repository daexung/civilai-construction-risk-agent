# 근거 선택 방식 추가 조사와 다음 비교 계획

작성일: 2026-10-12
상태: 공개 자료와 기존 결과에 근거한 계획. 새 모델 호출과 구현은 하지 않았다.

## 1. 결정

기존 결합 검색과 원문 조회를 유지하고, 낱말 일치 위주의 근거 선택을 의미 비교 방식으로 개선한다. 언어 모델 선택기를 곧바로 최종 채택하지 않는다. 같은 후보와 같은 문맥을 주고 전용 재순위 모델과 기존 서비스 언어 모델을 비교한 뒤 선택한다.

최종 구성은 후보 검색 → 구조 문맥을 포함한 후보 비교 → 필요한 원문·참조 조회 → 부족한 항목이 있을 때 제한된 추가 조회 → 근거 상태와 함께 전달이다. 모델이 모든 관계를 새로 만들거나 계산 적용 여부를 확정하는 구성은 아니다.

## 2. 공개된 실무 방식

아래는 업체가 공개한 제품 동작과 기술 문서다. 모든 에이전트가 이 방식이라는 통계도, 한국어 건설 표에서 우수하다는 증명도 아니다.

| 공개 사례 | 확인한 방식 | 우리에게 적용할 점 |
|---|---|---|
| Anthropic의 문맥 관리와 Claude Code | 먼저 일부 문맥을 제공하고 필요할 때 식별자와 도구로 추가 자료를 읽는다. 무제한 탐색은 지연과 시행착오를 늘릴 수 있다. | 기존 색인을 유지하고 필요한 원문만 추가로 읽는다. |
| Anthropic의 Contextual Retrieval | 문맥을 붙인 검색, 키워드와 벡터 검색, 재순위를 결합한다. | 이미 있는 문맥 청크와 결합 검색을 재사용하고 선택 단계를 비교한다. |
| Azure AI Search | 검색 후보를 의미 기반으로 재순위하며, 에이전트 검색은 질문 분해와 조회 결과·출처를 결합한다. | 후보 검색, 후보 선택, 근거 충분함을 별도 역할로 다룬다. |
| Cohere Rerank | 한국어를 포함한 여러 언어를 지원하고 구조 자료의 필드 표현을 안내한다. | 표를 숫자 문자열만 주지 말고 제목·기준·행 이름과 함께 비교한다. |
| Voyage Rerank | 질문과 후보 글을 함께 읽어 관련도를 평가한다. | 임베딩을 다시 만들지 않고 현재 후보에 적용할 수 있는 비교안이다. |

## 3. 현재 실패를 어떻게 해석할 것인가

4b 독립 결과는 필수 근거 조회 24/27이지만, 답변에 실제 전달되는 문맥에서는 21/27이다. 앞으로는 최종 문맥을 우선 평가한다. 관련 절 하나를 찾았다는 사실만으로 표 선택이나 답변 준비가 끝난 것은 아니다.

| 문제 | 필요한 조치 | 한 가지 도구만으로 해결되지 않는 이유 |
|---|---|---|
| V09·V12에서 다른 표 선택 | 제목·대상·단위·설명을 함께 읽고 표를 비교 | 같은 절 안의 표 선택도 재순위 대상이다. 앞선 '재순위가 필요 없다'는 판단은 너무 좁았다. |
| V12의 대상어가 소속 미확정 설명에만 있음 | 해당 설명을 후보 문맥에 포함하고 미확정 상태 표시 | 모델도 입력에 없는 설명은 판단할 수 없다. 선택해도 소속 확정으로 바꾸면 안 된다. |
| V11의 서양식과 서양식대변기 | 단어의 완전 일치 대신 의미 비교 | 조사·활용형 예외를 계속 더하는 방식은 일반화에 한계가 있다. |
| V02의 목록 일부 누락 | 대상 범위를 정하고 절 목록을 조회해 빠진 공종 확인 | 재순위는 주어진 후보 순서를 바꾸므로 없는 후보를 만들 수 없다. |
| V20의 없는 대상 | 대상과 요청 조건을 직접 뒷받침하는 근거 확인 | 관련도 점수는 답변 가능 확률이 아니다. 낱말 일치 비율만으로 결정하지 않는다. |
| 필요한 설명이 최종 문맥에서 빠짐 | 선택 뒤 필수 조건·참조의 전달 여부 검사 | 후보 조회 성공과 최종 문맥 완성은 다르다. |

## 4. 비교할 두 방법

현재 4b 결과를 기준선으로 보관하고 아래 두 방법을 같은 후보 묶음에서 비교한다.

**방법 가: 전용 재순위 모델.** 기존 계획의 Voyage 계열에서 한 모델만 비교 후보로 삼는다. 실제 이용 가능 여부·비용·자료 전송 조건은 실행 지시 전에 확인한다. 새 계정이 없으면 비교 미실행으로 기록하며, 임의로 다른 모델 여러 개를 시험하지 않는다. 이 방법은 표 선택의 품질을 측정한다. 관련도 점수로 자료 없음이나 목록 완성을 자동 확정하지 않는다.

**방법 나: 기존 서비스 언어 모델.** 후보들을 함께 읽고 선택한 원문 식별자, 뒷받침 문장, 빠진 조건, 추가 조회 요청을 구조화해 반환하게 한다. 현재 설정 모델은 `gemini-3.5-flash-lite`다. 설정에 있다는 사실과 실제 호출 가능 여부는 구분한다. 이번 조사에서는 호출하지 않았다.

두 방법 모두 같은 제목·절 경로·소제목·단위 기준·표 내용·주변 설명을 받는다. 주변 설명의 소속 미확정 표시도 같다. 표가 크면 기존 구조 조각과 원문 조회를 활용하고 묵시적으로 잘라 보내지 않는다. 출력 식별자와 인용은 코드로 원문 존재 여부를 검사한다. 이 검사는 의미 판단의 정확성을 보장하지 않으므로 정답 자료와도 비교한다.

비교는 두 부분으로 나눈다. 먼저 동일 후보에서 표 선택 품질을 비교해 모델 차이를 확인한다. 그다음 더 나은 방법에 목록 탐색·추가 조회·근거 상태 처리를 연결하고 전체 경로를 평가한다. 두 방식을 모두 직렬로 붙이는 것은 초기 기본안이 아니다.

## 5. 질문별 처리

- 특정 값: 질문의 대상·작업·단위·조건과 맞는 표를 비교하고, 선택한 표에 필요한 기준과 주석을 읽는다.
- 규칙: 규칙 본문과 조건을 우선 읽고, 명시된 참조 절을 기존 연결로 조회한다. 적용 여부는 근거가 충분할 때만 별도로 판단한다.
- 목록: 상위 몇 개만 반환하지 않는다. 먼저 요청 범위를 정하고 해당 절 목록을 조회한다. 범위가 모호하거나 모두 읽지 못하면 일부 목록임을 표시한다.
- 근거 부족: 어떤 대상 또는 조건의 근거가 없는지 남긴다. 검색 실패만으로 문서 전체에 없다고 단정하지 않는다.

추가 조회는 기존 계획대로 질문당 최대 두 번이다. 허용 동작은 질문을 보완한 검색, 절 목록 조회, 선택한 원문과 참조 읽기로 제한한다. 예산에 걸리면 누락 항목을 표시하고 완료로 보고하지 않는다. 파싱 단계의 보류·수식 미확정·소속 미확정은 모델 판단으로 해제하지 않는다.

## 6. 실행 순서와 중단 기준

1. 기존 후보 출력과 4b 결과를 고정한다. 실패 사례와 정상 사례 약 12개로 두 방법의 소규모 비교를 먼저 한다. 호출 전 예상 비용과 최대 호출 수를 기록한다.
2. 같은 후보에서 의미 선택이 개선되는지 확인한다. 개선이 없으면 전체 구현으로 확대하지 않고 입력 부족·선택 실패·조회 누락 중 원인을 보고한다.
3. 더 나은 후보에만 제한된 조회를 연결한다. 이미 사용한 질문 60개는 개발·회귀 자료로 사용한다. 문구 수정마다 새 독립 질문을 만들지 않는다.
4. 설정을 고정한 뒤 별도로 마련한 새 질문으로 한 번 평가한다. 언어 모델은 주요 표 혼입·자료 없음·정상 질문 거부 사례를 반복 실행해 결과 흔들림도 기록한다.

우선 지표는 최종 전달 문맥의 필수 근거 포함률이다. 기존 목표 95%를 유지하고 잘못된 주 근거, 정상 질문 거부, 자료 없음 처리, 목록 누락을 따로 보고한다. 지연과 비용도 함께 비교한다. 작은 평가 세트의 통과를 전체 문서 정확도 95%로 표현하지 않는다. 두 방법이 비슷하면 더 단순하고 저렴한 방법을 택한다.

평가 자료의 기대값도 원문과 기존 미확정 상태에 맞아야 한다. 미확정인 소속을 반드시 확정 선택하라고 요구하는 기대값을 만들지 않는다. 모델이 자기 선택을 맞다고 평가한 결과만으로 통과시키지 않는다.

개발·회귀와 독립 평가를 구분하는 운영 원칙은 [Anthropic 에이전트 평가 안내](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)를 참고했다. 질문 수·호출 한도·통과 목표는 우리 프로젝트의 결정이다.

## 7. 기존 계획에서 유지할 것과 달라지는 것

유지: 파싱·청킹·문서 임베딩, PostgreSQL 원문과 절 연결, 결합 검색, 근거 조회, 원문 출처·보류 표시, 추가 조회 두 번 제한.

변경: 4b에서 허용하지 않았던 의미 비교 모델의 소규모 호출 실험을 다음 단계로 제안한다. 재순위 비교도 다시 포함한다. 이는 새 설계 결정이며 이미 구현한 것으로 기록하지 않는다.

당장 추가하지 않을 것: 새 파서, 문서 재임베딩, 새 데이터베이스, 전체 그래프 재구축, 여러 에이전트 분업, 무제한 탐색, 원격 서비스 전환. 현재 실패가 이 변경을 요구한다는 근거가 없다.

다음 Claude 지시서는 먼저 두 방법의 소규모 비교까지로 한정한다. 결과를 검토한 뒤 전체 근거 선택 경로 변경과 독립 평가를 지시한다.
