## 1. 질문의 목적과 범위는 근거 선택에 사용

공통 검색은 work/rule/table 세 종류를 모두 유지한다. 질문 분류로 특정 종류를 후보에서 미리 배제하지 않는다. 그 뒤 근거 선택 정책에서 목록, 특정 값·품, 규칙·조건, 여러 공종을 구별한다. 분류가 불분명하면 후보를 함께 제시하거나 확인 필요로 표시한다. 원문에 없는 공법·범위를 기본값으로 채우지 않는다.

첫 결과 1위가 틀린 개발 사례가 있으므로 ‘단일 견적은 첫 절만 읽기’를 채택하지 않는다. 질문의 대상·부문·공법·단위·조건과 후보 근거를 대조해 선택하며 선택 사유와 후보를 남긴다. 질문 ID나 정답 파일을 실행 코드에서 참조해 맞추지 않는다. 특정 실패 문장만 예외 처리하지 않는다.

## 2. 목록 질문은 범위를 정하고 공종 집합 확장

목록에 정답 절 9~10개가 있을 수 있다. ‘상위 5개를 전부 읽기’로 종료하면 부족하다. 검색 후보와 본문 절의 계층·목록을 사용해 질문 범위의 관련 공종을 넓게 모은다. 절·공법별로 중복을 정리하되 서로 다른 공종을 합치지 않는다.

공종 목록 확장과 자세한 표 조회를 구별한다. 각 공종은 적어도 제목·원문 출처·질문과의 관련 근거를 갖고, 필요할 때 표·설명을 조회한다. 전체 하위 절을 무조건 정답이라고 넣지 않는다. 범위가 넓거나 모호하면 그 한계와 누락 가능성을 표시한다. 결과 수·예산 때문에 목록을 중단하면 추가 조회 필요로 표시한다.

## 3. 특정 값·규칙 질문은 필요한 묶음을 선택

`evidence_sections=3`, `chunks_per_section=2`를 모든 질문의 완료 조건으로 쓰지 않는다. 자원 제한으로 둘 수는 있지만 그 제한으로 필요한 근거를 놓치면 추가 조회하거나 미완료로 표시해야 한다.

질문에 직접 답하는 표나 설명을 먼저 선택하고, 해당 표의 단위·기준·관련 조건·예외·명시적 참조와 칸 안 작은 표를 원문 식별자로 읽는다. 같은 절이라는 이유만으로 재료량 표를 투입 인력·장비 질문의 주 근거에 넣지 않는다. 조건 설명과 주석 표가 후보에만 있어도 필요한 연결 근거라면 점수와 무관하게 조회할 수 있게 한다.

한 절의 여러 표나 나뉜 표의 다른 부분이 필요한 경우 목적·행 조건·설명 연결을 확인해 확장한다. 내용이 달라지는 다른 표를 무조건 합치지 않는다. 필수 관계와 미확정 관계는 구별한다. 위치 근거 후보는 확인 문맥으로 표시하며 적용 확정으로 바꾸지 않는다.

N08처럼 556쪽 필요한 표와 설명이 후보 안에 있는데 제한으로 빠지는 사례를 해결한다. N09·N11처럼 관계는 있지만 질문에 불필요한 표는 주 근거에 섞지 않는다. 포함·제외 사유와 질문별 읽은 범위를 기록한다. 평가에서 금지한 ID를 하드코딩해 제외하지 않는다.

## 4. 근거 부족을 확인하고 최대 2회 추가 검색

실행 시에는 정답 파일이 없으므로 일반적인 부족 판단을 구현한다. 질문이 요구한 값·단위·공종 범위·조건이 실제 근거에 있는지, 미해결 참조·예산 제외·필요한 표 부분이 남았는지 확인한다. 검색 점수가 높거나 `coverage.complete=true`라는 이유만으로 충분하다고 판단하지 않는다. 적용·수식 해석이 불명확하면 보류 상태를 유지한다.

추가 검색은 부족한 항목에 맞춰 같은 절·표의 관련 조각, 상위 묶음의 하위 절, 동의어·공법 후보 등으로 범위를 정한다. 전체 후보 수 50개가 개발에서 악화됐으므로 단순히 전체 컷을 늘리는 것을 기본 해법으로 쓰지 않는다. 검색용 동의어는 원문 표기를 보존하고 일반 규칙·출처와 변환 기록을 남긴다.

추가 검색은 질문 전체에서 최대 2회다. 기존 상위 묶음 참조 검색도 이 횟수에 포함한다. 부족 사유·검색 문구·필터·반환 후보·추가된 근거·종료 이유를 기록한다. 해결되지 않으면 근거 부족·확인 필요를 반환한다. 다른 공종의 값을 대신 넣지 않는다. 여러 공종은 항목별 근거와 상태를 유지한다.

## 5. 근거를 못 찾은 질문 처리

검색은 문서에 답이 없어도 가까운 후보를 반환한다. 후보가 나온 것과 답할 근거가 있는 것을 구별한다. RRF 점수 하나를 그대로 답변 가능 확률로 쓰지 않는다.

개발 자료의 정답·자료 없음·애매한 질문으로 관련성과 근거 충분함을 구별하는 기준을 정한다. 빈 후보, 약한 관련성, 질문의 핵심 대상 불일치, 요청 값·조건 부재를 검사한다. 정답 질문을 잘못 거부한 건수도 함께 보고한다. 두 실패 질문의 특정 단어만 차단하지 않는다.

반환 상태는 최소한 근거 있음, 근거 부족·확인 필요, 관련 근거를 찾지 못함을 구별한다. ‘문서 전체에 없다’고 증명하지 못했다면 그렇게 단정하지 않는다. 엉뚱한 후보는 진단 정보로 보존할 수 있으나 정상 답변 근거로 내보내지 않는다.

## 재순위는 필요한 경우 별도 비교안

먼저 위 선택·추가 조회를 구현한다. 정답이 같은 후보 안에 있는데 순서가 계속 틀리는 실패가 남으면, 이미 조사한 재순위를 같은 후보에서 끈 상태와 비교할 수 있도록 비교 설계와 예상 비용을 보고한다. 이번에 별도 유료 재순위 모델·답변 모델을 호출하거나 새 계정을 만들지는 않는다. 후보 자체가 없는 오류를 재순위 문제로 바꾸지 않는다.

## 평가와 완료 판단

기존 두 질문 세트에서 수정 전후 후보 검색, 최종 공종 집합, 필수 근거, 금지 표, 거부와 추가 조회를 비교한다. 개발 실패를 해결하고 회귀를 확인한 뒤 코드·설정·새 질문·벡터 해시를 새 고정 기록으로 저장한다. 과거 `freeze_step04.json`과 결과는 보존한다. 이후 새 독립 20개는 한 번만 평가한다. 실패를 보고 고치면 개발 전환 사실과 추가 독립 평가 필요를 보고한다.

지표를 분리한다.

- 검색 순위 Recall@5: 원래 지표를 그대로 보고하되, 정답 하나 이상 찾기와 정답 집합의 비율을 구별한다.
- 목록: 요청 범위의 정답 공종 전체에 대한 회수율·불필요한 공종·집합 완료 질문 수. 정답이 5개보다 많은 질문은 최종 확장 목록도 별도로 평가한다.
- 근거: 필수 조각과 질문별 완료, 금지 조각 혼입, 단위·수치·조건 오류, 후보 선택과 조회 범위 실패를 분리한다.
- 자료 없음: 올바른 거부와 잘못된 답변 가능 표시, 정답 질문의 잘못된 거부를 집계한다.
- 기존 보류·수식·모호한 참조 상태 보존, API·검색·조회 지연과 추가 호출 비용, 최대 메모리.

초기 목표는 원문으로 확인 가능한 질문의 필수 근거 95% 이상, 중요 수치·조건 오류와 금지 주 근거 혼입 0이다. 불명확한 사례는 별도 집계하며 분모에서 몰래 빼지 않는다. 근거 조회기의 자기 완료 표시만으로 정답 평가를 대체하지 않는다. 목표 미달이면 남은 실패와 원인을 보고하며 서비스 연결은 시작하지 않는다. 끝없는 조정으로 평가를 통과시킨 것처럼 보고하지 않는다.
