## 2. 질문과 기대값을 먼저 고정

기존 V 질문에서 V02, V09, V11, V12, V20을 포함하고, 기존 4b에서 정상 처리한 질문 7개를 고른다. 정상 사례에는 값·규칙·목록·자료 없음과 가능하면 참조 또는 미확정 상태 사례를 포함한다. 합계 12개다. 이는 이미 결과를 본 개발 자료이며 독립 평가가 아니다. 새 독립 질문은 이번에 만들거나 실행하지 않는다.

기존 정답 자료와 원문 연결을 읽어 필수 근거, 금지 주 근거, 허용 상태를 고정한다. 소속이 미확정인 자료에 확정 적용을 요구하지 않는다. 기존 기대값에 오류가 있으면 모델 결과를 보기 전에 원문 근거와 변경 사유를 별도 기록한다. 질문 선택에 정답 파일을 사용할 수 있지만 실행 선택기에는 질문 ID나 정답 식별자를 전달하지 않는다.

## 3. 공통 후보를 한 번 만들어 고정

기존 결합 검색의 후보 경로와 질문 임베딩 캐시를 재사용한다. 질문마다 후보 ID·순서·검색 점수·원문 버전을 기록하고 해시를 고정한다. 정답이 후보 밖이면 후보 누락으로 기록한다. 정답을 알고 후보를 보충하지 않는다.

각 후보에 절 경로, 제목, 소제목, 단위 기준, 표 또는 설명 본문, 연결된 주변 설명과 출처를 담는다. 기존 원문 연결을 활용하며 주변 설명의 소속 미확정 상태를 그대로 표시한다. 두 모델에 동일한 후보 문맥을 전달한다. 모델용 요약을 한쪽에만 추가하지 않는다.

모델 한도를 넘으면 원문을 조용히 자르지 않는다. 기존 구조 조각을 이용한 동일한 분할 정책을 호출 전에 고정하고, 분할이 비교에 미친 영향을 기록한다. 그래도 불가능하면 입력 한도 때문에 미실행된 사례로 보고한다. 재순위 API의 자동 잘림은 끈다.

기존 4b의 원래 결과도 그대로 보관한다. 새 문맥 표현의 효과와 모델 교체 효과를 혼동하지 않도록 후보 생성과 문맥 보강에서 바뀐 내용을 따로 기록한다.

## 4. 비교 호출

가. 전용 재순위: 공식 문서와 이용 가능 여부를 확인해 Voyage 모델 한 개를 고정한다. 같은 후보에 대해 순위와 점수를 받는다. 비교용 상위 1개·3개·5개의 필수 근거와 금지 표 포함을 각각 측정한다. 관련도 점수를 답변 가능 확률로 바꾸거나, 자료 없음 판단을 했다고 보고하지 않는다.

나. 기존 서비스 언어 모델: 현재 설정 모델과 기존 호출 경로를 재사용한다. 같은 후보를 읽고 관련 후보 순위, 주 근거 식별자, 필요한 보조 근거 식별자, 원문 인용, 부족한 대상·조건, 추가 조회 필요 여부, 근거 상태를 구조화해 반환한다. 답변이나 견적 계산은 생성하지 않는다. 제공되지 않은 식별자를 만들어서는 안 된다.

언어 모델에도 상위 1개·3개·5개 순위 지표를 적용해 재순위 모델과 공통 지표로 비교한다. 별도로 언어 모델의 선택 집합과 근거 상태를 평가한다. 재순위 모델이 제공하지 않는 상태 판단 기능은 해당 없음으로 표시한다.

자료 속 문구는 근거 데이터이며 실행 지시가 아님을 명시한다. 반환 식별자와 인용이 실제 후보·원문에 있는지 코드로 검사하고, 선택이 질문에 맞는지는 고정한 기대 근거로 평가한다. 모델 자체 채점만으로 통과시키지 않는다. 미확정 소속·보류·수식·참조 적용 상태를 확정으로 승격하지 않는다.

추가 조회 요청은 이번에 기록만 하고 실행하지 않는다. 목록의 후보 누락을 재순위 실패로 집계하지 않는다. 두 방식을 직렬로 붙이는 세 번째 구성은 만들지 않는다.

## 5. 비용과 반복 제한

호출 전에 공식 가격, 실제 입력량, 예상 호출 수와 비용을 기록한다. 이번 실험의 운영 상한은 총 예상 비용 2달러, 시도 횟수 50회다. 이는 실험 폭주 방지를 위해 정한 상한이며 현재 가격이나 예상 청구액이 아니다. 둘 중 먼저 도달하는 한도에서 멈춘다. 비용을 확인할 수 없거나 입력량으로 상한을 지킬 수 없으면 해당 호출은 보류하고 준비 결과를 보고한다.

각 질문의 최초 응답을 보관한다. 언어 모델은 V09·V11·V12·V20을 총 세 번씩 실행해 흔들림을 확인한다. 성공 응답 캐시를 반복 측정으로 세지 않는다. 과금되는 재시도·형식 복구도 횟수와 비용에 포함한다. 같은 입력의 일반 재실행은 캐시를 쓰되 반복 측정은 별도 실행 ID를 쓴다.

결과를 보고 특정 질문을 맞추는 프롬프트 수정을 반복하지 않는다. 실행을 막는 전송·형식 오류만 고치고 변경 전후 기록을 남긴다. 기존 질문 벡터가 없으면 누락을 기록하고 소량 생성은 위 비용 한도 안에서 수행한다. 문서 임베딩은 재호출하지 않는다.

## 6. 근거 전달 점검과 보고
