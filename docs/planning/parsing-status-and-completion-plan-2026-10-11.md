# 파싱 개선 현황과 빠르게 마무리할 계획

작성일: 2026-10-11

## 지금의 위치

전체 데이터 흐름은 파싱 → 청킹 → 임베딩이다. 현재는 파싱을 개선하고 있다. 파싱 결과를 기존 청킹 함수에 넣는 제한된 연결 확인은 했지만, 청킹 설계 개선과 임베딩 갱신은 하지 않았다.

이 문서에서 파싱은 PDF의 글과 표를 가져오고, 원문 칸·기준·주석·소속·위치를 보존해 후속 단계의 입력으로 정리하는 일이다. 검색용 묶음을 어떻게 나눌지 결정하는 청킹과 구분한다. 참조 문장을 보존하는 일은 파싱에 속하지만 다른 절을 실제로 조회해 답변 근거로 조립하는 일은 후속 조회 단계의 책임이다.

현재까지는 파싱 안의 특정 오류 수정과 구조 보존 경로를 만들었다. 전체 품셈에 사용할 파싱 방식을 선택하고 적용한 상태는 아니다.

## 파싱 안의 단계별 현황

| 단계 | 하는 일 | 확인된 문제 | 지금까지 고친 것 | 남은 것 |
|---|---|---|---|---|
| 1. 글과 표 가져오기 | PDF의 글·표 칸·숫자·위치를 추출 | 표나 제목과 같은 글자 블록에 있는 `100㎡당` 같은 기준이 함께 삭제됨. ODL에서도 숫자 한 글자가 옆 칸으로 이동한 사례가 있음 | 별도 `parse.py`에서 줄별 제외와 반복 기준 보존을 적용. 지정된 실제 아홉 쪽에서 제한된 확인 | 전체 문서의 누락 규모와 추출 도구의 적용 범위 확인. 의심 숫자는 원문 그대로 보존하고 표시 |
| 2. 표의 행과 칸 정리 | 작업명·숫자·병합·공동 값의 관계 유지 | 줄바꿈된 작업명을 여러 작업으로 나눔. 공동 시공량을 독립된 값처럼 복사. 숫자 없는 표의 본문이 사라짐 | 555쪽 23건 → 원문 본문에 대응하는 13건. 185쪽 63/55를 원래 칸과 세 직종에 연결. 숫자 없는 표의 글을 보존하고 머리글 가정은 불확실로 표시 | 여러 줄로 쌓인 실제 행의 대응, 머리글 판정, 어댑터와 조립의 행 분리 역할 정리 |
| 3. 기준·주석·소속 연결 | 어느 표·절에 어떤 기준과 주석이 적용되는지 기록 | 같은 글을 제거하면 다른 표의 기준·주석까지 사라짐. 다음 쪽 주석과 소제목 기준의 연결 부족 | 807쪽 반복 기준과 주석을 각자 위치로 보존. 이미 확인한 같은 쪽 소속 후보와 확정 여부 전달 | 번호 없는 소제목 끝의 기준, 다음 쪽 주석, 이어지는 표, 앞 쪽 상위 절 제목 연결 |
| 4. 파싱 결과 저장과 전달 | 원문 보관 결과와 후속 입력을 연결 | 글 문자열만 남으면 원래 칸과 공동 관계를 잃음. 불확실성이 뒤에서 정상으로 바뀔 수 있음 | 보관 자료 → 레코드 → 변경 없는 청킹 함수 → 원문 연결 자료까지 재현. 불확실 상태 전달 | 생성 번호에 부문 정보 입력 반영. 운영 전 기존 ID와 새 결과 대응 계획 |
| 5. 전체 적용 확인 | 선택한 방식으로 문서 전체의 결과와 오류 규모 확인 | 현재 표본 결과만으로 전체 정확성을 알 수 없음 | 기존 ODL 12쪽의 32표로 제한된 보존·회귀 확인. PDF 원문 대조는 최신 작업에서 세 쪽 | 후보 채택 판단, 전체 별도 생성, 누락·보류·원문 추적 점검 |

## 무엇이 실제로 끝났는가

완료된 작은 작업:

1. `parse.py`의 기준 문구 누락 수정과 후속 머리글 조건문 제거.
2. 표의 원래 칸과 관계를 보관하고 후속 입력까지 전달하는 경로의 핵심 구현.
3. 위 경로에서 555쪽 가짜 작업 행, 185쪽 공동 시공량, 807쪽 반복 자료 보존의 제한된 확인.

첫 수정은 실제 아홉 쪽 및 확인 항목 99개 결과가 보고됐다. 두 번째 작업은 기존 ODL 12쪽 출력과 PDF 세 쪽 대조를 사용했고 확인 항목 89개 결과가 보고됐다. 두 수치를 합쳐 전체 파싱 정확도로 표현하지 않는다.

최신 결과의 표 청크 32개는 구조 문제 표시가 없는 14개, 불확실 표시가 있는 18개다. 14개가 계산 승인됐다는 뜻은 아니다. 18개에는 기존 행 대응 확인 필요 13개, 값 훼손 의심 표, 머리글 가정으로 새로 불확실 표시된 표가 포함된다. 현재 파싱이 아직 남은 작업을 가지고 있음을 보여 주는 자료이며 전체 문서의 보류율로 환산하지 않는다.

최신 구조 보존 작업의 핵심은 구현됐지만, 검토에서 생성 번호의 입력 누락을 확인했다. 보완 지시서는 이미 작성됐다. 현재 확인 가능한 결과 문서 목록에는 해당 보완의 결과 보고서가 없다. 따라서 보완 완료로 기록하지 않는다.

수정본은 모두 별도 작업 폴더에 있다. 운영 코드와 데이터·벡터는 갱신하지 않은 것으로 보고됐다.

## 빨리 마무리하기 위한 진행 방식

지금까지는 작은 오류 수정과 전달 확인을 여러 번 나눠 진행했다. 이후에는 이미 확인된 남은 문제를 목적별로 묶고, 완료 조건을 고정해 진행한다. 같은 사례를 계속 새 평가처럼 반복하지 않는다.

### 다음 구현은 남은 핵심 파싱 문제를 묶는다

두 가지를 하나의 목적 아래 정리한다. 목적은 “원문을 보존하면서 작업 행과 표 소속을 틀리게 확정하지 않기”다.

- 표 내부: 실제 하위 행과 작업명 줄바꿈 구별, 머리글 판정, 행 분리의 책임과 근거 정리.
- 표 주변: 앞 쪽 절 제목, 소제목 기준, 다음 쪽 주석, 이어지는 표 연결.

한 번에 모든 표의 뜻을 확정하려 하지 않는다. 일반 규칙으로 판정할 수 있는 범위와 보류할 범위를 정한다. 쪽이나 공종마다 손으로 예외를 추가하지 않는다. 모르는 자료를 정상으로 표시하는 방식으로 속도를 높이지 않는다.

이 범위는 아직 구현 지시가 승인된 것이 아니다. 실제 다음 지시서를 만들 때 수정 파일, 사용할 연속 구간, 필요한 새 오프라인 추출의 범위와 출력, 완료 기준을 정해 사용자에게 보고한다. 이미 발행한 생성 번호 보완은 중복 지시하지 않는다.

### 확인은 한 번의 묶음으로 한다

코드가 바뀐 부분에 필요한 기능 확인, 기존 32표의 회귀 비교, 결과를 보기 전에 고른 소규모 미사용 표본의 원문 대조를 한 결과 보고로 제출한다. 각각의 목적과 표본 성격을 구분한다.

성공한 기존 확인을 이유 없이 다시 반복하지 않는다. 새 실패가 다음 결정에 영향을 주는지 판단한다. 일반 규칙으로 해결하지 못한 개별 표는 보류 목록에 남긴다. 보류가 목표 서비스 범위를 지나치게 줄인다면 후보 채택 판단에서 문제로 다룬다.

### 그 결과로 방식을 결정하고 전체 결과를 한 번 만든다

표본 비교 뒤 사용할 추출 방식과 보관·후처리 조합을 선택한다. 전체 문서는 원본 데이터를 보존한 별도 출력으로 생성한다. 전체 처리와 위험 자료 확인을 작은 추가 검사로 끝없이 나누지 않고 한 계획과 보고로 묶는다.

전체 생성에는 아직 별도 사용자 지시가 필요하다. 실행 전 처리 범위·출력 위치·시간과 저장 공간·재개·실패 처리·비교 기준을 제시한다. 현재의 전체 재처리 금지 조건을 이 보고만으로 해제하지 않는다.

## 이번 파싱 작업에 넣지 않을 일

- 검색 순위·부모 문맥·참조 대상 조회의 개선
- 청크 크기나 분할 방식의 최적화
- 임베딩 모델 선택과 재임베딩
- 계산 명세의 의미 검증, 질문 정책, 다공종 대화, 단가, Excel
- 모든 보류 표의 실무 해석을 수작업으로 확정하는 일

필요한 원문과 불확실 상태는 파싱 결과에 남기고, 후속 단계의 책임을 파싱 완료 조건에 섞지 않는다.

## 파싱 완료라고 말할 기준

1. 사용할 추출·보관·후처리 방식을 선택했다.
2. 확인된 주요 오류 유형의 처리 규칙과 보류 규칙이 있다.
3. 전체 문서를 처리한 별도 결과에서 누락·오류·보류 범위를 보고할 수 있다.
4. 숫자·기준·주석이 원문까지 추적되고, 불확실한 자료가 정상으로 전달되지 않는다.
5. 확인한 범위와 확인하지 않은 범위가 분명하며 후속 단계에서 사용할 수 있는 범위를 설명할 수 있다.

모든 표의 계산 명세가 승인돼야 파싱을 끝내는 것은 아니다. 전체 처리 성공만으로 원문 정확성이나 계산 정확성이 보장되는 것도 아니다.

## 작성 근거

인계 문서, 승인한 첫 작업 지시서, 최신 구조 보존 결과와 검토 문서, 해당 코드에 대한 앞선 읽기 전용 검토를 종합했다. 2026-10-11에는 관련 결과 문서 이름을 확인했으며 새 구현·파싱·검사를 실행하지 않았다.
