## 1. 현재 실행 경로 고정

현재 코드·모델·프롬프트·스키마·설정·자료 버전의 해시와 변경 목록을 보관한다. 원문 릴리스 `rk-complete-82c206c61e21-37f81b5cfb1b`, 청킹 묶음 `cs-37f81b5cfb1b-46f4f035c0fa`, 완료 문서 벡터를 사용한다.

파싱·청킹·문서 벡터·DB 자료·운영 코드는 유지한다. 과거 질문·기대값·결과·캐시·원장을 덮어쓰지 않는다. 새 평가 실행기와 집계 코드는 `experiments/retrieval-v1/pilots/step04g/`에 작성할 수 있다. 검색·선택·검증 로직은 수정하지 않는다. 형식이나 실행기 문제를 고친 경우 기록하고, 의미 결과가 달라지는 변경이 필요하면 이번 평가를 중단해 보고한다.

## 2. 새 질문 20개와 원문 기대값

현재 60문이나 개발 질문의 단순 말바꾸기만으로 새 자료를 만들지 않는다. 다른 절·표·배치와 다른 조건의 실제 질문을 포함한다. 질문 구성은 아래와 같다.

- 값·품·단일 작업 6개: 단위 기준, 비슷한 표 구별, 활용형·구어체를 포함.
- 규칙·참조·조건 4개: 부정·제외 조건, 다른 절 참조, 소속 또는 수식 미확정인 경우를 포함.
- 공종 목록 4개: 목록 범위가 명확한 경우와 넓거나 모호한 경우를 포함.
- 현재 자료로 답할 근거가 없는 질문 4개: 새 대상, 같은 대상의 다른 작업, 같은 주제의 다른 공법을 포함.
- 번호·범위 모호 질문 2개: 번호+일반 표현, 여러 번호 등을 포함. 부문 명시 대조는 반복 평가가 아닌 별도 개발 점검으로 추가하지 않는다.

유형 수는 합계 20개이며 위험 특성은 겹칠 수 있다. 정답 여부가 모호한 질문을 억지로 자료 없음 질문으로 분류하지 않는다. 자료 없음은 읽은 범위와 검색 점검 근거를 적고 문서 전체 부재가 증명됐다고 하지 않는다.

기대값은 원문 DB와 필요한 실제 PDF 표·설명을 읽어 정한다. 절 제목만 보고 만들지 않는다. 정답 파일에는 필수 원문 조각·줄 또는 칸 위치·단위·조건·관련 참조 상태·금지 근거·허용 상태를 기록한다. 목록은 필요한 공종과 허용 가능한 추가 항목 및 범위를 적는다. 모호한 질문은 부문 대안과 선택 필요를 기대한다. 미확정 자료는 적용 확정 대신 올바른 보류와 필요한 문맥을 기대한다.

정답 준비에는 원문 조회를 사용할 수 있지만 새 질문으로 검색·선택 경로를 미리 실행하지 않는다. 평가 실행 전에 질문과 기대값, 근거 확인 기록의 해시를 고정한다. 실행 경로에는 질문 글만 전달하며 정답 파일과 질문 ID에 따른 선택 규칙을 전달하지 않는다.

## 3. F03의 기존 기대값 오류 기록

기존 F03은 원문을 다시 읽어 기대값 오류와 불필요 보류를 별도로 기록한다. 최초 기대·최초 실패 결과는 보존하고 정정 근거를 새 문서에 남긴다. 정정은 현재 검색 결과에 맞추는 것이 아니라 원문 내용에 근거해야 한다.

F03은 이미 결과를 본 개발 자료이므로 새 독립 질문 20개에 넣거나 독립 성공으로 세지 않는다. 이번에는 F03을 해결하는 코드 수정도 하지 않는다.

## 4. 현재 경로 전체 실행

새 질문에서 기존 결합 검색 → 현재 선택기 → 원문·참조 조회 → 최종 문맥과 상태까지 실제 경로를 실행한다. 4d·4e 응답 재생으로 새 질문의 모델 선택을 대신하지 않는다. 문서 임베딩은 재호출하지 않고 필요한 새 질문 벡터만 기존 모델로 생성한다.

후보 검색, 모델 선택, 코드 검증, 최종 문맥의 누락·혼입을 구분한다. 실제 원문 조건을 읽지 못했는데 식별자가 존재한다는 이유만으로 통과시키지 않는다. 자료 없음 결과가 `not_found`여도 관련 없는 정상·확인용 문맥이 남아 있는지 확인한다.

첫 실행 결과를 전부 저장한다. 결과를 본 뒤 프롬프트·임계값·모델·기대값을 조정하지 않는다. 기대값 오류가 실행 뒤 발견되면 원래 점수와 원문 정정에 따른 점수를 구분해 기록하고 새 독립 성공이라고 포장하지 않는다.

질문 고정 시 위험 사례 4개를 지정하고 각각 총 세 번 실행해 선택·상태·문맥 변동을 확인한다. 자료 없음, 같은 대상 다른 작업, 부정 조건, 미확정 자료를 우선 포함한다. 결과를 보고 반복 질문을 바꾸거나 좋은 응답만 골라 대표값으로 쓰지 않는다. 같은 성공 응답 캐시는 일반 재실행에만 쓰고 반복 측정은 별도 실행 ID를 사용한다.

## 5. 호출 상한

새 유료 호출의 운영 상한은 전체 시도 **80회·예상 비용 2달러**다. 모델·질문 벡터·추가 조회의 모델 호출·재시도·형식 복구를 포함하며 먼저 도달하면 멈춘다. 시작 전 실제 호출 경로의 공식 가격과 예상 입력량으로 비용을 기록한다. 단가 미확인이면 추정 한계와 보수적인 상한을 명시한다.

반복·추가 조회를 포함해 상한 안에 계획한다. 비용을 줄이려고 필요한 근거를 조용히 자르거나 반복 대신 캐시를 성공 실행으로 세지 않는다. 상한 또는 실행 장애 때문에 미실행된 질문은 분모와 별도로 명시한다. 다른 작업의 세션·프로세스를 종료하지 않는다.

## 6. 판단과 보고

최종 전달 문맥의 필수 근거 포함률 95% 이상, 중요한 잘못된 표·수치·조건의 정상 전달 0, 금지 주·문맥 혼입 0을 기존 목표로 유지한다. 목표를 평가 결과 뒤에 바꾸지 않는다. 자료 없음 4문, 정상 질문 거부, 필요한 보류 유지, 목록 누락·불필요 항목·완전성도 각각 보고한다. 목록이나 구형 집합 질문을 조각 지표에서 빼서 전체 성공이라고 하지 않는다.

확정 선택, 확인용 선택·문맥, 구조 조회 도달을 구분한다. 미확정 사례는 원문에 필요한 설명을 보여주고 올바르게 보류했는지를 평가한다. 근거 있음은 계산 적용 승인이 아니다. 모델 자기 채점만으로 의미 정확성을 평가하지 않는다.

반복 실행의 실패도 보고한다. 작은 20문 평가의 비율을 전체 문서 또는 전체 사용자 질문의 정확도라고 표현하지 않는다. 이미 알려진 목록 과다 포함, 부정 과다 보류, 부재 대상 탐지 누락 등 한계가 사라졌다고 하지 않는다.

결과를 다음 중 하나로 추천한다.

- 로컬 서비스의 제한된 시험 연결 준비: 해당 범위의 근거·상태 처리가 목표에 맞고 반복에서 중요한 오류가 없음. 계산·운영·배포 승인이 아님.
- 일부 유형만 시험 가능: 지원 가능한 질문과 제외·확인 필요한 유형을 근거와 함께 명시.
- 시험 연결 전 보완 필요: 중요한 잘못된 근거·거부·범위 선택 오류의 원인을 후보 검색/선택/검증/조회로 구분.

완료된 유형과 실패 유형을 설명하고 새 수정 작업은 시작하지 않는다. 이전 질문을 추가 실행해 새 독립 실패를 상쇄하지 않는다.
