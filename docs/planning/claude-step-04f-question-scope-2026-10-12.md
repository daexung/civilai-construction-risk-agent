## 1. 질문에서 대상과 요청 표현을 구분

`absent_terms`가 뽑은 원문 부재 낱말을 모두 대상이라고 보는 것이 핵심 결함이다. 예외 어미를 계속 붙이는 방식으로만 해결하지 않는다.

질문 표현을 다음 역할로 구분해 기록한다.

- 대상: 공종·재료·시설·공법 등 실제로 근거가 맞아야 하는 대상.
- 작업·조건: 절단 등 요청한 작업, 단위·수량·조건. 원문 표현과 의미상 대응 여부를 확인한다.
- 요청 표현: 하려는데, 알려줘 등 질문 의도를 전달하는 표현. 이것이 원문에 없다는 이유로 근거를 보류하지 않는다.
- 부문·절 번호: 검색 범위를 구별하는 정보.

예를 들어 ‘절단하려는데’의 요청 표현은 근거 부재가 아니지만 작업 의미인 ‘절단’은 유지한다. 활용형 전체를 지워 중요한 작업·부정·조건을 잃지 않는다. ‘방법별로’의 ‘별로’를 제거하더라도 목록·비교 요청 자체는 유지한다.

우선 기존 질문·선택 응답·원문 위치에서 역할을 확인한다. 기존 규칙으로 분명한 표현은 코드에서 처리한다. 대상 의미가 모호한 경우에만 기존 서비스 모델로 작은 별도 대상 대조를 수행할 수 있다. 전체 60문 선택 프롬프트와 스키마는 바꾸지 않는다. 판정 필드는 대상 원문 구간, 역할, 비교한 원문 위치, 동일/다름/판단 불가와 이유를 갖는다. 반환 위치와 원문은 코드로 검사한다. 모델 판정 자체가 진실 보장이라는 식으로 보고하지 않는다.

V13·V18의 불필요 보류를 해제하고 V04가 요청 표현 때문에 근거 역할이 내려가지 않게 한다. 기존 소속·수식·참조·목록 불완전 때문에 필요한 보류는 유지한다. 새로운 개발 대조 사례에는 다른 활용형, 대상과 작업이 다른 비슷한 질문, 부정 또는 조건이 있는 질문을 포함한다. 결과를 보기 전에 원문 기준 기대 행동을 기록한다.

## 2. 대상이 다른 자료와 판단이 안 되는 자료 구분

N19에서 BIM 요청에 3차원 건물데이터 제작 표가 선택되었다. 같은 주제라는 이유로 요청한 대상·작업의 근거가 되지는 않는다. 기존 자료와 원문으로 대상·요청 작업이 직접 뒷받침되는지 대조한다.

- 같은 대상과 요청 작업을 뒷받침하면 기존 상태 검증으로 진행한다.
- 실제로 다른 대상·작업이거나 요청 내용을 뒷받침하지 않는 경우 해당 자료를 주·보조·확인용 답변 문맥에서 제외하고 진단 후보로만 보관한다.
- 관련성이 있고 동일성·조건을 확인하지 못하면 확인 필요와 구체적인 부족 조건을 남긴다.

정상 답변 근거가 없으면 `not_found`는 현재 읽은 범위에서 관련 근거를 찾지 못했다는 의미로 반환한다. 낱말 부재만으로 이렇게 결정하지 않는다. N19를 맞히기 위해 BIM을 차단하거나 특정 표를 제외하는 규칙을 넣지 않는다. 반대로 모든 자료 없음 질문을 확인 필요로 바꿔 정상 처리를 주장하지 않는다.

N19, 기존 자료 없음 5문, 기존 동의어·구어체 정상 사례를 대조한다. 정상 질문을 자료 없음으로 오판하는지도 집계한다. 실제로 판단이 안 되는 사례를 억지로 거부하지 말고 잔여 문제로 보고한다.

## 3. 절 번호는 요청 표현이 있어도 부문을 확정하지 않음

번호가 있으면 먼저 기존 절 색인에서 같은 번호의 본문 절 후보를 조회한다. 내용어가 하나도 없을 때만 번호 조회를 하는 현재 조건을 보완한다.

부문 또는 구별되는 제목·대상이 후보를 특정하는지 확인한다. ‘몇 인’, ‘일당’, ‘시공량’, ‘기준’은 요청하는 정보이며 그 자체로 부문 선택 근거가 아니다. 서로 다른 부문 절이 남으면 대안과 부문 선택 필요를 반환한다. 검색 순위나 모델 선호 한 개만으로 확정하지 않는다. 질문 글에서 부문이 명확하면 적용하며, 이 실험에 없는 대화 이력을 읽었다고 가정하지 않는다.

여러 번호가 주어지면 각각 후보를 조회해 모호성을 유지한다. 번호 형식을 일반적으로 처리하고 특정 번호를 실행 코드에 넣지 않는다. 후보가 하나이거나 유효한 구별 정보가 있으면 정상 실행 경로로 이어간다. 제목 의미가 애매하면 후보를 남기고 확인 필요로 표시한다.

기존 Q13, 번호에 일반 표현이 붙은 질문, 여러 번호, 부문 명시, 구별되는 제목을 명시한 질문을 확인한다. 구조 조회로 충분하면 모델 호출을 하지 않는다.

## 4. 실행 순서와 상한

1. 4e 저장 응답으로 활용형·번호 경로를 고치고 필요한 가상 입력을 확인한다. N08·V12의 상태와 근거 전달이 유지되는지 점검한다.
2. N19 대상 대조와 일반화 대조 사례 중 새 응답이 필요한 것만 소량 호출한다. 사례별 최초 결과를 보관한다. 실패 때문에 전체 프롬프트를 계속 바꾸지 않는다.
3. 수정·설정을 고정한 뒤 기존 60문을 마지막으로 한 번 재생·평가한다. 입력이 같은 응답만 캐시로 재사용하고, 추가 대상 대조의 실행 여부와 새 결과를 구분한다.
4. 최종 확인에서 실패가 남으면 보고하고 종료한다. 전체 60문 모델 재호출과 독립 평가를 시작하지 않는다.

새 유료 호출은 총 **20회·예상 비용 1달러**를 상한으로 한다. 모델·질문 벡터·재시도·형식 복구를 모두 센다. 공식 가격을 확인할 수 없으면 비용은 추정임을 밝히고 보수적으로 상한을 지킨다. 같은 성공 입력은 캐시를 활용한다. 과거 원장·캐시는 보존하고 이번 기록을 분리한다. 불변 자료의 재생 동등성을 실제 입력 해시로 확인한다.

새 개발 사례는 현재까지 결과를 본 자료와 함께 개발·회귀로 표시한다. 독립 질문으로 이름만 바꾸지 않는다. 처리 시간도 기록하되 무관한 대규모 성능 검사를 하지 않는다.

## 5. 완료와 보고

확인용 문맥, 검증된 주·보조 선택, 계산 적용 여부를 구별한다. N08은 자료를 읽을 수 있어도 수식이 확정된 것이 아니다. 이 관계를 바꾸거나 확인용을 확정으로 세지 않는다.
