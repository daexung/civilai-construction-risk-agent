# 품셈 원문 데이터의 구조 개선 계획

작성일: 2026-10-10

상태: Codex의 기획안. 구현, 검사, 전체 재처리, 운영 전환을 실행한 문서가 아니다.

## 1. 이번 계획의 목적

대목표는 한국 건설 표준품셈 전체로 확장할 수 있는 근거 있는 품·다공종 견적 서비스와 실무용 Excel이다.

지금 할 중목표는 원문에서 가져온 숫자·단위·산출 기준·작업 조건·주석의 관계를 보존하는 데이터 생성 경로를 만드는 것이다. 그 결과를 검색과 계산 지식 생성의 바탕으로 사용한다.

파싱은 다음 세 책임으로 나눠 개선한다.

1. 추출: PDF에서 표의 칸과 글, 위치를 가져온다.
2. 보관과 해석: 원래 칸을 보존하고, 병합·행 대응·기준·주석의 연결을 별도로 기록한다.
3. 전달: 보관된 자료에서 검색용 글과 기존 청킹 입력을 만든다.

ODL 채택만으로 세 책임이 모두 해결되지는 않는다. 이번 계획에서는 원문 구조 보관을 중심으로 뒤의 변환이 정보를 잃지 않게 만든다.

## 2. 이미 끝난 일과 재사용할 자산

| 자산 | 이번 계획에서의 사용 |
|---|---|
| 별도 작업 폴더의 산출 기준 누락 수정과 머리글 두 줄 제거 | 완료된 국소 수정으로 유지한다. 최초 구현을 다시 지시하지 않는다. 실제 아홉 쪽과 확인 항목 99개 결과는 그 범위의 근거로 사용한다 |
| 기존 ODL 12쪽 출력 | 첫 구현의 입력으로 재사용한다. 시작부터 새 추출을 실행하지 않는다 |
| 원문 구조 보관과 근거 조립 시제품 | 칸·병합·공동 값·원문 위치·상태 보관 방식을 재사용한다. 같은 시제품을 처음부터 다시 만들지 않는다 |
| 실제 공통부문 6-1-3 참조 조회 | 문서·부문·번호·제목을 함께 확인하고, 발견·확보·전달 상태를 나누는 설계를 재사용한다 |
| 기존 코드와 계산·상태·검색 | 비교 기준과 연결 대상으로 남긴다. 데이터 개선만으로 전체 서비스를 교체하지 않는다 |
| 기존 개발 사례와 별도 확인 다섯 표 | 확인된 오류와 회귀 확인에 쓴다. 다시 실행해도 새 평가 표본이라고 보고하지 않는다 |

최신 패치는 별도 작업 폴더에 있고, 원본 저장소의 데이터·벡터·운영에는 반영되지 않았다. 이 문서에서는 외부 작업 폴더의 현재 파일을 다시 확인하지 않았으며 최신 보고와 인계 문서를 근거로 삼았다.

## 3. 근거가 있는 문제와 대응

| 문제 | 확인된 사례 또는 코드 | 해결 방향 |
|---|---|---|
| 기준 문구 제거 | 186·195·645쪽. 최근 국소 수정으로 제한된 범위에서 해결 | 해당 수정은 유지하고 후속 변환이 기준을 다시 잃지 않게 한다 |
| 칸 안 줄바꿈을 여러 작업 행으로 오인 | 555쪽에서 원문 본문 13행이 조립 후 23개 레코드로 늘어남 | 원래 칸과 행을 먼저 보존한다. 하위 행 분리는 별도 해석이며 판정 근거를 남긴다 |
| 공동 시공량이 독립 숫자로 복사됨 | 185쪽의 63/55가 세 직종에 반복 표시됨 | 원래 칸 하나와 적용 행을 연결한다. 검색에서 반복해도 같은 칸을 가리키게 한다 |
| 같은 글을 지우면서 소속까지 사라짐 | ODL 시제품 보고에서 기준 두 건·주석 세 건의 손실 재현. 기준 코드의 조립 단계에 글 내용만으로 중복 제거하는 경로가 있음 | 원문 위치가 다르면 각각 보관한다. 화면이나 검색에서 반복을 줄여도 원문 연결은 모두 남긴다 |
| 추출한 기준이 표에 연결되지 않음 | 679쪽 번호 없는 소제목 끝의 기준은 기존 청킹이 연결하지 못한 것으로 보고됨 | 글을 인식하는 일과 표에 소속시키는 일을 분리한다. 근거가 부족하면 후보로 남긴다 |
| 숫자 글자가 옆 칸으로 이동 | 555쪽의 `영상지도 편집1`과 `.00` | 자동으로 1.00으로 고치지 않는다. 값 훼손 의심과 원문 위치를 남기고 계산 사용을 막는다 |
| 쪽 경계의 절·표·주석 연결 부족 | 앞 쪽의 절 제목, 다음 쪽 주석, 이어지는 표의 연결이 시제품에서 불완전 | 인접 쪽을 포함한 연속 구간에서 소속과 이어짐을 확인하고 연결 근거를 남긴다 |
| 재생성 때 ID와 참조가 어긋남 | 추가 기준 때문에 줄글 청크 순번이 이동한 보고 | 생성 버전과 원문 위치를 분리하고 이전 결과와의 대응을 기록한다 |

기준 코드 `baf186f`의 `assemble.py`는 ODL 공통 표를 글 레코드로 만들며, 해당 레코드에는 원문 칸 식별자와 적용 범위가 남지 않는 경로가 있다. `chunk.py`는 표 식별자·원문 좌표·구조 상태·레코드 번호 등을 요구한다. 따라서 ODL 출력에 기존 조립을 그대로 붙이는 것만으로 운영 청킹과의 연결이 끝나지는 않는다.

## 4. 채택할 설계 방향

### 4.1 원문에서 가져온 자료와 해석 결과를 나눠 보관한다

PDF가 최종 원문이다. 추출 도구의 출력은 PDF에서 가져온 결과이며 틀릴 수 있다.

원문 PDF와 추출 도구의 원시 출력을 보존하고, 다음 해석 결과를 별도로 저장한다. 기존 파일 형식으로 시작할 수 있으며 새 데이터베이스 도입을 선행 조건으로 삼지 않는다.

| 대상 | 최소 보관 정보 |
|---|---|
| 문서와 생성 기록 | 문서 이름·연도·원본 해시·추출 도구와 버전·변환 코드 기준·처리 범위·생성 버전 |
| 절과 소제목 | 부문·절 번호·제목·상위 소속·원문 위치·소속 판정 근거 |
| 표와 칸 | 식별자·쪽·좌표·원래 행과 열·병합 범위·줄바꿈을 포함한 원래 글·안쪽 작은 표 연결 |
| 정리한 값 | 표시용 글과 숫자 해석 후보·단위·원문 칸 연결·변환 내역 |
| 작업 묶음과 공동 값 | 적용 행·원문 칸 연결·묶음 판정 근거·확정 여부 |
| 산출 기준 | `100㎡당` 등의 원문·위치·대상 표 후보·연결 근거와 상태 |
| 주석과 참조 | 원문·위치·소속 후보·적용 조건 원문·대상 문서와 부문·절·연결 상태 |
| 문제와 사용 상태 | 추출 이상 사유·행 대응 상태·필수 근거 확보 상태·원문 대조 기록 |

표의 빈칸, `-`, `〃`, 숫자 0은 같은 값으로 바꾸지 않는다. 정리한 값이 있어도 원래 표기는 남긴다. 서로 다른 표에 같은 문장이 나오면 각각의 원문 위치를 유지한다.

### 4.2 행 분리를 한 번의 명시적인 변환으로 관리한다

현재 후보 경로에는 ODL 어댑터의 행 분리와 조립 단계의 추가 행 분리가 있다. 어느 단계에서 어떤 행이 나뉘었는지 추적하고, 판정이 끝난 행을 뒤 단계가 다시 추측해 나누지 않게 한다.

- 원문 칸의 줄바꿈은 기본적으로 그대로 보존한다.
- 줄 수가 같다는 이유만으로 행 분리를 확정하지 않는다.
- 표 격자·병합·열 역할·실제 위치 등 여러 근거로 행 대응을 판정한다.
- 문단 높이를 줄 수로 나눈 위치는 추정 좌표로 표시한다. 실제 글자 좌표와 같은 증거로 취급하지 않는다.
- 하위 행을 만들면 각 조각이 원래 어떤 칸과 글 범위에서 왔는지 남긴다.
- 숫자·라벨을 누락하거나 복사해서 대응을 맞추지 않는다. 결정할 수 없으면 원래 칸과 대응 후보를 함께 남긴다.

555쪽의 잘못된 행 분리를 막는 것과, 아직 보류 중인 다른 표의 행 대응을 확정하는 것은 서로 다른 완료 항목이다. 행 분리를 줄였다는 이유로 모든 표가 해석됐다고 보고하지 않는다.

### 4.3 기준·주석·참조는 대상과 판정 근거를 함께 남긴다

연결에는 최소한 다음 상태를 구분한다.

- 원문에 대상을 직접 적은 연결
- 표 내부 구조로 확인한 연결
- 위치나 제목 흐름으로 정한 후보
- 대상이 여러 개이거나 확보되지 않은 상태

가까운 표라는 이유만으로 모든 주석을 확정 연결하지 않는다. 상위 절의 일반 규정과 표 아래 주석을 구분하고, 다음 제목을 넘어 무조건 이어 붙이지 않는다.

소제목 끝의 기준도 원문 위치와 대상 후보를 보관한다. 다음 쪽의 주석과 이어지는 표는 연속 쪽의 제목·열 구성·이어짐 표시를 함께 보고 연결한다. 부문과 절 정보가 없으면 단어 반복만으로 다른 공종에 연결하지 않는다.

참조는 기존 시제품의 문서·부문·번호·제목 확인 방식을 유지한다. 대상 내용을 가져오는 것과 그 비용을 견적에 더하는 것은 별도 책임이다.

### 4.4 검색용 글은 보관 결과에서 만든다

공종 목록, 규칙 설명, 표와 작업 조건용 글은 같은 보관 결과에서 생성한다. 각 글은 원문 표·칸·주석으로 돌아갈 수 있어야 한다.

검색용 글에 63/55를 여러 행에 반복해도 원문 칸은 각각 하나로 유지한다. 공동 값이라는 관계를 숫자 복사로 대신하지 않는다. 작업 묶음의 이름도 포함된 모든 작업을 반영해야 한다.

이 단계에서는 검색 입력과 근거 연결이 보존되는지를 확인한다. 세 종류의 별도 색인이 검색 순위를 개선했다는 주장은 하지 않는다. 순위 비교와 후보 결합은 다음 중목표에서 다룬다.

### 4.5 구조 상태와 계산 사용 가능 여부를 분리한다

상태는 한 개의 통과 표시로 합치지 않는다.

| 상태 | 답하려는 질문 |
|---|---|
| 추출 상태 | 원문 글과 숫자를 잃거나 잘못 가져왔는가 |
| 행·열 대응 상태 | 어느 숫자가 어느 작업과 조건에 해당하는가 |
| 근거 연결 상태 | 기준·필수 주석·필요한 참조가 확보되고 연결됐는가 |
| 계산 지식 상태 | 단위·산식·조건·대표 계산이 별도로 검증됐는가 |

첫 세 상태가 양호해도 계산 지식이 승인된 것은 아니다. 반대로 일부가 불확실해도 정확한 원문과 불확실한 부분을 표시하며 읽기·설명에 사용할 수 있다. 훼손된 부분을 확정 사실처럼 설명하지 않는다.

초기에는 기존 원칙대로 표에 값 훼손이나 행 대응 문제가 있으면 표 전체의 자동 계산 사용을 보류한다. 부분 사용을 허용하려면 영향 범위를 별도로 입증해야 하며 이번 첫 작업에 넣지 않는다.

### 4.6 추출 도구 선택과 구조 보관 선택을 나눈다

구조를 보존하는 방향은 지금 채택할 기획 방향이다. ODL은 유력한 추출 후보로 두되 운영 채택은 비교 결과 뒤에 결정한다.

기존 방식과 ODL 후보가 같은 보관 형식으로 결과를 내도록 맞춘다. 기존 격자에서 원래 병합 범위 등을 확보하지 못하면 모르는 정보로 표시한다. 존재하지 않는 칸 관계를 복원한 것처럼 쓰지 않는다.

처음부터 공종별로 다른 파서를 선택하는 규칙을 수작업으로 만들지 않는다. 후보가 특정 표에서 실패하면 보류하거나 제한된 대체 경로를 검토하고, 다른 후보의 숫자로 조용히 덮어쓰지 않는다.

## 5. 실행 순서와 각 작업의 완료 기준

각 단계는 별도 지시서와 결과 검토로 진행한다. 다음 단계는 이전 결과를 검토한 뒤 구체화한다.

### 작업 1. 기존 시제품에서 보관 결과와 청킹 입력을 연결한다

**목적:** 원문 칸을 보존한 결과를 실제 후속 단계가 받아들일 수 있는 최소 경로를 만든다.

기존 시제품의 보관 구조를 재사용하고, 기존 ODL 출력의 185·555·807쪽으로 진행한다. 이는 개발·회귀 자료이며 새 평가가 아니다. 현재 기준 누락 패치는 별도 완료 작업으로 유지한다.

산출물:

- 보관 형식과 기존 형식의 대응 설명
- 칸·주석·관계를 포함한 보관 결과
- 기존 청킹이 요구하는 필드를 가진 변환 출력과 원문 연결 정보
- 입력 버전·변환 버전·변환 손실 및 보류 사유를 담은 생성 기록
- 원문 → 보관 결과 → 청킹 입력을 나란히 보여 주는 결과 보고

완료 기준:

1. 원래 칸의 글·병합·위치가 남고, 전달된 값에서 해당 칸으로 돌아갈 수 있다.
2. 185쪽의 63/55는 각각 원래 한 칸이며 세 직종과의 관계가 유지된다.
3. 555쪽의 단순 줄바꿈이 가짜 작업 행으로 늘어나지 않는다. `.00` 등 값 훼손 의심은 고치지 않고 보류 상태로 전달된다.
4. 807쪽처럼 글자가 같은 기준과 주석도 위치와 소속이 다른 원문 항목으로 남는다.
5. 기존 청킹에서 표현할 수 없는 관계는 별도 연결 정보로 유지한다. 단순 글 레코드가 유일한 보관 원본이 되지 않는다.
6. 변환이 구조의 불확실성을 정상 상태로 바꾸지 않는다. 청킹의 `ok`도 계산 승인으로 해석하지 않는다.

이 작업에서는 나머지 표의 모든 행 대응이나 쪽 경계를 동시에 해결하지 않는다. 새 표 추출·전체 데이터 생성·검색 평가·계산 명세 생성도 포함하지 않는다.

### 작업 2. 아직 보류된 행·열 대응을 해결한다

**목적:** 여러 줄로 쌓인 실제 작업 행과 한 작업명의 줄바꿈을 일반 규칙으로 구분한다.

기존 보고에서 확인 필요로 남은 13표를 오류 형태별로 나눈다. 이미 만들어진 분류와 후보를 재사용하고, 필요한 경우 PDF의 글자 위치를 읽어 보강한다. 쪽 번호나 특정 공종 이름에만 맞춘 예외를 만들지 않는다.

산출물은 행 분리·보존의 판정 규칙, 원문 대응, 적용되는 표와 남는 보류 표의 목록이다. 193쪽처럼 일부 유형 칸의 줄 수가 다른 경우도 정보가 빠진 채 정상으로 표시되지 않아야 한다.

완료 기준은 모든 표의 승인 수가 아니라, 결정 가능한 범위와 결정 불가능한 범위를 설명하는 것이다. 판정 규칙을 고정한 뒤 새로운 표본을 확인하는 절차는 작업 4에서 한 번 묶어 진행한다.

### 작업 3. 기준·주석·절과 쪽 경계의 연결을 완성한다

**목적:** 같은 쪽과 인접 쪽의 문맥을 잃지 않고 필요한 근거를 표에 연결한다.

우선 사례는 679~680쪽의 소제목 기준, 185~187쪽의 다음 쪽 주석, 기존 출력에 있는 이어지는 표 사례다. 기존 개발 결과를 재사용하고 실제 원문 대응이 부족한 부분만 확인한다.

처리 구간 시작 전에 필요한 상위 절 상태를 확보하고 구간 끝에서 다음 쪽 주석을 살핀다. 쪽을 묶음으로 나눠 처리해도 앞 묶음의 끝 문맥을 다음 묶음에 넘겨야 한다. 확인할 인접 범위는 실행 지시서에 적는다.

완료 기준:

- 기준은 대상 표와 연결되거나 연결 미확정으로 남는다.
- 다른 절이나 표의 주석이 확정 근거처럼 붙지 않는다.
- 다음 쪽에 주석이 있는 표를 근거 완료로 잘못 표시하지 않는다.
- 이어지는 표를 합치면 원래 표 조각과 각 쪽의 출처를 유지한다.
- 참조 번호가 같아도 부문이 다른 대상은 구분한다.

### 작업 4. 후보를 비교하고 전체 생성 여부를 결정한다

**목적:** 기존 방식과 ODL 후보 중 무엇을 어느 범위에 채택할지 결정한다.

원문 보관·변환 규칙을 고정한 뒤 같은 입력과 기준으로 비교한다. 기존 개발 표본의 재확인과 새 평가 표본의 결과를 따로 보고한다. 기존 기대값과 평가 초안을 처음부터 다시 만들지 않고 출처·검토 상태를 정리해 재사용한다.

새 표본은 구조 형태와 부문을 기준으로 결과를 보기 전에 선택한다. 초기 제안은 아직 개발에 쓰지 않은 연속 구간 12~20쪽이다. 실제 쪽 번호와 표 목록은 기존 자료의 중복 여부 및 유형 분포를 확인한 후 지시서에 고정한다. 새로운 실패 유형을 발견해 규칙을 바꾸면 그 표본은 개발 사례로 바꾸며 독립 평가라고 유지하지 않는다.

| 비교 항목 | 보고 방법 |
|---|---|
| 원문 값과 단위 | 대조한 값 수·오류 수·누락 수·원문 위치 |
| 행·열 대응 | 올바른 대응·잘못된 대응·보류를 구분 |
| 공동 값 | 칸 수와 적용 범위, 중복 숫자 생성 여부 |
| 기준과 주석 | 필요한 근거의 누락과 무관한 연결을 별도로 집계 |
| 불확실성 처리 | 실제 오류를 정상으로 받아들인 사례와 정상 자료를 보류한 사례 |
| 추적과 ID | 원문으로 돌아가지 못하는 결과와 이전 결과와 대응 불가능한 항목 |
| 운용 부담 | 실행 시간·최대 메모리·출력 크기·수작업 보류 규모 |

값 손실이나 잘못된 대응이 확인된 자료가 정상 상태로 통과하면 해당 범위는 채택하지 않는다. 평가 범위에서 그러한 사례가 없더라도 전체 문서 정확성으로 환산하지 않는다. 보류가 너무 많아 실제 견적 범위를 확보하지 못하는 후보도 개선이 필요하다.

비교 뒤에는 채택·제한 채택·보류 중 하나를 선택하고 이유와 남는 범위를 기록한다. 두 후보 모두 부족하면 어떤 실패 유형 때문에 결정을 못 하는지 명시하고, 그 유형만 다음 작업으로 삼는다.

### 작업 5. 전체 문서를 별도 출력으로 생성하고 점검한다

**목적:** 선택한 방식이 전체 문서에서 작동하는지 확인하고, 운영에 옮길 수 있는 데이터 묶음을 만든다.

실행 전에 범위·입력·출력 위치·추정 시간과 저장 공간·재개 방식·실패 시 처리·ID 대응·비교 기준을 담은 별도 지시서를 만든다. 현재 전체 재처리 금지 조건을 바꾸는 사용자 지시를 받은 뒤 실행한다.

원래 데이터는 보존하고 별도 출력으로 생성한다. 전체 쪽의 처리 성공·실패·표와 기준·주석 수·보류 사유를 집계한다. 모든 자동 점검을 실행하되 모든 칸을 사람이 검토했다고 주장하지 않는다. 일반 표본과 이상 징후가 있는 표의 원문 대조를 구분해서 수행한다.

표본에서 확인한 규칙의 적용 범위, 새 정수 줄글의 발생 규모, 제목 오인 신호, 부문·절 누락, 다음 쪽 연결, 원문 추적 실패 등을 전체 결과에서 확인한다. 숫자 줄은 정수라는 이유만으로 지우지 않고 위치·소속·분류를 확인한다.

완료 기준은 다음과 같다.

- 처리하지 못한 쪽과 표, 보류 자료가 목록으로 남는다.
- 원문 보관·변환 레코드·청크는 같은 생성 결과를 가리킨다.
- 새 ID에 대응하지 못하는 기존 명세·인용·평가·캐시 참조가 파악된다.
- 자동 점검과 원문 대조의 범위가 설명된다.
- 사용 가능한 범위와 후속 검토 범위가 나뉜다.
- 기존 결과로 돌아갈 수 있다.

전체 생성 성공은 운영 전환 완료가 아니다. 재임베딩과 운영 데이터 교체는 현재 금지 범위이며 별도 요청과 지시서로 진행한다.

## 6. ID와 원문 추적의 원칙

생성 결과 안의 ID와 PDF의 원문 위치를 구분한다. 원문 위치에는 문서 해시·쪽·좌표·추출 도구의 원시 식별자를 기록하고, 생성 결과에는 생성 버전과 내부 식별자를 둔다.

글이나 레코드 순번이 같다는 이유만으로 두 결과를 동일하다고 보지 않는다. 추출 도구가 바뀌면 칸과 표 경계도 달라질 수 있으므로 좌표만으로 영구적으로 같은 ID가 보장된다고 약속하지 않는다.

기존 ID와 새 결과를 대응할 때 문서·쪽·표 위치·내용을 함께 확인하고, 일대일·분리·병합·미확정으로 구분한다. 원문 내용이 같아도 위치가 다른 반복 주석은 각각 유지한다. 미확정 대응을 임의로 확정하지 않는다.

이 대응은 작업 1에서 기록 형식을 정하고, 작업 4에서 확인하며, 작업 5의 전체 생성 뒤 운영 전환 전에 사용한다. 현재 국소 패치에 ID 전면 개편을 섞지 않는다.

## 7. 이 중목표를 끝냈다고 말할 조건

다음 네 가지가 갖춰지면 검색과 계산 지식 개선의 바탕이 마련됐다고 판단한다.

1. 추출 방식과 적용 범위를 근거로 선택했다.
2. 원문 칸·기준·주석·관계·불확실성이 보관되고 후속 단계까지 전달된다.
3. 전체 생성 결과의 처리 범위와 검증 범위, 사용 가능 범위와 보류 범위를 설명할 수 있다.
4. 새 결과의 참조가 일관되고 기존 결과를 보존해 복구할 수 있다.

모든 표가 계산 가능해져야 이 중목표를 끝내는 것은 아니다. 해결되지 않은 자료가 정상 자료처럼 섞이지 않아야 한다. 계산 명세 검증·대화·단가·Excel은 뒤의 중목표로 남는다. 제한된 데이터로 목록과 설명을 개선하는 일까지 전체 문서 완벽성을 기다릴 필요는 없다.

## 8. 역할과 실행 범위

Codex는 설계와 지시서 작성, 원문과 결과 검토, 단계별 채택 판단을 맡는다. 실제 구현은 별도 Claude Sonnet 세션에서 진행한다. 한 번에 한 작업만 지시한다.

이 문서는 실행 승인으로 쓰지 않는다. 첫 지시서는 작업 1만 구체화하며 입력 경로·출력 위치·수정 가능 파일·비교 기준·완료 기준을 고정해야 한다. 다른 작업 폴더의 현재 패치나 원본 브랜치를 자동으로 변경하지 않는다.

현재 계속 금지된 범위는 코드·설정·데이터의 임의 확대 변경, 전체 재처리, 운영 접속, 외부 추론·임베딩 API, 비밀값 파일 접근, 설치·다운로드·환경 변경, 커밋·푸시·병합·배포다. 범위를 늘리는 실행은 별도로 구체화한다.
