## 1. 실행 전에 기대 행동 고정

G03·G09·G10·G14와 기존 정상·자료 없음·미확정 사례를 원문으로 확인하고 아래 정책에 따른 기대 행동을 먼저 적는다. 과거 기대값을 덮어쓰지 않는다. 정책 변경으로 자료 없음 사례가 확인 필요가 될 경우 의미와 이유를 별도 기록하고 기존 기준 통과로 세지 않는다.

주요 기대는 정답 근거를 검토할 수 있도록 보존하고, 미확정·불일치 경고가 있는 자료를 정상 계산 근거로 승격하지 않는 것이다. 모든 후보를 정상 답변 문맥에 넣어서 필수 포함률을 맞추지 않는다.

## 2. 질문 원문과 약한 낱말 판정 구분

질문 원문과 각 어절을 그대로 보존한다. 직접 작성한 어미 분리로 나온 어간·앞부분 일치 결과는 검색 보조 표현이며 대상 동일성 판단의 사실이 아니다.

`짜리` 같은 규격 연결 표현 때문에 대조·전면 강등을 실행하지 않도록 요청 역할을 분리한다. `호퍼스케일`처럼 명사 끝을 어미로 잘라 만든 표현으로 원문 부재를 결정하지 않는다. 어절 전체의 원문 존재 여부와 직접 선택한 근거의 실제 대상을 먼저 확인한다. 전체 표현이 없더라도 대상이 없다는 충분조건으로 쓰지 않는다.

잘림이 애매하면 원래 표현과 불확실한 분석을 남긴다. 새 어미 목록을 늘리거나 G 질문 단어만 예외 처리하는 것을 주된 해결책으로 삼지 않는다. 새 형태소 서비스·임베딩·파서를 도입하지 않는다. 작업·부정·단위·조건은 지우지 않는다.

G03·G09·G10 및 다른 명사·외래어·규격 표현의 소수 대조 사례로 확인한다. 새 사례의 기대 행동은 결과 전에 원문으로 고정한다. 표현을 알아봤다는 이유만으로 소속·수식·참조 보류를 해제하지 않는다.

## 3. 추가 대조 모델의 근거 제외 권한 제거

`target_compare`의 `different`와 유효한 줄 ID만으로 주·보조 근거를 제거하는 경로를 없앤다. 줄 ID 존재는 모델 판단의 의미가 맞다는 증명이 아니다. 주 근거 제거 후 보조 근거까지 연쇄 제거하는 경로와 자동 `not_found`도 함께 점검한다.

이번 기본 경로에서는 추가 대조 호출을 자동 제외 장치로 사용하지 않는다. 기존 응답은 참고 판정 재생에 사용할 수 있다. 대조 결과를 사용하는 경우 불일치 경고·이유·원문 위치로 기록하며, 그것만으로 근거를 없애거나 `supported`로 승격하지 않는다.

출력은 용도를 분명히 나눈다.

- 정상 답변 근거: 대상과 조건이 검증되고 해당 소속 상태로 사용할 수 있는 원문.
- 검토용 원문: 유효한 선택 또는 구조 조회로 읽었지만 불일치·소속·조건이 미확정인 자료. 일반 답변이나 계산에 자동 사용하지 않도록 별도 필드와 상태를 둔다.
- 진단 후보: 다른 대상임이 확인되거나 관련성을 입증하지 못한 가까운 자료. 답변 근거와 필수 근거 포함 집계에 넣지 않는다.

유효하지 않은 ID·위치·버전은 계속 거부한다. 확인된 다른 표 제목·소속 경계도 계속 막는다. 정상/검토용 근거 어디에도 관련성을 확보하지 못하면 `not_found`이며, 관련 근거는 있으나 판정이 충돌하면 `needs_confirmation`과 구체적인 부족 사유를 반환한다. N19를 억지로 `not_found`로 만들기 위해 이전 낱말 부재 차단이나 특정 단어 제외 규칙을 복구하지 않는다.

G03의 잘못된 대조 응답을 유효한 ID 형식으로 변환한 가상 입력도 시험한다. 형식 오류 덕에 정답 표가 살아남는 동작이어서는 안 된다. G10 표의 보존은 형식과 무관하게 같아야 한다. 대조 경고가 남은 사례를 정상 처리 성공으로 세지 않는다.

## 4. 설명에서 필요한 표를 구조로 조회

G09처럼 설명만 선택해도 해당 설명과 연결된 표·기준이 필요한 경우 기존 원문 조회 관계로 읽는다. 미확정 관계면 검토용 원문으로 전달하고 관계·소속 상태를 유지한다. 모델이 매번 표를 보조 선택해야만 전달되게 하지 않는다.

모든 같은 절 표를 추가하지 않는다. 직접 연결 또는 독립적으로 확인되는 위치 관계를 기록한다. 여러 표가 소유 경쟁이면 대안과 부족 사유를 표시한다. 관계가 없는데 정답 ID를 알고 넣는 규칙은 금지한다. 원문 버전과 제목 경계, 기존 잘못된 길어깨 관계 제외를 유지한다.

G09의 최초 응답과 반복 응답을 각각 재생해 필요한 표·설명 전달과 보류 상태가 일관되는지 확인한다. G10의 조건 규칙과 기준 표도 함께 읽히는지 확인한다. N08·V12에서 수식 보류와 다른 표 혼입 방지가 유지되는지 대조한다.

## 5. 목록 완전성 의미 분리

현재 `complete`가 '모델에 준 후보 목록을 모두 판단했다'와 '질문 범위의 전체 목록이 완성됐다'를 혼용한다. 다음 정보를 분리한다.

- 요청 범위: 명시한 부문·대상·포함 범위와 모호성.
- 조회 범위: 실제 탐색한 절 계층과 탐색하지 않은 가지·자원 제한.
- 후보 처리 완료: 반환한 후보를 모두 포함/제외/보류로 판단했는지.
- 요청 범위 완전성: 요청 범위를 충분히 탐색·판단했는지. 입증할 수 없으면 미확인 또는 부분 목록.

모델이 `complete=True`라고 해도 요청 범위 완전성을 그대로 확정하지 않는다. 광범위·모호한 목록은 대상 범위를 확인하도록 표시한다. 제목 낱말이 맞는 절의 수를 정답 개수로 간주하지 않으며, 그것은 누락 점검 신호일 뿐이다.

G14에서는 최종 이유에 범위 모호성·미탐색 또는 목록 부족을 명시한다. `no_primary`만으로 모호성을 설명하지 않는다. G11~G13 및 기존 명확한 목록에서 불필요하게 모두 불완전으로 바뀌지 않는지 확인한다.

## 6. 실행 범위와 한도

1. 주요 실패와 위험의 저장된 선택·대조 응답으로 먼저 구현·검증한다. 코드만 바뀐 경우 모델을 다시 부르지 않는다.
2. 새 응답이 필요한 주요 사례와 소수 대조 사례만 호출한다. 필요한 반복은 G09와 대상 대조 오류 사례에 집중한다.
3. 설정을 고정한 뒤 기존 60문+4g 20문을 마지막으로 한 번 재생·평가한다. 고정 입력 해시가 같은 모델 응답만 재사용한다. 4g는 개발·회귀 전환을 명시한다.
4. 최종 확인 뒤 실패를 다시 고치며 전체를 반복하지 않는다. 중요한 실패가 남으면 원인과 범위를 보고하고 종료한다.

기존 선택 프롬프트·스키마를 전체 재설계하지 않는다. 변경으로 입력이 달라져 재생이 불가능하면 해당 사례만 새 호출하며 그 범위를 기록한다. 80문 전체 새 모델 호출은 이번에 하지 않는다. 재생·새 호출·미실행을 각각 기록한다.

새 유료 호출 상한은 총 **30회·예상 비용 1달러**다. 모델·질문 벡터·재시도·형식 복구를 모두 센다. 공식 가격 미확인이면 추정 한계와 보수적인 비용을 기록한다. 성공 캐시를 일반 재실행에 재사용하고 반복 측정은 별도 실행 ID로 한다. 다른 작업의 프로세스를 종료하지 않는다.

## 7. 지표와 종료 보고

필수 원문 보존, 정상 주·보조 선택, 검토용 전달, 진단 후보를 구분해 집계한다. 진단 후보를 답변 문맥에 숨겨 필수 포함률 95%를 맞추지 않는다. 검토용 근거가 모두 확정된 것처럼 보고하지 않는다.

주요 확인은 정답 표를 잘못 제외하는 동작 0, G09 표·설명 전달 일관성, G14 잘못된 요청 범위 완전 표시 0이다. 기존 금지 주·문맥 혼입·정상 질문 거부·미확정 승격·자료 없음과 불필요 보류도 같이 보고한다. 변경 정책에서 `needs_confirmation`이 된 자료 없음 질문은 기존 목표 달성으로 세지 않는다.

기존 독립 평가의 18/20 통과·필수 11/13과 이번 개발·회귀 결과를 분리한다. 알려진 부정 조건 미확인·목록 과다 포함·구형 집합 누락·모델 변동이 사라졌다고 하지 않는다. 새로운 독립 평가가 필요하다는 사실은 남기되 이번에 질문을 만들거나 실행하지 않는다.

원문·청크·문서 벡터·DB 자료 불변과 영향 경로의 검사를 확인한다. 불필요한 전체 파이프라인을 다시 생성하지 않는다.
