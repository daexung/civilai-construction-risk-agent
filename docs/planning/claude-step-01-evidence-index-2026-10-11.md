프로젝트 루트는 `C:\Users\user\Desktop\PROJECTS\civilai-construction-risk-agent`다. 설명과 결과 보고는 쉬운 한국어로 하고 한자는 쓰지 않는다. 원문 자료의 글자는 있는 그대로 보존한다.

## 수행할 일

### 1. 입력을 고정한다

입력 해시, 생성 ID, 파일 크기, 표·글·관계 수를 `input_manifest.json`으로 기록한다. 서비스 설정을 import하지 말고 표준 Python과 기존 설치 도구를 우선 사용한다. 단계 출력과 코드 버전을 분리한다.

### 2. 기존 PostgreSQL 기반 저장 경로를 만든다

기존 Supabase·PostgreSQL 연결과 마이그레이션 코드의 규칙을 먼저 읽는다. 실제 비밀값을 출력하지 않는다. 원문 자료는 기존 회원·대화 자료와 별도 스키마 및 릴리스로 관리한다. 최종 스키마 이름은 기존 구성과 충돌하지 않게 정한다. 마이그레이션 SQL, 적재 코드, 조회 코드를 구현하고 별도 PostgreSQL 검증 환경에서 실행한다. 검증 환경이 없으면 그 제약을 명시하고 기존 코드 규칙과 SQL·입력 장부·확인 코드를 준비한다. 공유 Supabase에 바로 적용하는 것은 이번 지시의 실행 범위가 아니다. 실제 적재 환경 검증 없이 DB 구현 완료라고 보고하지 않는다.

전체 계획의 `documents`, `nodes`, `sections`, `source_records`, `source_relations`, `edges`, `edge_candidates`, `releases` 역할을 구현한다. 구조 JSON과 원래 관계 JSON을 보관해 표현하기 어려운 정보도 잃지 않는다. 청크·임베딩은 다음 단계다.

원문 레코드 23,481개, 표 2,328개, 관계 11,823건을 모두 추적할 수 있어야 한다. 제목·기준·설명·칸·행 묶음은 실제 식별자로 조회한다. 기존 관계 끝점에 제목 문자열이나 행 선택자가 있으면 원시 값도 남기고 정규화 상태를 표시한다. 없는 노드를 확정 노드처럼 만들지 않는다.

한 번의 적재가 중단되면 완성본처럼 보이지 않게 새 릴리스와 상태를 사용한다. 트랜잭션·무결성·외래 키·중복 ID를 검사한다. 조회에는 필요한 읽기 권한을 사용한다. 출발·도착 관계와 문서·부문·절 번호에 조회 색인을 둔다. 기존 회원·대화·활성 자료를 덮어쓰지 않는다.

### 3. 실제 본문 절 목록을 만든다

`headings`, 표의 `section_path`, 레코드 연결, 부문 페이지 지도를 함께 사용한다. 목차의 제목 줄과 실제 본문 제목을 구분하고 반복된 제목은 원문 위치를 보존하며 같은 본문 절로 연결한다.

절 식별자는 문서 버전·연도·부문·절 번호를 포함한다. 부문을 모르면 미확정으로 남긴다. 같은 번호가 다른 부문에 있다고 합치지 않는다. 원문에 있는 번호 없는 제목과 품목 코드를 억지 절 번호로 만들지 않는다. 판단 규칙과 예외 수를 기록한다.

### 4. 기존 참조 232건의 대상을 연결한다

각 문장에 출발 위치, 원문, 대상 표현, 부문, 절 번호, 하위 항목, 후보, `target_status`, 조건 원문, 기존 상태를 남긴다. 232건 각각의 처리 결과가 장부에 있어야 한다.

대상 상태는 `resolved/partial/ambiguous/missing/external`을 사용한다. 부문·번호·제목·하위 항목을 대조한다. 부문 생략 32건을 같은 부문으로 무조건 확정하지 않는다. `/7.`처럼 하위 항목이 있으면 절만 찾은 상태는 부분 연결이다. 조건 문구가 비어 있다고 무조건 적용으로 만들지 않는다.

원래 `confirmed=false`를 보존한다. 참조 대상이 정해졌다는 새 필드와 규칙 적용 여부를 구분한다. 비용을 자동 추가하거나 숫자를 계산하지 않는다.

현재 목록에 없는 참조를 놓치지 않도록 전체 본문에서 부문·절 번호·참조 표현의 일반적인 패턴을 읽기 전용으로 점검한다. 새 후보는 별도 장부에 근거와 함께 보관한다. 이 단계에서 LLM으로 의미 관계 전체를 새로 추출하거나 누락 파싱을 고치는 작업으로 넓히지 않는다.

### 5. 실제 사례와 적용 제한을 확인한다

결과를 보기 전에 기대 연결을 원문으로 정해 `expected_references.json`에 저장한다. 최소 다음 유형을 포함하되 검사 개수를 채우기 위한 중복 테스트는 만들지 않는다.

- 185쪽의 공통 6-1-1 → 공통 6-1-3. 건축·기계설비의 같은 번호로 연결하지 않는다.
- 원문에서 부문을 명시한 다른 부문 참조.
- 부문이 생략된 참조와 후보가 모호한 경우.
- `1-2-4/7. 잡재료 및 소모재료`처럼 하위 항목을 포함한 참조.
- 목차와 실제 본문에 같은 번호·제목이 있는 경우.
- 대상이 없거나 외부 문서인 경우. 실제 사례가 없으면 가상 입력으로 표시한다.
- 순환 참조·반복 참조·연결 대상 변경 후 캐시 혼용. 가상 입력 여부를 명시한다.
- 기존의 기준·표 주석·이어지는 표가 대상 연결 작업 때문에 확정 적용으로 바뀌지 않는지.

전체 원문 보존은 데이터 직접 비교로 검사하고, 참조의 의미는 원문 대조 사례와 일반 규칙으로 검사한다. 같은 출력끼리 비교한 사실을 원문 정답 확인으로 표시하지 않는다.
