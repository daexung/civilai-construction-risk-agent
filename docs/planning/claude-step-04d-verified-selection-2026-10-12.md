## 1. 모델 역할과 실행 결과

모델은 질문의 대상·작업·조건·단위에 맞는 주 근거와 보조 근거, 이를 뒷받침하는 원문 위치, 필요한 참조·누락 조건을 추천한다. 계산과 최종 답변은 생성하지 않는다. 질문 ID·정답 ID·특정 실패 단어를 실행 로직에 하드코딩하지 않는다.

기존 공통 후보와 구조 문맥을 재사용한다. 모델 응답, 검증된 선택, 거부된 선택, 최종 근거 상태를 별도 필드로 남긴다. 모델의 `supported`를 그대로 최종 상태로 복사하지 않는다. 모델 오류 시 기존 방식으로 전환한다면 전환 사실과 불완전 여부를 표시하며 성공처럼 감추지 않는다.

## 2. 대상과 표 연결 검증

V12의 원인을 먼저 원문 순서와 실제 후보 표현에서 확인한다. 설명 끝의 다음 제목을 앞 표의 소속 근거로 사용한 문제인지, 후보 표기의 문제인지 구분하고 일반적인 연결 규칙으로 처리한다.

표의 대상 근거는 해당 표 소제목, 유효한 구조 관계, 또는 위치가 확인되는 제목·설명 구간으로 기록한다. 한 설명에 다음 제목이 들어 있다고 설명 전체를 그 제목의 표와 연결하지 않는다. 모델이 연결에 사용한 설명과 표 사이의 관계·방향·위치를 검증한다. 모델의 인용만으로 새 확정 관계를 만들지 않는다.

위치 기반 연결밖에 없다면 관련 표를 확인용 후보로 제시할 수 있지만 미확정 상태를 유지한다. 다른 대상의 표는 정상 주 근거로 전달하지 않는다. 일반 규칙으로 정확한 선택을 못 정하면 경쟁 후보와 부족한 연결을 반환한다. 잘못된 표에 확인 필요 표시만 붙이는 것으로 완료하지 않는다. V12의 기대 결과는 병원 표와 관련 설명의 제시 및 소속 미확정 유지이며, 견적 적용 확정이 아니다.

## 3. 원문 인용은 코드가 가져오기

자료별로 원문 위치를 선택할 수 있는 식별자를 제공한다. 글은 줄 또는 구간, 표는 행·칸 식별자를 사용할 수 있으며 기존 구조를 우선 활용한다. 모델은 해당 식별자를 반환하고 코드는 그 원문을 가져온다.

ID 존재, 자료와 위치의 소속, 실제 읽은 내용, 버전을 검증한다. 서로 떨어진 구간은 각각의 원문으로 표시하며 하나의 연속 인용처럼 합치지 않는다. 표 값은 행 이름·열 이름·단위와 함께 전달한다. 공동값 표지를 지우거나 다른 자료의 문장을 해당 표 인용으로 옮기지 않는다.

잘못된 위치는 거부하고 이유를 남긴다. 거부 때문에 필요한 근거가 없어지면 완료 상태로 내보내지 않는다. 4c의 인용 불일치 네 사례와 잘못된 ID·위치의 가상 입력으로 확인한다. 이 검사 통과는 선택 의미의 정확성과 별도로 보고한다.

## 4. 최종 상태는 필요한 근거의 의존 관계로 결정

선택한 자료와 질문에 필요한 연결 경로를 따라 보류·소속 미확정·수식 미확정·부분/모호/없는 참조·예산 누락을 유지한다. 해당 미확정 자료에 기대야 질문을 해결할 수 있으면 `needs_confirmation`이다. 모델이 확정으로 올릴 수 없다.

필요하지 않은 주변 후보의 미확정 상태만으로 전체 답변을 보류하지 않는다. 근거 충분함, 참조 대상 상태, 계산 적용 여부는 별도 필드로 유지한다. `supported`여도 계산 적용을 승인한 뜻이 아니며 `applicability=unknown`을 모델이 해제하지 않는다.

`not_found`는 현재 읽은 범위에서 관련 근거를 찾지 못했다는 의미다. 검색 결과만으로 문서 전체에 없다고 단정하지 않는다. 자료 없음 질문에서 비슷한 후보를 정상 근거로 보내지 않는다. V17 부분 참조와 V12 미확정 소속뿐 아니라 무관한 미확정 후보가 끼어 있는 정상 사례도 확인한다.

## 5. 목록과 제한된 추가 조회

목록은 질문 범위를 먼저 기록하고 기존 절 계층·목록을 조회한다. 범위 내 절을 목록 후보로 수집하고 포함·제외·판단 보류를 각각 기록한다. 같은 표 조각을 다른 공종으로 중복 세지 않는다. 상위 묶음의 모든 하위 절이 정답이라고 가정하지 않는다.

전체 후보를 확인하지 못했거나 범위가 모호하면 부분 목록 또는 확인 필요로 표시한다. 모델의 주/보조 역할 분류 때문에 관련 공종이 목록에서 빠지지 않도록 목록 항목과 세부 근거를 별도 출력한다. V02와 V01에 적용하고 기존 목록 질문 전체에서 누락·불필요 항목을 확인한다.

추가 조회는 질문당 최대 두 번이며 절 목록 조회·질문 보완 검색을 포함한다. 주어진 원문 식별자로 필수 기준·주석·명시적 참조를 읽는 기존 근거 조회와 횟수 정의를 구분해 기록한다. 부족한 항목, 조회 입력, 반환 자료, 종료 사유를 남긴다. 불필요한 전체 탐색이나 반복 모델 호출은 하지 않는다.

## 6. 검증 순서와 호출 한도

1. 저장된 4c 응답으로 원문 위치·관계·상태 검증 경로를 먼저 확인한다. 모델을 다시 부르기 전에 가능한 오류를 잡는다.
2. 개발용 12문으로 변경된 선택 경로를 실행한다. 실패를 입력 표현·선택·검증·조회·예산 문제로 분류한다. 정상 사례도 함께 확인한다.
3. 현재 구성으로 기존 질문 세트 3개, 합계 60문을 실행해 비교한다. 이미 사용한 자료이므로 개발·회귀로 표시한다. 12문은 이 60문에 포함되며 합계 72문으로 보고하지 않는다.
4. 잘못된 표·자료 없음·미확정 상태 사례를 반복해 흔들림을 기록한다. 결과를 본 뒤 바꿨다면 최종 코드와 프롬프트 해시를 구분한다. 새 독립 질문은 이번에 실행하지 않는다.

같은 입력·모델·프롬프트·설정의 성공 응답은 캐시를 재사용한다. 반복 측정만 별도 실행으로 호출한다. 문서 임베딩은 호출하지 않는다. 보완 검색의 새 질문 벡터만 필요할 때 생성한다.

호출 전에 실제 사용 경로의 공식 가격과 입력량으로 예상 비용을 기록한다. Gemini API와 Vertex 가격을 같은 것으로 단정하지 않는다. 확인할 수 없으면 기존 추정의 한계를 명시하고 보수적으로 상한을 계산한다. 이번 작업의 운영 상한은 예상 비용 5달러·전체 유료 호출 시도 200회이며, 둘 중 먼저 도달하면 멈춘다. 이 금액은 실험 제한이지 예상 청구액이 아니다. 재시도·형식 복구·질문 임베딩도 집계한다.

프롬프트 수정은 일반 규칙에 근거한 제한된 수정으로 진행한다. 개발 12문을 통과할 때까지 무제한 조정하지 않는다. 60문 확인 뒤에도 중요한 실패가 남으면 결과와 원인을 보고하고 새 설계 변경이나 서비스 연결을 시작하지 않는다.

## 7. 완료 판단과 보고

검사 개수보다 최종 문맥의 필수 근거 포함, 금지 주 근거와 금지 문맥 혼입, 정상 질문 거부, 자료 없음 처리, 목록 누락·과다 포함을 우선 보고한다. 원문 위치 오류·상태 승격·버전 혼용의 가상 입력 검사와 실제 사례를 구분한다.
