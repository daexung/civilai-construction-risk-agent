## 적용 방식

완료된 `experiments/parsing-final`의 코드와 출력은 원본으로 보존한다. `experiments/retrieval-v1`에서 원문 근거를 가진 교정 자료를 읽어 제목과 검색용 소속을 보완한다. 원본 파싱 내용과 교정된 검색 입력을 구별해서 보관한다.

1. 수정 전 코드·입력 해시·현재 릴리스·대상 주변의 소속을 보관한다. 원문 세 쪽의 제목 위치와 다음 제목 경계를 그림으로 확인한다. **수정 결과를 보기 전에** 기대 제목, 대상 표와 설명 목록, 바뀌면 안 되는 인접 절을 기록한다.
2. 교정 자료에 PDF 해시, 제목 원문, 쪽과 위치, 적용 대상 원문 식별자, 기존 소속, 새 소속, 대조 근거를 기록한다. 입력이나 기존 소속이 예상과 다르면 적용을 거부한다. 새 제목은 원문 대조로 추가한 항목임을 표시하고 존재하지 않는 ODL 항목 번호를 만들지 않는다.
3. 세 절을 등록하고 해당 표·기준·설명의 검색용 소속을 바꾼다. 원본 레코드 글과 원본 연결 정보는 유지한다. **검색용 글에 앞 절 제목이 들어 있다면 그것도 새 소속과 맞게 보완한다.** DB의 절 번호만 바꾸고 나중에 청킹할 글에 잘못된 제목을 남기면 완료가 아니다. 다음 청킹이 사용할 보완된 입력 경로를 명시한다.
4. 교정 코드와 자료의 해시를 릴리스 계산과 실행 기록에 포함한다. 로컬 검증 DB `civilai_rag_verify`에 새 릴리스를 적재한다. 이전 검증 결과와 릴리스를 보존한다. 원격 Supabase 연결, 운영 활성화, 기존 서비스 DB 변경은 하지 않는다.

절 사이의 순서를 넣는 구현 방식은 기존 코드에 맞게 선택한다. 다른 항목의 원문 순서 번호를 임의로 다시 매겨 범위 밖 차이를 숨기지 않는다.

## 확인 기준

- 세 제목과 소속 경계가 PDF 원문과 맞는다. 기계 작업 표가 인력 작업 절 아래에 남지 않는다.
- 같은 쪽의 본선 작업과 다음 절의 표·설명은 기존의 올바른 소속을 유지한다.
- 원본 레코드 23,481개와 표 2,328개를 보존한다. 기존 원문 글, 값, 칸 연결, 보류 상태를 바꾸지 않는다.
- 현재 절 1,359개에 세 절을 더해 1,362개가 되는지 확인한다. 실제 원문과 다른 결과면 숫자를 맞추기 위해 규칙을 완화하지 않고 원인을 보고한다.
- 대상 밖의 내용과 소속은 같다. 릴리스 식별자 등 실행 정보 차이는 내용 차이와 별도로 집계한다. 대상 안에서 바뀐 항목 목록을 전부 남긴다.
- 기존 참조 232개와 추가 후보 9개를 보존한다. 기존 참조의 210개 연결, 부분 연결 15개, 후보가 여러 개인 6개, 대상이 없는 1개는 수정 전후 비교한다. 소속 보완으로 달라지는 관계가 있다면 개별 근거를 기록한다. 남은 참조 22개를 이번 작업에서 억지로 확정하지 않는다.
- 기존 검사를 실행한다. 세 제목 누락을 예상한 기존 검사가 있다면 이전 기대값과 변경 이유를 기록해 수정한다. 교정 거부, 반복 실행의 동일 결과, 적재 실패 시 이전 정상 릴리스 보존도 확인한다.
- 758쪽의 서로 다른 값과 기존 보류를 포함한 파싱 교정은 그대로 유지한다.

검사 수는 정확도라고 보고하지 않는다. 새 ODL 추출, 임베딩 API, 청킹 개선, 배포, 커밋·푸시·PR 변경은 하지 않는다.
