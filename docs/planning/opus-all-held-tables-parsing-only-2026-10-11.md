## 최신 작업 범위

사용자가 통합 작업 범위가 너무 크다고 판단하고 **우선 파싱만 해결하도록 지시했다.** 이전 `opus-today-parsing-chunking-embedding-service-2026-10-11.md`의 후속 단계는 진행하지 않는다.

이번 목표는 **남은 보류 표 286개를 모두 원문으로 확인하고 실제 오류와 미확정 연결을 해결하는 것**이다. 청킹, 임베딩, 서비스 코드 수정·실행, 외부 API 호출, 운영 자료 변경, 커밋·푸시·배포는 포함하지 않는다.

이미 이전 지시서에 따라 작업을 시작했다면 기존 변경과 실행 기록을 보존하고 파싱 작업만 이어간다. 원래 상태로 되돌리거나 같은 수정을 다시 하지 않는다. 후속 단계의 실행을 중지하되 이전부터 있던 서비스나 다른 작업의 프로세스를 임의 종료하지 않는다.

구현과 원문 대조는 Claude Code Opus가 맡는다. Codex는 결과 검토를 맡는다. 아래 범위에서 실제 수정과 확인까지 수행하고 결과 보고 뒤 멈춘다. 반복해서 승인을 요청하거나 계획만 제출하고 끝내지 않는다.

## 실행 순서

1. **전체 작업 목록을 고정한다.** 표 식별자·쪽·모든 보류 사유·원문 근거·기대 구조·수정 결과·상태를 기록한다. 각 표의 모든 사유를 추적한다.
2. **원문 기준을 먼저 정한다.** 표 전체 그림과 제목·단위·주석·필요한 앞뒤 쪽을 확인한다. 수정 결과에 맞춰 기대값을 정하지 않는다. 표 역할에 따라 값 표와 정의·설명 표를 구분한다.
3. **같은 문제는 유형별로 고친다.** 행·머리글을 먼저 확정하고 이름·번호를 연결한다. 원문 근거가 같은 구조에만 공통 규칙을 적용한다. 대표 몇 표만 보고 전체를 승인하지 않고 적용 대상 모두를 원문 기준과 대조한다.
4. **예외는 표별 교정으로 마무리한다.** 기존 문서 버전·교정 전 내용·좌표 확인 경로를 재사용한다. 원래 글·칸·번호와 교정 후 표현을 함께 보관한다. 칸 번호가 바뀌면 전후 대응과 기존 교정 자료를 갱신한다. 판정 기준을 느슨하게 하거나 표시만 지우지 않는다.
5. **적용 조건까지 연결한다.** 굵은 계단선 8개 표는 그림 첨부만으로 완료하지 않는다. 관련 주석의 장비 출력과 선의 범위를 연결해 어떤 값에 어떤 조건이 있는지 기록한다. 원문 계산 결과를 재계산해 바꾸지 않는다.
6. **전체 파싱 출력을 생성하고 확인한다.** 같은 원시 출력으로 982쪽을 이번 폴더에 생성한다. 원문 글자·위치에서 칸과 행·이름·단위·번호·조건, 내보낸 레코드와 원문 연결까지 비교한다. 누락, 칸 하나에 몰림, 잘못된 행·열 연결, 반복도 확인한다. 이는 파싱 출력 확인이며 청킹 실행은 하지 않는다.

새 파싱 출력의 레코드와 연결 정보에는 교정 내용이 실제로 반영돼야 한다. 확인 문서만 쓰고 기존의 잘못된 출력을 그대로 두면 해결이 아니다.

기존 완료 작업인 복구 표 24개, 칸 8개 교정, 수식, 머리글·목록·설명, 행 연결 6개를 유지한다. 대상 밖 결과의 차이는 원문으로 확인하고 의도하지 않은 부작용을 해결한다. 새로 확인한 실제 오류를 숨기지 말고 같은 작업 목록에 추가한다.

## 완료 기준

- 표마다 `정상 확인 완료`, `교정 완료`, `미해결`을 구분해 기록한다.
- 286개 각 표의 모든 사유가 원문 확인 또는 교정으로 해결되고 실제 파싱 출력과 원문 연결에 반영돼야 이번 목표를 완료했다고 보고한다.
- 정의·단위·설명 표는 계산 표로 바꾸지 않고 그 역할에 맞는 원문 구조와 연결을 정확히 보관한다.
- 원문 자체가 모호하거나 충돌하면 구체적인 근거와 남은 이유를 적고 미해결로 남긴다. 추측으로 확정하지 않는다. 미해결이 있으면 전체 완료라고 하지 않는다.
- 보류 표시만 제거하거나 검사 개수를 늘려 완료로 판단하지 않는다.
- 최종 출력의 코드·원문·교정 자료 버전이 일치하고, 다른 버전이나 교정 전 내용 불일치에서는 적용을 거부해야 한다.

현재 알려진 파싱 문제 해결과 견적 계산 로직 전체의 정확성 승인은 구분한다. 계산식을 새로 만들거나 계산 명세의 사용 가능 범위를 넓히지 않는다.
