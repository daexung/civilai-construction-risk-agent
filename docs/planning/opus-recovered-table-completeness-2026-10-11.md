## 진행 순서

### 1. 기준선과 기대 결과 기록

- `experiments/parsing-recovered-completeness-2026-10-11`을 작업 폴더로 만든다. 이미 있으면 확인하고 기존 결과를 덮어쓰지 않는다.
- 최신 후보 코드와 교정 자료를 기반으로 작업한다. 원본 PDF, ODL 원시 출력, 이전 작업 폴더는 읽기 전용으로 유지한다.
- 수정 전 출력과 버전을 고정한다. 대상 표의 칸·행·머리글·레코드·보류 상태를 보관한다.
- 먼저 표 24개의 원문 영역과 빠진 내용 목록을 만든다. 수정한 출력을 읽기 전에 확인된 누락의 기대 칸·값·행 연결을 기록한다.

### 2. 원문에서 출력까지 빠진 내용 찾기

다음 세 단계를 서로 비교한다.

`원문 표 전체 글자와 위치 → 복구 칸과 소속 → 내보낸 레코드와 원문 연결`

- 원문 표 영역은 **원본 PDF의 쪽 그림과 주변 머리글·가로 선·배치**로 정한다. 복구 도구가 찾은 `bbox`가 표 전체라는 가정을 하지 않는다. 501쪽처럼 도구의 영역 밖으로 누락된 바깥 열도 찾아야 한다.
- 표마다 원문 영역 안의 글자와 숫자를 위치별로 목록화한다. 복구 칸 안에 들어간 것뿐 아니라 **어느 칸에도 들어가지 않은 원문 글자**를 반드시 찾는다.
- 표 밖 제목·주석 등이 범위에 들어오면 원문 근거를 기록해 별도로 구분한다. 설명 없이 제외하거나 정상 누락으로 처리하지 않는다.
- 글자가 같은 숫자도 원문 위치별로 구분한다. 글자 총수나 숫자 목록이 같다는 이유만으로 다른 행·열에 붙은 것을 통과시키지 않는다.
- 병합 칸·공통 칸은 원문 칸 하나가 여러 행에 적용될 수 있다. 이것을 내용 중복 오류와 구분한다.
- 머리글이나 별도 설명으로 보관된 글은 행 레코드에 없더라도 구조 보관과 원문 연결로 돌아갈 수 있어야 한다. 쓸데없이 모든 글을 행 본문에 반복하지 않는다.
- 표 24개 모두에 같은 확인을 적용하고, 누락 후보를 원문 그림으로 대조한다. 자동 결과만 보고 완료로 판정하지 않는다.

### 3. 확인한 누락과 분수식 교정

- 바깥 선이 없거나 병합이 복잡한 표의 칸 누락 원인을 확인한다. 기존 보충 경로와 표별 교정 자료를 사용해 최소한으로 복구한다. 새 서비스·새 파서 도입이나 전체 ODL 재실행으로 범위를 넓히지 않는다.
- 원문 선·글자 위치·머리글을 근거로 빠진 칸의 좌표, 행·열, 병합 범위, 이름·단위·값 연결을 복구한다. 남아 있던 칸도 올바른 행·열에 유지되는지 확인한다.
- 교정 전 내용과 원문 버전이 맞을 때만 교정을 적용한다. 원래 보충 결과와 추가 교정의 전후 이력을 남긴다.
- 가능하면 기존 표·칸 식별자를 유지한다. 변경이 필요하면 전후 대응을 명시하고 행 연결 자료와 레코드 연결을 함께 갱신한다. 기존 교정 자료의 예상 내용 검사를 끄거나 검증을 느슨하게 하지 않는다.
- 501쪽에 칸이 추가되면 기존 행 연결 교정의 칸 목록·좌표·문서 해시 조건이 맞는지 확인한다. 바뀐 근거를 새 자료에 명시한다.
- 분수식은 원래 칸 글자와 위치를 보존하고 **읽기용 표현**을 추가한다. `/` 같은 표현은 원문 분수 배치를 읽기 위한 교정임을 기록한다. 공백만 다른 일반 글 교정 경로와 구분하고, 임의 글자 변경을 허용하는 범용 경로로 만들지 않는다.
- 해결한 사유만 보류를 해제한다. 다른 사유는 유지한다. 추가 누락을 발견했지만 복구 근거가 부족하면 해당 표에 누락 보류를 실제로 달고 목록에 남긴다.

### 4. 전체 결과 생성과 영향 확인

- 대상 표의 교정과 기대 결과를 확인한 뒤 같은 원시 출력으로 전체 982쪽을 이번 작업 폴더에 생성한다. 최종 결과는 최종 코드와 교정 자료의 버전과 일치해야 한다.
- 최신 기준선 `parsing-row-mapping-6-2026-10-11`과 전체 비교한다. 대상 표 24개 밖의 내용과 보류 상태는 그대로여야 한다. 생성 식별자·레코드 위치 번호 변화는 내용 변화와 구분한다. 대상 표에 딸린 관계가 바뀌면 변경 사유를 적는다.
- 기존 칸 8개 교정, 224쪽 수식, 머리글·설명·목록 수정, 최근 표 6개의 행 연결과 공동 칸 관계를 유지한다.
- 기존 검사도 재사용하되, 만든 칸만 비교하는 기존 검사가 이번 누락 확인을 대신하지 않도록 한다. 변화로 기존 기대값을 갱신해야 한다면 원문으로 정한 기대 결과를 기준으로 하고 이유를 기록한다.
- 특히 501쪽 바깥 열과 275·276쪽 누락을 **수정 전에는 잡고 수정 후에는 해소됐다고 판단하는 검사**가 있어야 한다. 검사가 교정 자료의 존재만 확인하고 통과하면 안 된다.
- 다른 PDF·원시 출력 버전 또는 예상 칸·글자·연결 불일치에서는 교정을 거부하는 기존 제한을 유지하고 추가 교정에도 적용한다.

## 완료 기준

검사 개수가 아니라 아래 상태를 확인한다.

1. 표 24개 각각에서 **원문에 있으나 복구 칸 또는 원문 연결에서 빠진 내용**이 목록화돼 있다.
2. 확인된 누락은 복구했고 원래 위치·행·열로 연결된다. 남은 누락이 있으면 해당 표가 보류 상태이며, 글자·위치·미해결 이유가 명시된다.
3. 알려진 누락 표 4개와 분수식 1곳의 전후 결과를 원문으로 대조했다.
4. 원문 내용 보관과 출력 전달이 모두 확인된다. 잘못된 행·열 연결이나 의미 없는 반복으로 글자 수만 맞추지 않는다.
5. 대상 밖에 의도하지 않은 변화가 없고 기존 수정 결과가 유지된다.

모든 대상 표를 확인했다고 해서 전체 문서 또는 계산 정확도를 승인했다고 쓰지 않는다. 자동으로 발견하지 못할 수 있는 글자, 그림·기호, 분수 배치 등의 한계도 구체적으로 적는다.

기존 집계의 `all_30_confirmed_targets_present`는 표가 존재한다는 확인이다. 이를 모든 결함 해결의 증거로 사용하지 않는다. `confirmed_defects_closed` 같은 이름은 실제 해결 상태와 맞는지 점검하고, 존재 확인 수·누락 해결 수·미해결 수를 구분해서 집계한다.
