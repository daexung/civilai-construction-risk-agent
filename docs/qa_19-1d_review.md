# 상담 답변: 관련 절과 조건 값의 구분

- `p681-t0`의 파싱된 표에는 수량이 없지만 PDF bbox 원문 행에는
  `미 장 공 인 0.14`가 있다. 구조가 불확실하거나 내용에 숫자가 없는 표는
  PDF 단어 위치를 이용해 줄 단위 원문을 보충한다. bbox가 없으면 해당 쪽의
  절 제목부터 다음 절 제목 전까지만 가져온다. 원본 PDF와 청크 파일은 수정하지 않는다.
- 보충은 같은 조각 ID로 표시하며 숫자·인용 검증에도 사용한다. 표 구조가
  불확실하다는 표시는 유지하고, 문맥 표시용 ID의 숫자는 근거 숫자로 인정하지 않는다.
- 전체 문맥은 최대 12,000자, 1위 후보 절은 최대 8,000자다. 나머지 절에는
  남은 문맥을 나누고, 질문 조건과 소제목·표 머리·본문의 겹침을 먼저 비교한다.
  선택한 내용은 원래 쪽·레코드 순서로 전달한다. 잘림 표시와 [주]·비고 보존을 유지한다.
- `8-1-3` 질문의 `5층` 조건으로 `p747-t0` 전체 표가 문맥에 포함되는지 검사한다.
- 후보가 없으면 `section_not_found`다. LLM이 not_found로 답했을 때 후보 점수가
  비슷하면 같은 분류를 사용한다. `chosen` 결정 또는
  1위 점수가 2위 점수의 `MARGIN`배 이상인 경우에는 LLM의 not_found를
  `section_found_value_missing`으로 구분해 절 이름과 원문 내용 줄을 보여준다.
  검색 조각의 내용 줄이 부족하면 같은 절의 다른 조각에서 보충한다.
- 금지 표현은 답변의 결론·설명·비교 문장에서 검사하며, 걸리면 대체 답변을 사용한다.
  평가 결과 JSON과 표에는 not_found 두 종류의 개수를 추가한다.
- 기본 모델 `gemini-3.5-flash-lite`, LLM 전체 호출·재시도 상한 12초를 유지한다.
  실제 품질과 검색을 포함한 전체 지연은 검토자의 재채점으로 확인한다.

## 검증

`run_quick.py` 19개 스크립트 모두 통과, `check_qa.py` 61/61 통과,
`npm.cmd run build` 성공. 기존 라우터·견적·API 기대값은 변경하지 않았다.
종전의 4,000자 명시적 예산 검사도 유지했다. `.env`를 읽거나 외부 LLM을 호출하지 않았다.

## 검토자 재채점

```powershell
$env:AGENT_LLM='on'
$env:AGENT_OFFLINE='0'
$env:PYTHONIOENCODING='utf-8'
.venv/Scripts/python.exe evals/eval_qa.py --model gemini-3.5-flash-lite
```

같은 날짜에 실행하면 해당 날짜의 모델 결과 JSON과 사람 검토용 모델 섹션을 갱신한다.
