## 5. 오프라인 시험 목록 (15개, 모두 통과)

- 지어낸 예시 13개가 코드 규칙을 지킴 / 시스템 프롬프트에 예시가 들어감
- 정상 견적 / 견적+상담 동시 보내기
- 근거 글자가 문장에 없으면 고치기 1회 후 통과 / 두 번 다 틀리면 출력 오류
- JSON이 깨지면 출력 오류 / AI 호출 실패면 처리 실패
- 카드 답 값이 허용 목록 밖이면 오류 / 진행 중 견적 없이 '바꾸기'면 오류 / 갈래와 칸이 안 맞으면 오류
- wants가 정해진 값이 아니면 오류
- 버튼 답은 AI 호출 0회로 견적에 감 / 버튼 값이 틀리면 오류
- 근거 비교 때 띄어쓰기 무시

- **가끔 틀림:** e08(품+금액 → 상담, 1/3), o08(양생 이유 → 상담, 1/3). 흔들림이다.

### 7-2. 처음 보는 상담 질문: `evals/draft_questions.jsonl` 2,695문

모두 품셈 상담용으로 만든 질문이다(정답은 상담).

- **낱말 규칙 (전체 2,695문):** 상담 1,574(58%) · 범위 밖 740(27%) · 견적 381(14%). 상담 질문 10개 중 4개를 엉뚱한 길로 보낸다. 운영에서 존댓말 상담이 막히는 원인 중 하나로 보인다.
- **v2 (표본 60문: 규칙이 틀린 40 + 맞힌 20, AI 약 60회):**

| 규칙 결과 → v2 결과 | 문항 수 |
| --- | --- |
| 상담 → 상담 | 20 / 20 |
| 범위 밖·견적 → 상담 | 30 / 40 |
| 범위 밖 → 다시 물어보기 | 8 |
| 범위 밖 → 범위 밖 | 1 |
| 범위 밖 → 출력 오류 | 1 |

- 규칙이 틀린 40문 중 v2는 30문을 상담으로 바로잡았다. 예: "프라이머 재료비는 어떻게 산정하나요?"(규칙: 견적), "법면 다짐판 손료는 어떻게 처리하나요?"(규칙: 범위 밖).
- v2가 상담으로 보내지 않은 10문은 거의 다 **사용자 질문이 아니라 상담원이 되묻는 말**이다(예: "석고판 설치 물량이 어떻게 되나요?", "나무높이가 0.9m 미만인가요?"). 시험지 자체의 잡음이고, 다시 물어보기는 그럴듯한 반응이다.
- 규칙이 맞힌 20문은 v2도 20/20 그대로 맞혔다(나빠진 것 없음).

### 7-3. 결론

- 옛 46문에서는 규칙 46 > v2 44~45. 처음 보는 상담 질문에서는 v2가 크게 낫다(표본 기준 규칙 20/60 → v2 50/60).
- **다음:** draft 질문은 상담원이 되묻는 말이 섞여 있어 정답이 깨끗하지 않다. 사람이 정답을 단 새 시험지(상담·견적·애매·범위 밖 섞어서)를 만들어 최종 판단하면 더 확실하다. 그 전이라도 R3(스위치로 운영 연결, 기본 꺼짐)은 진행 가능.
- 남은 결정: e16 정답을 '다시 물어보기'로 바꿀지.
